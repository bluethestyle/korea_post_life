### 실제 호출 시험

질의 1건(현대해상, 출시·개정 소식)을 시트에 쓰지 않는 방식으로 두 번 돌렸습니다.

| 단계 | 결과 |
| --- | --- |
| 검색 (gemini-2.5-flash-lite) | 1회 호출, 출처 15~20건 |
| 정형화 (gemini-3.5-flash-lite) | 1회 호출, 소식 6건 |
| 코드 날짜 확인 | 6건 중 5건이 수집 구간 밖(2026-04-07 ~ 2026-11-01 발행)이어서 버림 |
| 선별·분류 (gemini-decision-1) | 남은 1건: 대상 확률 0.96, 분류 "상품개정" |
| 출처 주소 | 검색 그라운딩의 경유 주소가 실제 기사 주소로 풀림 |

- 날짜를 질의에 적어도 검색 모델은 구간 밖 소식을 많이 돌려줍니다. 기획 4.3의 세 번째 단계(코드 확인)가 없으면 오래된 소식이 그대로 들어옵니다.
- 판정 모델은 참·거짓 문항의 답을 참일 확률(숫자)로 돌려줍니다. 처음에는 이 값을 참·거짓 값으로 잘못 읽어 대상 소식을 반려했고, 응답 형태를 확인해 고쳤습니다. 받은 응답 형태를 시험(`tests/test_gemini.py`)에 고정해 두었습니다.

### 첫 실제 수집 (2026-11-18 12:33, GitHub Actions)

비밀값 3개를 등록한 뒤 수요일 분(현대해상·메리츠화재·한화손해보험)을 실제로 돌려 시트에 기록했습니다.

| 항목 | 결과 |
| --- | --- |
| 검색 질의 | 6건, 실패 0건 |
| 정형화된 소식 | 27건 |
| 수집 구간 밖이라 코드가 버린 건 | 23건 (2023-09 ~ 2026-11-03 발행) |
| 판정 모델이 반려한 건 | 1건 (분류 "해당없음") |
| 사람 검토로 넘긴 건 | 2건 (선별 확률 0.60, 0.61. 둘 다 배타적 사용권 소식) |
| 시트에 기록한 건 | 1건 (선별 확률 0.74) |
| 호출 수 | 검색 6회, 정형화 6회, 판정 4회. 소요 1분 41초 |

- 서비스 계정으로 `sys_시장동향`과 `sys_작업로그`에 쓰는 것까지 확인했습니다.
- 같은 기사가 준비 단계 시험에서는 0.96, 이번에는 0.74를 받았습니다. 정형화 단계가 쓴 요약 문장이 달라지면 선별 확률도 크게 움직입니다. 통과 기준(0.70)을 정답셋으로 맞춰야 하는 이유입니다.
- 14일 구간으로는 한 번에 기록되는 건수가 적습니다. 시간선 화면을 채우려면 처음 한 번은 구간을 넓혀(`lookback_days`) 돌려야 합니다.

### 구현하면서 정한 것

기획 문서에 없거나 구체적이지 않아 구현 중에 정한 내용입니다. 검토 대상입니다.

1. 수집 구간은 실행일 기준 14일입니다. 기관마다 주 1회만 돌기 때문에 7일로 잡으면 실행이 하루 밀렸을 때 빈 구간이 생깁니다. 겹치는 구간은 중복 병합으로 걸러 냅니다.
2. 중복 비교 범위는 "같은 기관·같은 분류·발표일 7일 이내"입니다. 기획 4.6은 같은 수집주차 안에서 비교한다고 했지만, 구간이 14일이라 주차를 넘어 같은 기사가 다시 잡힙니다.
3. 중복은 주소가 같거나 요약 글자가 80% 이상 같으면 코드가 합치고, 그 밖에는 판정 모델에 같은 사건인지 묻습니다.
4. 검색 질의는 기관 묶음마다 두 갈래(출시·개정·배타적 사용권 / 판매중지·간편고지 완화·한도 상향)로 나눕니다. 요일별 호출 수는 기획 4.4의 표와 같습니다. 질의마다 최대 3회까지 시도해도 하루 18회로 검색 한도 20회 안입니다.
5. 특정 회사에 속하지 않는 소식의 기관코드로 KLIA(생명보험협회), KNIA(손해보험협회), FSC(금융위원회), FSS(금융감독원), COMMON(업계 공통)을 둡니다.
6. 선별 확률이 통과 기준과 반려 기준 사이인 소식은 `sys_시장동향`에 쓰지 않고 `sys_작업로그`에 "사람검토이관·보류"로 남깁니다. 요약과 출처 주소를 사유에 적어 화면 6에서 볼 수 있게 합니다.
7. 실패한 질의는 작업로그에 보류로 남기고, 일요일 실행이 그 주에 성공하지 못한 질의만 다시 돕니다.
8. 판정 구간 값(기사 선별 0.70/0.40, 중복 0.70, 담보 매핑 0.90, 추출 검증 0.85/0.30)은 정답셋으로 맞추기 전의 임시값입니다. `hum_기준값`에서 고치면 코드 수정 없이 반영됩니다.
9. 비교 기준 단위는 진단 1,000만 원, 수술 100만 원, 입원·통원 1만 원(기획 3.3)에 더해, 치료비 100만 원, 허가치료비(표적·면역·양성자) 1,000만 원을 초안으로 넣었습니다.
10. 표준질병군은 KCD-9 기준으로 적었습니다. 제9차 개정은 2026-01-01에 시행됐습니다(출처 아래). 코드 구간은 통상 약관의 분류표를 따른 초안이므로, 비교 대상 상품의 약관 별표와 대조해야 합니다.
11. 시트 ID도 Actions 비밀값(`SPREADSHEET_ID`)으로 둡니다. 공개 저장소에 시트 주소를 남기지 않기 위함입니다.
12. `hum_기준값`의 적용시작일은 법령 시행일이 아니라 이 앱이 그 값을 쓰기 시작한 날입니다.
