## 5. 회사별로 알아 둘 것

### 한화생명

- 급부 표가 `[간편가입형]` / `[일반가입형 및 건강가입형]`으로 갈립니다(213개 특약 중 114개). `segment.scope_parts`로 나누고 `scope_matches`로 종형에 맞춥니다. 종형은 간편가입형(1년)/(2년)/(5년), 일반가입형 넷.
- 갱신 주기는 요약서 11~13쪽 목록에서 읽습니다(`segment.renewal_periods`, 여러 만기가 있으면 가장 짧은 것).
- 이름 없는 "보장개시일 이후"는 계약일(면책 0). "암보장개시일"처럼 이름이 붙은 것만 대기 날수가 있습니다(`benefits.plain_start_in`, `waiting_days_of`).
- 2단 감액("180일이내 …, 1년이내 …"), 셀 안 예외("※ 단, 재해로 인한 …시" → `감액예외`), "보장형 계약/연장형 계약" 하위 표, 소수 만원("2.5만원"), 원 단위("5,000원")가 있습니다.
- 특약 이름 꼬리의 "(KTA1.1) 무배당", "(무)"는 계보키에서 뗍니다(`ids.rider_lineage_key`).

### 삼성화재

- 급부 표는 PDF에서 읽습니다(`extract/tables.py`: `riders_from_pdf`, `for_variant`, `to_blocks`). 금액이 아니라 가입금액 대비 비율로 적혀 있어, 시트에는 기준가입금액만원 100, 기준지급금액만원 = 지급률(%)로 적기로 했습니다. 화면에서 우체국, 한화 금액과 나란히 놓을 때 표시 방식을 따로 정해야 합니다.
- 문구가 규칙적이라 모델 없이 `extract/table_rules.py`로 뽑습니다. 읽지 못한 형태는 "확신 없음" 사유가 붙습니다(상품마다 34줄: 통합치료비의 "약관에서 정한 금액", 체증형, 묶음 세부보장, 진단 시점 기준 감액, 계약일 기준이 아닌 보장개시일). 이 줄들을 확률 산정 모델, 담당자 검토, 작업로그로 넘기는 경로는 아직 없습니다.
- 새로고침은 1·3·7종 공통 표이고 전부 갱신형입니다. 갱신주기 = 보험기간(30/20/15/10년)을 호출하는 쪽이 넘겨야 합니다. 종별로는 `tables.for_variant`를 먼저 거칩니다.
- 같은 이름의 특약이 기본계약과 선택계약에 모두 있으면 뒤쪽 ID를 "이름(선택계약)"으로 만듭니다. 가입조건 쪽도 같은 규칙으로 맞춰야 이어집니다.
- 원문 자체의 문제 두 곳(새로고침 요약서): 105쪽 전액본인부담 특정치료비Ⅲ 세 줄은 본문 "각 치료행위별 연간 1회"와 주석 "수술은 수술 1회당"이 엇갈리고, 140쪽 특정내시경 지원비는 보장개시일 주석에 "특정생검(급여)"이라고 잘못 적혀 있습니다.

### 우체국

- 가입조건 추출을 고칠 때는 실제 추출을 되돌려 돌리는 재현으로 행이 그대로인지 확인합니다(로컬 자료 꾸러미의 `replay/`).

### 삼성생명, KB라이프생명 (행 패키지로 적재)

- Actions 러너에서 두 회사 공시실 접속이 실패합니다(2026-11-24 실행 45308408466, 45308470752. 삼성생명은 목록 조회는 되지만 PDF 다운로드가 417 Expectation Failed, KB라이프생명은 목록 조회 응답이 JSON이 아님). 이 서버에서는 같은 코드가 정상 동작하므로 해외 IP 차단으로 추정하지만 확인하지는 못했습니다. `docs_run`도 Actions에서 문서를 받아야 해서 해결되지 않습니다.
- 그래서 로컬에서 받은 문서로 행을 만들어 행 패키지(`data/backfill_rows/<회사>_benefits.json`, `<회사>_conditions.json`)로 커밋하고, Actions는 문서 없이 패키지를 검증한 뒤 시트에 씁니다. 패키지는 시트에 들어갈 행 그대로이고(원문 구절 열은 `sys_급부`의 지급횟수제한, 감액예외로 다른 회사와 같음), 대상 설정과 검증 결과 파일의 sha256, 문서별 sha256, 행 수를 담습니다. 실행 시각과 로그ID는 쓸 때 채웁니다.
- 읽는 쪽(`--rows-in`)은 대상 설정과 검증 결과 파일의 해시가 체크아웃과 다르면 멈추고, 형식 검사, ID 겹침, 시트의 기존 행과의 관계(가입 한도 잇기, 시트에 있던 주계약 행 쓰기, 빠지는 행 보고)는 문서로 돌 때와 같은 코드(`finish`)로 봅니다. 대상 설정(`data/targets/<회사>.json`)이나 검증 결과 파일(`data/crosscheck/<회사>_*_2reader.jsonl`)을 고치면 패키지를 다시 만들어 함께 커밋합니다(`tests/test_row_package.py`가 어긋남을 잡습니다).

```bash
# 로컬: 패키지 만들기 (문서 폴더는 fetch_disclosure.py --org <회사>의 결과, 시트에 쓰지 않음)
python scripts/load_reader_product.py --docs <문서 폴더> --org samsunglife --targets data/targets/samsunglife.json --rows-out data/backfill_rows/samsunglife_benefits.json
python scripts/load_reader_conditions.py --docs <문서 폴더> --org samsunglife --targets data/targets/samsunglife.json --rows-out data/backfill_rows/samsunglife_conditions.json
# 로컬: 패키지로 흐름 보기 (--dry-run, 또는 --snapshot data/snapshot. 가입조건은 --seed-rows로 급부 패키지를 쓴 뒤의 시트를 볼 수 있음)
python scripts/load_reader_product.py --rows-in data/backfill_rows/samsunglife_benefits.json --org samsunglife --targets data/targets/samsunglife.json --snapshot data/snapshot
# Actions: rows_in을 켜고 돌림 (only와 함께 쓰지 않음)
gh api -X POST repos/bluethestyle/korea_post_life/actions/workflows/extract.yml/dispatches -f ref=main -f 'inputs[org]=samsunglife' -F 'inputs[rows_in]=true'
```

## 6. 제미나이와 나눠 한 방식

잘 통한 방식만 적습니다. 요청문 틀은 `docs/gemini_requests/`, 받은 결과는 `data/crosscheck/`.

- **정답셋 만들기**: 문서만 주고 "항목, 정답, 근거 쪽"을 표로 받은 뒤 원문과 대조(우체국, 한화, 삼성화재 160항목).
- **독립 구조화**: 파이프라인과 따로 같은 표를 구조화하게 하고 줄마다 대조(삼성화재 681줄, 오류 0).
- **표본 대조**: 추출 결과 일부와 해당 쪽 발췌 PDF를 주고 오류 행을 찾게 함(한화 검수 대기 행).
- **분류 의견**: 매핑 대기 388종류를 기존/신규/대상외로.
- **코드 검토**: 소스를 주고 "틀린 값을 조용히 통과시키거나 맞는 값을 버리는 곳"만 찾게 함.

요령:
- 한 번에 주는 양을 줄입니다. 사업방법서 세 권(759쪽)을 한꺼번에 주면 답을 못 냅니다. 문서별로 나누고, 필요한 쪽만 뽑아 원문 쪽 번호를 찍은 발췌 PDF로 줍니다. 표 구조화는 57행씩 끊었습니다.
- 번호를 붙여 주고 "번호를 빠짐없이, 순서대로, 표 하나만"을 요구하면 빠진 줄을 기계로 셀 수 있습니다.
- "자료에 없으면 만들지 말고 '확인 필요'"를 적어 두면 원문 오류를 잘 짚습니다.
- 웹의 "코드 가져오기"는 풀린 크기 10MB를 넘으면 실패합니다. 소스는 줄 번호를 붙인 글 파일 하나로 묶어 줍니다.
- 결과는 그대로 믿지 않고 원문·코드로 다시 확인합니다. 코드 검토 지적은 재현되는 것만 고칩니다.
