# 영업 인사이트 흐름 설계안

작성 2026-11-20. 사본 기준 2026-11-20 15:15(`data/snapshot/meta.json`의 snapshot_at). 사용자가 방향을 정하기 전의 설계안이고, 이 문서는 코드, 스키마, 사본을 바꾸지 않는다. 수치는 `insights.analyze()`와 저장소 밖 임시 스크립트로 사본을 읽어 잰 값이다. `scripts/dev/show_sales.py`가 생기면 그 출력으로 다시 확인한다.

## 1. 왜 쓰는가

사용자의 지적(2026-11-20, 그대로)
> 근데 우리 보험 영업 관련된 측면도 함께 고려하기로 하지 않았나 지금 보니 왜 청약에만 집중되어있는 것 같지
> 청약 지식에서 시작해서 영업 인사이트까지 연결되는 흐름을 최초에 서비스 기획에서 생각했던건데
> 아니 레이아웃은 바뀌어도 상관없는데 이유없이 갈아엎어질까봐서 그런거지 일관성은 있어야하잖아

기획 확정본(`docs/planning.md` 1절)의 주 사용자는 본부 상품, 영업지원 담당자이고, 창구 직원과 FC에게는 1장짜리 응대 카드로 전달한다. 관점은 "우체국보험의 청약(가입 적격)과 상품 영업"이다. 돕는 판단 열 가지 가운데 ② "병력 기간에 따라 어느 간편심사 상품을 통과하는가"(2.3절)가 청약에서 영업으로 넘어가는 첫 고리인데, 지금 코드는 고지 질문 값을 화면에 옮기기만 하고 계산에는 쓰지 않는다(`src/postlife/site/eligibility.py`의 `gate()`, 56~64행).

지금 화면이 좁아진 곳(시안 3, `site/proto/console3.html`)
- 브리핑 첫 문장이 "우체국은 견준 담보 n개 중 m개를 가졌습니다. 없는 담보 k개부터 보세요"다(874행). 패널 순서도 우리에게 없는 담보, 조건이 다른 담보, 우리만 있는 담보다. 상품 결손 점검에는 맞지만 응대 준비에는 맞지 않는다.
- 영업 쪽 문장은 "응대에서 먼저 꺼낼 강점입니다" 한 줄이다(903행). 응대 카드 단추가 없고, 가입 설계와 시장과 개정 탭은 "준비 중"이다(597, 598행). 시사점(`insights.py`)과 표준담보 관계(`relations.py`)는 화면 빌드(`build.py`)에 이어져 있지 않고, 해설 글(`commentary.json`)에 영업 문장은 0건이다.

정리하면 가입 관문과 담보 비교는 계산되는데, 둘을 "그래서 이 고객에게 무엇을 말하는가"로 잇는 계산과 화면이 없다. 이 문서는 그 고리를 정의한다.

## 4. 계산 정의

### 4.0 공통

모듈은 `src/postlife/site/sales.py`, 확인 도구는 `scripts/dev/show_sales.py`다. 입력은 `model.load()`가 읽은 `Data`, `relations.load_relations()`, `insights.analyze()` 결과다. 시사점 판정은 다시 계산하지 않고 `analyze()` 결과를 거르고 문장으로 옮기기만 한다. 검토 대기는 `insights.py`의 규칙(대기는 "없음"이 아니라 "모름")을 그대로 따른다.

짝 고르기 바로잡기(`compare.peers`, 239~258행). 지금은 심사 등급이 같은 종형 가운데 화면 순서의 첫째를 고르고 갱신유형을 보지 않는다. 그래서 우체국 4종(일반가입, 갱신)의 삼성화재 짝이 8종(일반형, 비갱신)으로 잡힌다. 기획서가 정한 짝은 8종(해약환급금 미지급형, 일반고지, 갱신, `SAMSUNGFIRE_ZPB358050_863d5a`)이다. 고칠 규칙은 같은 등급 후보 가운데 갱신유형이 같은 것, 그다음 환급유형이 같은 것을 먼저 고르고, 없으면 지금처럼 첫째를 고르는 것이다. 이렇게 고르면 4종 대 삼성화재의 조건 우열이 못함 7건에서 같음 5, 나음 2, 못함 0으로 바뀐다(`peers`만 바꿔 `analyze()`를 돌린 값). 나머지 네 종형의 짝은 그대로다.

고객 조건
```python
@dataclass(frozen=True)
class Profile:
    age: int | None = None
    sex: str | None = None          # "M", "F"
    since: float | None = None      # 마지막 입원이나 수술이 몇 년 전보다 오래됐나(0.25, 1, 2, 3, 4, 5). None은 이력 없음
    surgery_only: bool = False      # 그 이력이 입원 없이 수술만인가
    renewal: str | None = None      # "갱신", "비갱신". None은 전체
```

### 4.1 (가) 가입 관문과 고객군 지도

```python
def question_hit(variant: dict, p: Profile) -> str        # "해당 없음" | "해당" | "심사로 확인" | "자료 없음"
def gate(data: Data, p: Profile) -> dict                 # 회사별, 종형별 상태
def cell(data: Data, p: Profile, analysis: dict) -> dict  # 지도 칸 하나
def segment_map(data: Data, sex: str, renewal: str | None, analysis: dict) -> dict
```

`question_hit` 규칙
- 간편심사 종형: 이력이 없으면 해당 없음. `surgery_only`이고 `고지수술포함여부`가 거짓이면 해당 없음(기간 질문이 입원만 묻는다). 그 밖에는 `since >= 고지입원수술년수`이면 해당 없음, 아니면 해당. 열이 비었으면 자료 없음.
- 일반심사 종형: 이력이 없거나 `since >= 5`이면 해당 없음, 아니면 심사로 확인(일반 고지는 질문이 더 넓고 결과를 심사가 정한다).
- 최근 3개월 소견과 5년 안 중대질병 문항은 세 회사 모두 3개월, 5년이라 칸을 가르지 않는다. 입력으로 받지 않고, 결과 문장에 "두 문항에 해당하지 않으시면"이라는 전제를 늘 붙인다.

`gate` 상태. 대상은 정밀비교이고 판매 중(`판매종료일` 빈칸)인 종형이고, `renewal`이 있으면 갱신유형이 같은 종형만 본다. 나이는 `model.age_limit(주계약, Cond(age, sex))`로 본다.
- 열림은 질문 해당 없음이고 나이 가능, 닫힘은 질문 해당이거나 나이 불가다. 나이 자료 없음은 질문 해당 없음이고 `Limit.no_data`가 참인 경우로, 가입 가능으로 세지 않는다. 심사로 확인(일반심사이고 이력 있음)은 칸 분류에서 닫힘으로 센다.
- 회사 상태는 그 회사 종형 상태 가운데 열림, 나이 자료 없음, 심사로 확인, 닫힘 순으로 앞선 것이다.
- 돌려주는 값: `{"조건": Profile, "회사": {기관코드: {"상태": str, "종형": [{"종형ID", "질문", "나이", "상태", "한도만원"}]}}}`

칸 분류(우리 상태를 U, 상태가 열림이나 닫힘인 상대를 "자료 있는 상대"라 한다)

| 분류 | 조건 |
| --- | --- |
| 우리만 열림 | U 열림, 자료 있는 상대가 1곳 이상이고 모두 닫힘 |
| 함께 열림 | U 열림, 상대 1곳 이상 열림 |
| 우리만 닫힘 | U 닫힘, 상대 1곳 이상 열림 |
| 모두 닫힘 | U 닫힘, 자료 있는 상대 모두 닫힘. 패널에 "일반심사로 확인"을 적는다 |
| 자료 없음 | U가 나이 자료 없음이거나, 자료 있는 상대가 0곳 |

- 나이 자료가 없는 회사는 칸마다 "자료 없음: 삼성화재"처럼 이름을 적는다. 분류는 관문 상태이지 우열이 아니라서 판정 색(나음 파랑, 못함 주황)을 쓰지 않고 명도 단계와 글자로 나눈다.

축
- 행: 고지 이력. 종류 둘(입원이 있었음, 입원 없이 수술만)에 마지막 입원이나 수술 시점 여섯(3개월~1년 전, 1~2년, 2~3년, 3~4년, 4~5년, 5년 넘음이나 없음)을 곱한 12행이다. 경계는 세 회사 `고지입원수술년수` 값의 합집합(1~5년)에서 나오고, 회사가 늘어 새 기간이 생기면 행이 는다.
- 열: 나이. `Data.age_edges()`의 구간을 쓰되, 이웃 구간의 칸 분류와 칸 숫자가 모두 같으면 합친다. 지금 사본은 15~19세, 20~65세, 66~80세 세 열이 된다.
- 성별은 지도 위 스위치다(사본에서 남녀 결과가 같다). 갱신 유형 거르개는 전체, 갱신, 비갱신이다(기획 3.1절의 조건 목록).

칸의 숫자(판정어 대신)
- 대표 종형. 우리는 열린 종형 가운데 간편이면 질문 기간이 가장 긴 것(같으면 화면 순서 첫째), 열린 간편이 없으면 열린 일반심사 종형의 첫째다. 상대는 열림이나 나이 자료 없음인 종형 가운데 바로잡은 `compare.peers`가 우리 대표에 고르는 종형이고, 그 종형이 닫혔으면 남은 것 가운데 질문 기간이 가장 긴 것이다. 나이 자료가 없는 상대도 거르지 않고 꼬리표를 단 채 견준다.
- 숫자는 우리 대표와 상대 대표의 시사점에서 센 고유 수, 빈자리 수, 조건 못함 수, 조건 나음 수(4.2의 거르기를 거친 뒤), 검토 대기로 뺀 수다. 상대 대표가 `analyze()`의 맞붙는 종형과 다르면 그 쌍으로 다시 돌린다(`insights._Base`를 감싸는 공개 함수 `insights.analyze_pair(data, base, peers, relations)`를 새로 둔다).
  우리 대표가 없는 칸(우리만 닫힘, 모두 닫힘)은 숫자를 비운다. 담보 구성은 나이로 바뀌지 않으므로 숫자는 이력 종류와 대표에 따라서만 달라진다.
- `segment_map` 돌려주는 값: `{"행": [{"종류", "since", "이름"}], "열": [{"lo", "hi"}], "칸": [[{"분류", "회사": {기관코드: 상태}, "대표", "상대대표": {기관코드: 종형ID}, "수": {"고유", "빈자리", "못함", "나음", "대기"}, "자료없음": [기관코드]}]], "집계": {분류: 칸 수}}`

지금 사본의 지도(남, 갱신 거르개 전체, 12행 3열 36칸)

| 분류 | 칸 수 | 어디 |
| --- | --- | --- |
| 함께 열림 | 22 | 이력 1년 넘게 지난 20~80세, 5년 넘음이나 없음의 모든 나이 |
| 우리만 닫힘 | 8 | 15~19세의 이력 1~5년 전(두 종류 모두) |
| 모두 닫힘 | 4 | 입원 3개월~1년 전의 모든 나이, 수술만 3개월~1년 전의 15~19세 |
| 우리만 열림 | 2 | 수술만 3개월~1년 전의 20~65세, 66~80세 |
| 자료 없음 | 0 | 삼성화재 나이 자료 없음 꼬리표는 30칸에 붙는다 |

칸을 누르면 패널에 회사별 열린 종형, 질문 문구 차이, 칸 숫자, 근거가 뜬다. 패널의 "이 고객군으로 조건 바꾸기" 단추를 눌러야 조건 줄이 바뀌고 브리핑으로 간다.

### 4.2 (나) 응대 포인트

```python
def points(data: Data, base: str, p: Profile, analysis: dict, relations: Relations) -> dict
def render(template_id: str, values: dict) -> str      # 틀에 값을 끼운다. 금지어가 들면 예외
def scope(data: Data, base: str, peers: list[str], analysis: dict) -> dict   # 범위 띠
```
돌려주는 값: `{"기준종형ID", "맞붙는종형": [...], "범위": scope(), "포인트": [{"포인트ID", "종류", "세부", "표준담보ID", "틀", "값", "문장", "머리말", "근거", "점수", "목적", "구조다름", "원문대조", "시사점ID"}], "뺀포인트": [{"세부", "표준담보ID", "사유"}], "집계": {세부: 수}}`
- 포인트ID는 시사점ID와 같은 방식으로 `"PT_" + sha1(세부|기준종형ID|표준담보ID|조건)` 앞 12자리다.
- 근거는 `[{"종형ID", "문서", "쪽", "급부ID"}]`이고 문서와 쪽은 시사점 근거 급부의 `근거문서종류`, `근거문서쪽수`다. 고지 질문은 쪽이 없어 `{"문서": "사업방법서", "쪽": None}`이고 `원문대조`가 참이다.

종류와 문장 틀. `{}`는 화면이 자료 값을 끼우는 자리이고, 틀 밖에는 숫자를 쓰지 않는다(기획 3.4절).

범위 머리말 규칙
- 비교 문장마다(카드에서는 묶음마다) 앞에 "수집한 {상대 회사 정식명} {공시상품명} {종형명} 기준({적용시작일})"을 붙인다. 상품별 기준일이 다르므로 회사마다 적는다.
- 회사 수는 "견준 {n}개 회사 가운데 {m}곳"으로 쓴다. 지금은 n이 2라 빈자리 기준(`GAP_MIN` 2)이 "두 회사 모두"와 같다.
- 회사명은 줄이지 않는다. 시장 소식의 한화손해보험과 정밀 비교의 한화생명을 "한화"로 묶지 않는다.
- 짝의 갱신유형이나 환급유형이 다르면 머리말 뒤에 "구조 다름: 우체국 {갱신}, {환급} 대 {상대 갱신}, {상대 환급}"을 붙인다.
- 틀에 쓰지 않는 말: 업계, 유일, 독점, 최초, 최고, 가장, 더 좋다, 유리, 우수, 저렴, 가성비, 실속, 가입됩니다, 거절됩니다, 권하세요, 추천, 바꾸세요, 갈아타세요. `render()`가 이 말이 든 문장에 예외를 내고, 시험으로 막는다.

빼는 조건(`뺀포인트`에 사유를 적는다)
1. `analyze()`가 이미 뺀 시사점(매핑 대기, 작업 로그 대기)
2. 어느 쪽이든 `대표밖조건다른줄`이 1 이상인 담보의 A2, Q3
3. 조건 판정이 판정 보류인 담보(감액예외 글, 지급 형태 문구 없음)
4. 짝의 갱신유형이 다른 쌍의 A2. 영업 포인트 탭 본문에는 보이되 브리핑과 카드에서는 뺀다
5. 나이 자료가 없는 회사가 낀 나이 문장(G2의 상대 쪽)
6. 가입 한도 자료가 없는 회사와 금액을 견주는 문장(지금 틀에는 없다)

정렬
- 브리핑과 카드는 종류 순서를 고정한다. 관문, 앞세울 것, 물어올 것 순서이고, 고객이 묻는 순서(가입되나, 무엇이 다른가)와 흐름 순서가 같다. 관문 안에서는 G1, G2, G3 순이다.
- 앞세울 것과 물어올 것 안에서는 원래 시사점의 `점수`(10 × 걸린 회사 수 + 분야 가중 5 + 유형 가중)를 그대로 쓰고, 같으면 비교표의 담보 순서를 따른다. 새 점수는 만들지 않는다.
- 브리핑과 카드는 종류마다 위에서 세 개를 싣는다.

목적 묶음(영업 포인트 탭의 거르개이자 가입 설계 탭 구성 예시의 출발점, 기획 3.3절의 추천 목적 세 가지): 암은 보장대분류 암보장, 3대 질병은 암보장, 뇌혈관보장, 심장보장, 뇌심장보장(`insights.FOCUS_MAJORS`), 입원과 수술은 급부유형 입원과 수술이다.

## 5. 화면 구성

### (가) 화면 구성안

| 순서 | 탭 | 맡는 단계 | 누가 어떤 일에 | 영역 |
| --- | --- | --- | --- | --- |
| 1 | 브리핑 | 0~4의 결론 | 문의 응대: 1~2분 안에 할 말을 고른다 | 첫 문장, 결론 줄 여섯 |
| 2 | 가입 설계 | 1, 3의 구성 예시 | 청약 심사: 열리는 종형, 한도, 결합 제약 | 위는 관문 표(회사별 종형, 질문, 나이 구간, 한도), 아래는 한도 안 구성과 담보별 지급액(우체국) |
| 3 | 담보 비교 | 2 | 본부: 사실 확인과 상품 검토 | 위는 분야와 치료 여정 격자와 지금 브리핑의 패널 셋, 아래는 담보 비교표 |
| 4 | 영업 포인트 | 3 | 응대 문장 고르기, 카드 준비 | 목적 거르개, 관문, 앞세울 것, 물어올 것과 답의 전체 목록, 뺀 포인트 |
| 5 | 시장과 고객군 | 5 | 본부 주간 점검 | 고객군 지도, 시장 소식, 개정 전후 비교 |

모든 탭 위에는 조건 줄(나이, 성별, 마지막 입원이나 수술 시점, 수술만 스위치, 기준 종형, 비교 상대, 응대 카드 단추)과 범위 띠가 있고, 오른쪽에는 관계와 근거 패널이 있다.

브리핑의 구성
- 첫 문장: "{조건} 고객은 우체국 {열린 종형}, {상대 회사} {열린 종형}의 고지 질문에 해당하지 않습니다. 먼저 꺼낼 것은 {앞세울 것 첫째}입니다." 없는 담보 수로 시작하지 않는다.
- 결론 줄 여섯: 가입되나(관문), 먼저 꺼낼 것(앞세울 것 셋), 물어올 것과 답(셋), 얼마까지(우리 한도와 구성 예시 한 줄), 갱신과 환급(구조 한 줄), 이번 주(소식 수, 우리 담보에 닿은 수). 줄을 누르면 패널이 열리고, 줄 끝의 "자세히"는 그 단계를 맡은 탭으로 간다.

### (나) 시안 3에서 바뀌는 것과 그대로인 것

| 무엇을 | 지금 | 바꾼 뒤 | 이유 |
| --- | --- | --- | --- |
| 탭 순서와 수 | 브리핑, 담보 비교, 가입 설계, 시장과 개정 | 브리핑, 가입 설계, 담보 비교, 영업 포인트, 시장과 고객군 | 1단계(관문)가 2단계(비교)보다 앞이고, 3단계의 상세가 놓일 자리가 없었다. 탭 순서가 일의 순서와 같아야 한다는 사용자 원칙 |

| 범위 띠 | 없음 | 조건 줄 바로 아래, 모든 탭 | 0단계. 견준 상품과 분모 없이 쓴 비교 문장은 과장이 된다 |
| 응대 카드 단추 | 없음 | 조건 줄 오른쪽, 모든 탭(UIUX 개편안 5절의 자리) | 4단계. 어느 탭에서 일을 마치든 카드로 끝난다 |
| 카드 묶음 | 관문 표, 비교표 12행, 이름 다섯 개씩 | 관문 요약, 앞세울 것 셋, 물어올 것과 답 셋, 구성 예시 한 줄, 핵심 담보 6행, 유의사항 | 창구와 FC가 표를 말로 옮기지 않고 바로 읽게 한다 |
| 가입 설계 탭 | 준비 중 | 관문 표와 한도 안 구성 | 관문과 구성 예시는 같은 자료(가입조건, 한도, 결합 제약)를 쓴다. 계산기를 한 곳에만 둔다 |
| 시장과 개정 탭 | 준비 중 | 시장과 고객군(지도를 더하고 개정 비교는 둔다) | 5단계. 본부 주간 점검의 출발점 |
| 조건 줄을 모든 탭이 함께 씀 | 있음 | 그대로 | 두 진입로가 만나는 자리다 |
| 관계와 근거 패널 | 있음 | 그대로, 영업 포인트와 지도 칸도 같은 패널 | 근거까지 내려가는 조작이 한 가지여야 한다 |
| 담보 비교표 본문 | 있음 | 그대로 | 2단계의 상세이고 바꿀 이유가 없다 |
| 색의 뜻 | 나음 파랑 ▲, 못함 주황 ▼, 빈자리 점선, 자료 없음 빗금 | 그대로, 지도 칸에는 판정 색을 쓰지 않음 | 관문 상태는 우열이 아니다 |

### (다) 일관성 규칙

1. 탭 순서는 흐름 순서(관문, 비교, 영업, 넓혀 보기)이고, 브리핑 결론 줄도 같은 순서다. 결론 줄 하나는 탭 하나로 간다.
2. 조작 순서는 어디서나 조건을 고르고, 결론을 보고, 항목을 눌러 패널에서 근거를 본다. 다른 탭으로 넘어가는 것은 "자세히"나 패널의 단추를 눌렀을 때뿐이다.
3. 영역은 위에서부터 조건 줄, 범위 띠, 탭, 본문, 오른쪽 패널이다. 본문 맨 위는 그 탭이 맡은 단계의 결론 한 줄이다.
4. 조건(나이, 성별, 고지 이력, 기준 종형, 비교 상대)은 탭을 옮겨도 유지된다. 지도 칸에서 바꿀 때도 패널의 단추를 거친다.
5. 결론 줄, 포인트 줄(문장, 머리말, 근거 칩), 비교 칸, 지도 칸, 패널은 탭마다 같은 컴포넌트를 쓴다. 패널 안은 머리띠, 결론 배지, 문장, 관계 그림, 근거, 뺀 것 순서로 고정한다.
6. 열림, 닫힘, 자료 없음, 검토 대기, 구조 다름, 앞세울 것, 물어올 것, 구성 예시는 화면 전체에서 같은 뜻으로 쓴다.
7. 파랑 ▲ 나음과 주황 ▼ 못함은 조건 우열에만 쓴다. 빗금은 자료 없음과 검토 대기, 점선 빈 슬롯은 빈자리다(UIUX 개편안 7절).
8. 응대 카드는 조건 줄의 단추 하나로만 가고, 어느 탭에서 눌러도 지금 조건과 기준 종형, 비교 상대로 같은 카드가 나온다.
9. 탭 이동과 조건 바꾸기는 브라우저 기록에 남는다. 뒤로 가기는 패널이 열려 있으면 패널을 먼저 닫고, 그다음 바로 앞의 탭과 조건으로 돌아간다.
10. 숫자와 문장은 화면이 자료 값으로 만든다. 머리말이 없는 비교 문장과 금지어가 든 문장은 어느 탭에도 내지 않는다.

## 6. 구현 순서

버전 1(다음 주 초, 세 회사)
1. 짝 고르기 바로잡기(`compare.peers`). 운영 화면(`site/index.html`)의 값이 바뀌는 일이라 따로 커밋한다. 바뀌는 것은 4종의 삼성화재 짝(8종(일반형)에서 8종(해약환급금 미지급형, 일반고지)으로), 화면 3의 기본 비교 열, 4종 시사점, 관련 시험의 기대값이다.
2. `sales.py`의 `question_hit`, `gate`, `scope`와 조건 줄 입력 바꾸기
3. `sales.points`, `render`, 금지어 시험, `scripts/dev/show_sales.py`
4. 브리핑 다시 짜기(첫 문장, 결론 줄 여섯), 범위 띠, 응대 카드 단추
5. 영업 포인트 탭
6. 응대 카드 묶음 바꾸기(`card.py`의 묶음과 줄 수 상한)
7. 가입 설계 탭(지금 `site/index.html`의 관문 표와 조합 계산을 새 배치로 옮기고 목적 묶음을 출발점으로 단다)
8. 시간이 남으면 `segment_map`과 시장과 고객군 탭의 지도

버전 1 뒤로 미룸
- 시장 소식과 표준담보 잇기(`collect.py`가 비워 두는 두 열을 채우는 규칙), 소식별 대응 유형
- 삼성화재 가입조건 추출. 관문 칸의 "나이 자료 없음"을 없애는 자료 작업이다
- 상대 특약 가입 한도, 보험료, 질병코드(금액 비교와 가격 문장은 이 자료가 들어온 뒤), 고객이 가진 담보를 빼고 보는 보완 구성, 질문 줄

## 7. 다루지 않는 것, 받아들이지 않은 비평, 사용자가 정할 것

다루지 않는 것: 판매 시책, 수수료, 손해율, 실적, 병력과 투약과 직업별 인수 판정, 보유계약 기준 추가 가입 한도, 보험료 우열(보험료 자료가 들어오기 전), 고객 정보 저장.

법령. 금융소비자 보호에 관한 법률 제21조 제1호(불확실한 사항에 대한 단정적 판단 제공)와 제4호(금융상품 내용의 일부에 대하여 비교대상 및 기준을 밝히지 아니하거나 객관적인 근거 없이 다른 금융상품과 비교하여 해당 금융상품이 우수하거나 유리하다고 알리는 행위)는 국가법령정보센터에서 문구를 확인했다. 민영 보험에 적용되는 기준이다. 우체국보험에 직접 적용되는지는 확인이 필요하고, 같은 수준으로 지키는 것을 원칙으로 삼는다. 범위 머리말, 금지어, 빼는 조건이 이 원칙을 화면에서 지키는 장치다. 보험업법과 협회 광고 규정의 조문 번호는 확인하지 못해 적지 않는다.

사용자가 정할 것
1. 공개 주소(GitHub Pages)로 나가는 화면에 타사 실명 비교, 영업 문장, "대외 배포 금지" 표식이 붙은 응대 카드가 함께 실려도 괜찮은지. 공개본에서 카드와 영업 포인트 탭을 감출지, 표식을 바꿀지를 정해야 한다.
2. 핵심 분야와 대표 담보의 기준. 카드의 핵심 담보 6행과 목적 묶음이 이 기준을 쓴다. 임시 기준은 표준담보 사전의 보장대분류(암보장, 뇌혈관보장, 심장보장, 뇌심장보장)다.
3. 탭 구성. 이 문서의 다섯 탭(브리핑, 가입 설계, 담보 비교, 영업 포인트, 시장과 고객군)과 카본의 네 탭 가운데 무엇으로 갈지.
4. 추천 목적의 화면 이름. 기획 확정본은 "암 집중, 3대 질병 균형, 입원·수술 실속"(3.3절)인데 "실속"은 보험료 없이 가격을 말하는 것으로 읽힌다. 화면 이름만 "암, 3대 질병, 입원과 수술"로 바꿀지, 기획 문구도 바꿀지.
5. 응대 문장의 쓰임. 담당자가 읽고 자기 말로 옮기는 내부 참고로 둘지, 창구가 고객에게 그대로 말해도 되는 문장으로 둘지. 사내 준법 확인 전까지는 내부 참고로 두기를 권한다.
