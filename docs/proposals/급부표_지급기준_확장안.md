# 급부 표 지급기준구분 확장안 (초안)

작성 2026-11-23, Claude Code(조사와 초안). 이 문서는 제안입니다. 리포의 코드, 문서, 시험, 시트는 고치지 않았습니다. 조사는 읽기와 읽기 전용 실행(사본 형식 검사, 화면 자료를 임시 폴더에 다시 만들기, 메리츠화재 요약서로 행 만들기를 흉내 낸 실행)으로만 했습니다.

## 1. 요약

- 지급기준구분에 값 넷을 더합니다: **차등지급, 실손보상, 분할지급, 현물급부**. 판독 도구의 세부 사유(열다섯 가지)는 값으로 쓰지 않고 작업 로그의 사유에 남깁니다(3절).
- 이 넷 가운데 하나인 급부는 기준가입금액만원과 기준지급금액만원을 비웁니다. 형식 검사는 "넷 가운데 하나일 때만 두 금액을 비울 수 있고, 그때는 반드시 비어 있어야 한다"로 바꿉니다(4절).
- 화면 계산은 그런 급부를 보유로 셉니다. 지급액은 지금의 "금액 자료 없음" 부호를 그대로 쓰고, 지급 형태 항목은 "다름"(우열을 매기지 않음), 감액 항목은 "판정 보류"로 둡니다. 새 판정 이름은 만들지 않습니다(5절).
- 이미 적재된 세 회사(우체국, 한화생명, 삼성화재)의 행, ID, 화면 자료는 바뀌지 않습니다. 새 키는 모두 그 값이 있는 급부에만 붙입니다(8절).
- 정해 준 방향과 다른 의견이 하나 있습니다. 감액 네 칸과 감액예외는 "읽은 대로 채우기"가 아니라 비워야 합니다. 두 판독이 행없음 줄의 감액을 읽지 않았고, 191줄 가운데 70줄은 원문에 기간별, 회차별 비율이 있어 빈칸이 "감액 없음"으로 읽히기 때문입니다(2.3절, 14절).

### 2.3 메리츠화재 행없음 줄

판정이 끝난 판독 값(`data/crosscheck/meritz_*_benefits_2reader.jsonl`) 869줄 가운데 꼴이 행없음인 줄은 191줄(22%)입니다(알파Plus 106, 통합간편 85). 사유별 줄 수는 3.2절의 표에 적었습니다. "그밖"은 0줄입니다.

두 판독은 행없음 줄에서 사유, 면책일수, 보장개시일, 한도만 읽고 견줬습니다. 판독 지시문(`docs/backfill_reader_guide.md` 75줄)이 "나머지 칸(지급률, 감액 따위)은 비워도 된다"고 적고 있고, 견주는 칸(`reader_rows.py` 430~436)과 기계 검사(911~927, 977~995)도 행없음 줄의 감액과 지급단위를 보지 않습니다. 실제로 191줄 모두 감액, 감액예외, 지급단위, 대상이 비어 있습니다.

요약서를 다시 읽어, 조각 글자에 감액을 가리키는 말(`reader_rows._CUT_HINT`. "1년 미만 50%" 같은 꼴)이 있는 줄을 세었습니다.

| --- | --- | --- |
| 경과기간별지급률 | 37 | 23 |
| 가입금액구간별금액표 | 41 | 25 |
| 회차별지급률 | 14 | 7 |

70줄은 감액이 따로 있다기보다 지급률 표 안에 기간별 비율로 들어 있는 경우가 많습니다. 감액 두 구간으로 옮길 수 없어서 행없음이 된 줄이기도 합니다.

행 만들기를 흉내 낸 실행의 결과입니다. 행없음 줄을 금액이 빈 행으로 바꾸도록 함수 둘을 바꿔 끼우고 돌렸습니다(읽기 전용. 갱신형 특약은 모두 20년, 갱신형특약제외는 적용하지 않음).

- 지금 만들어지는 행은 급부ID와 값이 하나도 바뀌지 않았습니다(빠진 ID 0, 값이 바뀐 ID 0).
- 이름이 같은 세부보장 묶음 때문에 막힌 줄과 급부ID가 겹친 줄은 없었습니다.
- 새 행 195개 가운데 감액이 있는 행은 0, 면책이 있는 행은 54, 지급횟수제한이 있는 행은 89입니다.
- 표준담보 매핑 의견(`data/crosscheck/meritz_mapping_opinion_2reader.jsonl`)에는 행없음 줄의 묶음 174개가 이미 들어 있습니다. 두 의견이 같은 150개 가운데 암 주요치료비 36, 간병인 사용 입원일당 31, 종별 수술비(최고 종 기준) 11처럼 우체국에도 있는 담보가 많습니다. 지금은 이 담보들이 메리츠화재에 없는 것으로 보입니다.

## 4. 형식 검사의 새 규칙

아래에서 "금액 없는 값"은 차등지급, 실손보상, 분할지급, 현물급부 넷을 말합니다.

1. 허용 값은 금액, 가입금액비율, 차등지급, 실손보상, 분할지급, 현물급부입니다. 빈칸은 지금처럼 금액으로 봅니다.
2. 지급기준구분이 비었거나 금액이나 가입금액비율이면, 기준가입금액만원과 기준지급금액만원이 모두 있어야 하고 0보다 커야 합니다(지금과 같습니다).
3. 지급기준구분이 금액 없는 값이면, 기준가입금액만원, 기준지급금액만원, 감액개월1, 감액지급률1, 감액개월2, 감액지급률2, 감액예외가 모두 비어 있어야 합니다.
4. 면책기간일수(필수), 급부역할(필수), 지급횟수제한, 근거문서종류, 근거문서쪽수는 지금 규칙 그대로입니다.

구현은 갱신주기년의 선례를 따릅니다. 갱신주기년은 선택 열이고, "갱신형인데 갱신주기년이 비어 있음"은 `_logic`이 냅니다. 같은 방식으로 두 금액 열을 스키마에서 선택 열로 바꾸고 2번과 3번을 `_logic`에 둡니다. 스키마의 "필수"가 조건 없이 필수라는 뜻을 지킬 수 있습니다. 문제 글은 "지급기준구분이 금액인데 기준지급금액만원이 비어 있음", "지급기준구분이 차등지급인데 기준가입금액만원이 있음", "지급기준구분이 차등지급인데 감액이 있음" 꼴입니다.

3번이 이 안의 안전장치입니다. 행없음 줄로 행을 만들 때 `reader_rows._row`는 `table_rules.benefit_row`를 부르는데, 이 함수는 기준가입금액 100, 기준지급금액 100, 지급기준구분 가입금액비율을 채웁니다. 덮어쓰기를 하나라도 빠뜨리면 "가입금액의 100%"라는 그럴듯한 가짜 값이 정본에 들어갑니다. 3번이 있으면 그런 행은 형식 검사에서 걸립니다.

## 5. 화면 계산: 보유는 세고 우열은 매기지 않는다

### 5.1 고른 길

| 항목 | 금액 없는 급부가 낀 짝 | 쓰는 이름 |
| --- | --- | --- |
| 보유 | 매핑이 확정이면 보유로 셉니다. 작업 로그 대기가 아니므로 "확실한 보유"에도 듭니다 | 지금과 같습니다 |
| 지급액 | 비교표 부호 x. 사유 글만 "지급 형태가 달라 금액을 견주지 않음"으로 바꿉니다 | 지금의 x |
| 면책 | 지금처럼 견줍니다(두 판독이 읽고 견준 값) | 같음, 나음, 못함 |
| 감액 | 사유 "지급 형태가 달라 감액을 견주지 않음"으로 보류합니다 | 판정 보류 |

지급 형태가 다름이면 지금 규칙대로 설계 차이 시사점이 되고, 영업 인사이트의 단정 주의 목록에 "{담보}는 지급 형태가 달라 우열을 매기지 않았습니다"로 나옵니다. 브리핑 (라)의 "지급 형태가 다른 것" 수에도 듭니다. 시안 4의 담보별 판정 집계는 단정 주의를 판정 보류보다 먼저 보므로 "단정 주의"로 셉니다(`console4.verdict_codes`).

지급 형태 항목의 양쪽 글은 꼬리표 대신 지급 기준으로 적습니다. 금액이나 가입금액비율 쪽은 "정액 지급"(꼬리표가 있으면 "정액 지급(최초 1회)"), 금액 없는 쪽은 값 그대로입니다. 지금 꼬리표 글은 문구가 비면 "문구 없음"이라, 그대로 두면 단정 주의 문장이 "우체국 2종은 문구 없음"이 됩니다.

### 5.3 대표 급부

한 칸에 금액 급부와 금액 없는 급부가 함께 있으면 `pick_rep`가 금액 급부를 대표로 고릅니다(값이 없는 줄은 뒤로 밀립니다. Python과 calc.js가 같습니다). 그 칸의 우열은 금액 급부로 매기고, 금액 없는 급부는 "대표 밖에 조건이 다른 줄"로 세어 조건 우열 문장을 단정 주의(조건이 다른 특약 함께 판매)로 돌립니다. 이렇게 하려고 `condition_signature`에 꼴을 넣습니다.

## 8. 기존 세 회사 자료가 바뀌지 않음을 확인하는 방법

판단: 바뀌지 않습니다. 근거는 다음과 같습니다.

- 시트의 기존 행에 손대지 않고, `ids.py`를 고치지 않습니다.
- 기존 6,615행은 두 금액이 모두 있고 지급기준구분이 빈칸이나 가입금액비율이라 새 형식 검사의 2번에만 해당하며, 2번은 지금 규칙과 같습니다.
- 새 키(`form`, `formText`, cover.json의 두 키)는 금액 없는 급부가 있을 때만 싣고, 판정 함수의 새 갈래도 `form`이 있을 때만 탑니다.
- 지금 사본으로 임시 폴더에 다시 만든 `site/index.html`, `proto_src/console4`의 일곱 파일(sales.json, combo.json, gate.json, cover.json, d.json, tab3.js, tab4.js), `proto_src/graph/graph.json`이 커밋된 파일과 바이트까지 같았습니다. 그래서 커밋된 파일과 바로 견줄 수 있습니다.

확인 명령(구현 전에 한 번, 단계마다 한 번)

```bash
cd /data/projects/post_life
T=$(mktemp -d)
python3 scripts/build_site.py --out $T/index.html
python3 scripts/export_app_data.py --out $T/c4
python3 proto_src/graph/build_data.py $T/graph.json

# 1단계(Python과 자료만 고친 커밋): 화면 파일까지 바이트가 같아야 한다
cmp $T/index.html site/index.html
for f in sales.json combo.json gate.json cover.json d.json tab3.js tab4.js; do cmp $T/c4/$f proto_src/console4/$f; done
cmp $T/graph.json proto_src/graph/graph.json

# 2단계(app.js를 고친 커밋): HTML은 코드가 바뀌므로 안에 실은 자료만 같아야 한다
python3 - "$T/index.html" <<'EOF'
import subprocess, sys
sys.path.insert(0, "src")
from postlife.site.build import read_payload
old = subprocess.run(["git", "show", "HEAD~1:site/index.html"], capture_output=True, text=True, check=True).stdout
print("자료 같음" if read_payload(old) == read_payload(open(sys.argv[1], encoding="utf-8").read()) else "자료 다름")
EOF

# 3단계(Antigravity가 tab4.src.js를 고친 PR): cover.json은 같고 tab4.js는 코드 부분만 다르다
cmp $T/c4/cover.json proto_src/console4/cover.json

# 사본과 형식 검사
git diff --exit-code data/snapshot
python3 -c "import sys; sys.path.insert(0,'src'); from pathlib import Path; from postlife.snapshot import read_snapshot; from postlife.validate import check_rows; d=read_snapshot(Path('data/snapshot')); print({t: len(check_rows(t, d[t])) for t in d})"
```

마지막 줄은 모든 탭에서 0이 나와야 합니다. sys_급부, sys_특약, sys_상품종형에서 지금 0인 것을 확인했습니다.

## 10. 시트 쪽 작업

- 머리글은 그대로입니다. 지급기준구분 열은 시트에 이미 있습니다(사본의 모든 행에 이 열이 있습니다). `scripts/add_column.py`를 돌릴 일이 없습니다.
- 기존 행에 손댈 것이 없습니다. 고친 적재 도구를 다시 돌리면 메리츠화재 정밀비교 종형의 행만 바뀝니다(`replace_variants`).
- 새 급부의 매핑은 이미 받은 두 판독 의견(행없음 묶음 174개, 같은 의견 150개)으로 넣습니다. 새 회사의 매핑 확정 기준(두 판독이 같으면 확정)을 그대로 씁니다.
- 코드가 시트에 데이터 확인 규칙(드롭다운)을 건 곳은 없습니다. 사람이 시트에서 걸어 두었는지는 확인하지 못했습니다. 걸려 있다면 값 넷을 더해야 쓰기가 막히지 않습니다.
