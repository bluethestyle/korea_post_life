# UI/UX 개편안 (초안)

2026-11-20, Claude 초안. 제미나이 카본과 논의해 고칠 문서입니다. 온톨로지 설계안(`docs/proposals/온톨로지_설계안.md`)과 짝입니다.

## 1. 요구

사용자가 정한 방향입니다(2026-11-20).

- 실무자의 사용자 경험에 맞춰 화면 흐름을 배치한다.
- 직관성과 가독성이 중심이다.
- 쓰는 내내 감탄이 나올 만큼 수려하고 부드러운 애니메이션을 넣되, 사용감을 해치지 않는 구동 속도여야 한다.
- 스타일은 미래를 배경으로 한 콘솔 게임들이 잘하는 UI 요소와 시각 효과에서 가져온다.

특정 게임의 화면을 베끼지 않습니다. 그 장르가 공통으로 쓰는 화면 문법(브리핑, 스캔, 장비 비교, 노드 격자, 도감)을 보험 실무에 맞게 옮긴 우리 디자인을 만듭니다.

## 2. 지금 화면의 문제

- 탭 여섯 개가 자료 종류대로 나뉘어 있어, 실무자가 "내 질문이 어느 탭에 있는지"를 먼저 알아야 합니다.
- 비교표 한 화면이 5,000px가 넘는 표입니다. 결론이 표 속에 묻혀 있습니다.
- "검토 대기", "자료 없음" 같은 내부 상태가 실무 정보보다 먼저 보입니다.
- 관계(같은 담보에 이어진 회사별 특약)가 그림으로 보이지 않습니다.
- 화면이 바뀔 때 무엇이 왜 바뀌었는지 알려 주는 움직임이 없습니다.

## 3. 누가 언제 쓰나

| 실무자 | 쓰는 때 | 원하는 것 | 걸리는 시간 |
| --- | --- | --- | --- |
| 영업 지원 | 고객 문의가 왔을 때 | 이 고객 조건에서 우리가 나은 점, 못한 점, 응대 카드 | 1~2분 |
| 청약 심사 | 가입 가능 여부를 볼 때 | 나이와 병력 수준에서 가능한 종형, 한도, 제약 | 1분 |
| 상품 개발 | 주간 점검, 개정 기획 | 경쟁 구도, 빈자리, 시장 움직임, 근거 | 10~30분 |

세 사람 모두 "조건을 넣고, 결론을 보고, 필요하면 근거까지 내려간다"는 같은 순서로 씁니다. 화면 흐름을 이 순서에 맞춥니다.

## 4. 화면 흐름: 브리핑, 렌즈, 초점, 근거

탭 여섯 개를 네 단계로 다시 묶습니다. 어디서든 근거까지 두 번 누르면 닿게 합니다.

| 단계 | 화면 | 내용 | 지금의 탭 |
| --- | --- | --- | --- |
| 0 | 조건 줄 (늘 위에 있음) | 고객 조건(나이, 성별, 심사 등급), 기준 상품, 말로 묻는 입력 줄. 바꾸면 모든 화면이 따라 바뀜 | 탭마다 따로 있던 입력 |
| 1 | 브리핑 | 시사점 카드(우선순위 순), 경쟁 지형도, 이번 주 시장 소식 줄, 자료 신뢰도 계기 | 1번 탭과 새 기능 |
| 2 | 렌즈 셋 | 고객 렌즈(가입 적격, 관문, 조합 지급액), 경쟁 렌즈(분야별 비교, 대응 특약), 변화 렌즈(시장 소식, 개정 전후) | 2, 4번 / 3번 / 1, 5번 |
| 3 | 초점 | 담보 하나를 가운데 둔 관계 그림. 회사별 특약과 급부, 조건 차이 | 3번 탭의 칸 상세 |
| 4 | 근거 서랍 | 문서 종류, 쪽, 원문 특약명, 판정 기록. 오른쪽에서 열림 | 3번 탭의 근거 창, 6번 탭 |
| 출력 | 응대 카드 | A4 한 장 인쇄 | 그대로 |

6번 탭(AI 작업 내역)은 "자료 신뢰도"로 이름을 바꾸고 주 메뉴에서 뺍니다. 브리핑의 계기와 값 옆의 신뢰 표시를 누르면 열립니다.

## 5. 게임 UI에서 가져오는 화면 문법

| 문법 | 게임에서의 쓰임 | 우리 화면에서 |
| --- | --- | --- |
| 임무 브리핑 | 출격 전에 상황과 목표를 한 화면으로 | 브리핑: 이번 주 상황과 봐야 할 것 세 가지 |
| 늘 떠 있는 상태 표시 | 체력, 탄약처럼 판단에 필요한 값만 화면 가장자리에 | 조건 줄: 고객 조건과 기준 상품 |
| 스캔 모드 | 단추를 누르면 약점과 상호작용 대상이 강조됨 | 스캔: 어느 화면에서든 열위와 빈자리만 빛나게 |
| 장비 비교 | 두 장비의 능력치를 나란히 놓고 차이를 화살표와 색으로 | 담보 비교: 지급액, 면책, 감액, 지급 형태를 능력치 막대와 차이 표시로 |
| 노드 격자 | 해킹 화면처럼 격자에 놓인 노드와 직각 연결선 | 초점: 담보 대응 그림, 대응 특약 그림 |
| 기술 트리 | 선행 조건이 선으로 이어진 나무 | 특약 조합: 선행가입, 의무부가, 배타선택을 선으로 |
| 도감 | 수집한 정보의 항목과 출처 | 근거 서랍: 문서와 쪽, 표준담보 설명 |
| 알림 띠 | 달성과 변화가 잠깐 떴다 사라짐 | 조건을 바꿨을 때 달라진 결론 수 |

## 6. 시각 언어

- 바탕: 밝은 쪽을 기본으로 합니다(사용자 의견, 2026-11-20). 미래 배경의 게임에는 어두운 관제실만 있는 것이 아니라 희고 밝은 연구 시설 분위기도 흔하고, 이 앱은 낮의 사무실에서 긴 표와 글을 읽는 도구이며 인쇄물과 보고서에 화면을 옮겨 붙이는 일이 많기 때문입니다. 어두운 모드는 버전 1 뒤에 선택 사항으로 둡니다. 두 모드를 함께 만들면 색과 대비를 두 벌로 점검해야 해서 버전 1의 일이 늘어납니다.
- 색: 바탕은 아주 옅은 회백색, 패널은 흰 면에 옅은 선과 얕은 그림자. 글자는 짙은 남색 계열. 강조색은 하나(짙은 청록)만 쓰고 우체국을 뜻합니다. 밝은 바탕에서는 옅은 청록이 읽히지 않으므로 채도와 명도를 낮춘 짙은 값으로 씁니다. 경쟁사는 서로 구별되는 색 셋을 쓰되 색각 이상에서도 구별되게 무늬나 모양을 함께 씁니다. 판정 색은 나음, 못함, 엇갈림, 빈자리 넷으로 고정합니다.
- 선과 모양: 1px 가는 선, 모서리를 깎은 패널, 모서리 괄호, 옅은 점 격자 바탕. 밝은 바탕에서는 빛 번짐이 보이지 않으므로, 초점과 선택은 강조색 선과 옅은 색 면, 얕은 그림자의 깊이로 드러냅니다. 유리처럼 비치는 면은 글자 뒤에 쓰지 않습니다.
- 글자: 시스템 한글 글꼴(외부 글꼴을 싣지 않음), 숫자는 자릿수 폭이 같은 숫자. 본문 15~16px, 줄 간격 1.6, 표는 밀도를 두 단계로 고르게 합니다.
- 숫자 표기: 단위를 늘 붙이고, 차이는 화살표와 부호로 적습니다. 색만으로 뜻을 전하지 않습니다.
- 대비: 본문 글자와 바탕의 명암비 4.5:1 이상.

## 7. 그래프 표현

관계를 그림으로 보여 주는 화면의 규칙입니다. 점과 선이 엉킨 그물 그림은 쓰지 않습니다. 자리 자체가 뜻을 갖는 정해진 배치만 씁니다(같은 자료는 늘 같은 그림이 되고, 배치 계산이 가벼움).

그림마다 배치를 고정합니다

| 그림 | 배치 | 자리가 뜻하는 것 |
| --- | --- | --- |
| 담보 대응 그림 | 표준담보를 위 가운데에 두고, 아래에 회사마다 세로 레인 하나 | 가로는 회사(우체국이 늘 맨 왼쪽), 세로는 표준담보에서 특약, 급부로 내려가는 깊이 |
| 대응 특약 그림 | 세 기둥: 우리 특약의 급부, 표준담보, 타사 특약의 급부 | 가운데 기둥에서 한쪽으로만 선이 나가면 한쪽에만 있는 담보 |
| 경쟁 지형도 | 격자(선으로 잇지 않음): 세로는 보장 분야, 가로는 치료 여정 | 칸 안의 회사 표식 세 개로 보유와 조건 우열 |
| 표준담보 관계 | 들여 쓴 나무와 묶음 괄호 | 들여쓰기는 포함, 괄호는 통합 |
| 특약 결합 제약 (버전 1 뒤) | 위에서 아래로 내려가는 층 그림 | 위는 주계약, 아래로 갈수록 선행 조건이 많은 특약 |

포함은 선이 아니라 상자로 그립니다

- 종형이 특약을 갖고 특약이 급부를 갖는 관계는 상자 안에 넣어 보여 줍니다(특약은 상자, 급부는 그 안의 칩). 선은 상자를 건너는 관계(급부가 표준담보에 해당함, 표준담보끼리의 포함과 통합, 특약끼리의 대응과 제약)에만 씁니다. 선의 수가 크게 줄어 읽기 쉬워집니다.

모양, 색, 선

| 무엇 | 규칙 |
| --- | --- |
| 노드 모양 | 표준담보는 모서리를 깎은 육각 상자, 특약은 둥근 사각 상자, 급부는 알약 모양 칩, 문서 근거는 작은 문서 표식, 이벤트는 마름모, 시사점은 깃발 |
| 노드 색 | 회사 색을 옅게 깐 면. 표준담보는 회사와 무관하므로 무채색 |
| 선 모양 | 시트에 적힌 사실과 확정된 매핑은 실선, 검토 대기는 점선, 계산으로 만든 관계(대응, 닮음)는 파선 |
| 선 굵기 | 뜻을 싣지 않음(닮은 정도를 보일 때만 두 단계) |
| 판정 | 급부 칩 오른쪽 끝의 작은 배지(나음, 못함, 엇갈림)와 화살표. 색만으로 전하지 않음 |
| 글자 | 늘 가로쓰기, 두 줄까지. 넘치면 줄이고 가리키거나 초점이 가면 전체를 보여 줌. 급부 칩 안에는 지급액, 면책, 감액을 작은 숫자 줄로 |
| 범례 | 그림 구석에 늘 보이게, 다섯 항목 이내 |

많을 때

- 한 그림에 보이는 노드는 40개 안쪽으로 합니다. 넘으면 "12개 더"처럼 접어 두고 누르면 펼칩니다.
- 회사가 늘어도 레인은 우체국과 고른 경쟁사 서너 곳까지만 세웁니다. 나머지 회사는 "이 담보를 가진 회사 몇 곳, 없는 회사 몇 곳" 띠로 요약하고, 전체 회사는 격자 그림에서 봅니다.

조작

- 노드에 가리키거나 초점이 가면 가운데 표준담보까지의 길만 남기고 나머지를 흐리게 합니다.
- 노드를 누르면 근거 서랍이 열립니다.
- 이웃한 표준담보(포함, 통합 관계)를 누르면 그 담보가 가운데로 옮겨 오고, 지나온 담보가 위에 자취로 남습니다.
- 키보드: 방향키로 선을 따라 옮기고, Enter로 서랍, Esc로 닫습니다.
- 마음대로 끌거나 확대하는 조작은 두지 않습니다(그림이 늘 화면 폭에 맞음). 좁은 화면에서는 레인이 세로로 쌓입니다.
- 모든 그림에 "표로 보기" 전환을 둡니다. 같은 자료를 표로 보여 주고, 복사해 붙이기와 화면 낭독기를 위한 것입니다.

입체 표현 (사용자 물음, 2026-11-20: 3차원 공간에 입체로 놓으면 브라우저 자원을 너무 먹는가)

- 자원은 문제가 아닙니다. 한 그림의 노드가 수십 개에서 수백 개라, 그래픽 가속을 쓰면 사무용 PC의 내장 그래픽으로도 초당 60프레임이 나옵니다. 부담은 그리는 쪽이 아니라 글자(한글 이름과 숫자를 입체 공간에 선명하게 놓는 일)와, 라이브러리를 쓸 수 없다는 제약(외부 요청 없음, 파일 하나)에서 옵니다.
- 문제는 읽기입니다. 마음대로 돌리는 입체 그물 그림은 뒤 노드가 앞 노드에 가리고, 원근 때문에 길이와 위치를 견줄 수 없고, 돌려 봐야 보이므로 조작이 늘어납니다. 직관성과 가독성이라는 기준에 맞지 않습니다.
- 그래서 깊이에 뜻을 실은 층 배치(2.5차원)만 씁니다. 깊이 축에 회사(회사마다 반투명한 판 하나, 같은 자리에 같은 담보), 또는 개정 시점(지난 개정판이 뒤로 물러남)을 싣습니다. 카메라는 살짝 기울인 자리로 고정하고, 마우스를 움직이면 몇 도만 따라 움직이며, 판을 누르면 그 판이 앞으로 나와 평면으로 펴집니다. 읽을 때는 늘 평면입니다.
- 초점 화면으로 들어갈 때 깊이 방향으로 다가가는 전환에도 씁니다. 전환이 끝나면 평면으로 앉습니다.
- 구현은 CSS의 3차원 변형(원근, 깊이 이동, 기울임)으로 합니다. 판과 노드는 HTML 그대로라 글자가 선명하고 그래픽 가속을 탑니다. 움직이는 요소는 150개 안쪽으로 두고, 조작이 없을 때는 그리지 않습니다. "평면으로 보기" 단추를 늘 둡니다.

그리는 방법

- 노드는 HTML 요소(단추)로 놓고 CSS 격자로 배치합니다. 한글 글자가 가장 잘 그려지고 키보드와 낭독기가 그대로 통합니다. 선은 그 위에 겹친 SVG 한 장에 그리고, 노드의 화면 위치를 읽어 계산합니다. 창 크기가 바뀌면 선만 다시 그립니다.
- 선은 가운데에서 바깥으로 자라고(선의 그려진 길이를 늘림), 노드는 투명도와 위치로 나타납니다. 물리 계산으로 계속 흔들리는 배치는 쓰지 않습니다.

## 8. 인터랙션

모든 시각화는 보는 그림이 아니라 만지는 그림입니다(사용자 요구, 2026-11-20). 그림마다 조작을 따로 지어내지 않고, 아래 공통 문법을 모든 그림에 똑같이 씁니다. 한 그림에서 익힌 조작이 다른 그림에서도 통해야 합니다.

공통 문법

| 조작 | 마우스 | 키보드 | 터치 | 일어나는 일 |
| --- | --- | --- | --- | --- |
| 미리 보기 | 가리키기 | 초점 이동(Tab, 방향키) | 한 번 누르기 | 정확한 값과 단위, 근거 쪽이 작은 창에 뜨고, 이어진 것만 남기고 나머지가 흐려짐 |
| 내려가기 | 누르기 | Enter | 미리 보기 창의 "자세히" | 한 단계 깊은 화면(초점 화면이나 근거 서랍)이 열림 |
| 고정해 견주기 | Shift 누른 채 누르기, 또는 핀 단추 | 스페이스 | 길게 누르기 | 그 항목이 고정되고, 다음에 가리키는 항목과 나란히 차이가 표시됨. 둘까지 |
| 거르기 | 범례나 칩 누르기 | 범례에 초점 두고 Enter | 범례 누르기 | 그 회사나 판정만 남김. 다시 누르면 풀림 |
| 범위 고르기 | 끌기 | Shift와 방향키 | 두 손가락 또는 손잡이 끌기 | 나이 구간이나 기간을 골라 조건 줄에 반영 |
| 되돌아가기 | 바깥 누르기, 뒤로 단추 | Esc | 뒤로 쓸기 | 한 단계 위로. 고른 것과 스크롤 자리가 그대로 남음 |
| 표로 보기 | 그림 구석의 전환 단추 | 같은 단추 | 같은 단추 | 같은 자료를 표로. 복사할 수 있음 |

연동

- 어느 그림에서든 회사 하나를 가리키면 화면의 모든 그림에서 그 회사가 강조됩니다. 표준담보도 같습니다.
- 조건 줄(나이, 성별, 심사 등급, 기준 상품)을 바꾸면 모든 그림이 함께 바뀌고, 달라진 값만 잠깐 표시됩니다.
- 그림에서 고른 것(담보, 회사, 나이 구간)은 조건 줄에 칩으로 쌓여, 지금 무엇으로 걸러 보고 있는지가 늘 보입니다. 칩의 가위표로 풉니다.
- 주소 뒤에 고른 상태를 실어, 같은 화면을 주소로 전하거나 새로 고쳐도 그대로 열리게 합니다.

그림마다

| 그림 | 미리 보기 | 내려가기 | 견주기와 거르기 | 그 밖 |
| --- | --- | --- | --- | --- |
| 시사점 카드 | 근거가 된 담보와 회사 수 | 그 시사점의 초점 화면 | 유형(열위, 빈자리, 고유, 조건 격차)으로 거르기 | 카드를 넘기면 다음 우선순위. 본 카드는 표시가 남음 |
| 경쟁 지형도 (격자) | 칸의 회사별 담보 수와 조건 우열 요약 | 그 분야와 여정 단계의 담보 비교 | 회사 표식을 눌러 한 회사만, 줄 머리를 눌러 한 분야만 | 칸 두 개를 고정해 나란히 |
| 담보 비교 (능력치 막대) | 막대의 정확한 값, 단위, 차이, 근거 쪽 | 그 담보의 초점 화면 | 기준 회사 바꾸기, 판정(나음, 못함)으로 거르기, 분야로 거르기 | 줄 머리를 눌러 정렬(차이 큰 순). 줄을 고정해 응대 카드에 담기 |
| 담보 대응 그림 | 노드의 조건과 근거, 가운데까지의 길 강조 | 급부는 근거 서랍, 이웃 표준담보는 가운데로 옮김 | 회사 레인 켜고 끄기 | 지나온 담보의 자취에서 되돌아가기 |
| 대응 특약 그림 | 선이 잇는 두 급부의 조건 차이 | 급부의 근거 서랍 | 타사 특약 묶음 가운데 하나만 보기 | 한쪽에만 있는 담보만 남기기 |
| 가입 나이 막대 | 그 나이의 가입 가능 여부와 최대 가입금액 | 그 종형의 특약 조합 화면 | 회사로 거르기 | 막대 위를 끌어 나이를 고르면 조건 줄의 나이가 바뀜 |
| 특약 조합 지급액 | 막대의 지급액과 감액 기간 지급액 | 대표 급부의 근거 서랍 | 특약을 켜고 끄면 막대가 바로 바뀜 | 금액을 직접 고치면 제약에 걸리는 특약이 표시됨 |
| 개정 시간선 | 개정판의 적용 기간과 바뀐 항목 수 | 개정 전후 비교 | 기간을 끌어 고르기 | 두 시점을 고정해 견주기 |
| 시장 소식 | 요약 전체와 매체 | 출처를 새 창으로 | 분류와 회사로 거르기 | 소식이 다루는 담보를 누르면 그 담보의 초점 화면 |
| 자료 신뢰도 계기 | 확정, 검토 대기, 제외 수 | 작업 기록 목록 | 단계와 결과로 거르기 | 값 옆의 신뢰 표시를 누르면 그 값의 기록만 |

지킬 것

- 가리키기만으로 되는 일은 없게 합니다. 가리키기로 보이는 것은 모두 키보드 초점과 터치로도 보입니다.
- 누를 수 있는 것은 누를 수 있게 생기게 합니다(가리키면 모양이 바뀌고, 초점 테두리가 보임). 누를 수 없는 장식은 반응하지 않습니다.
- 조작의 결과는 100ms 안에 화면에 나타나기 시작합니다. 계산이 길면 먼저 자리를 잡아 두고 값을 채웁니다.
- 자료가 없는 칸은 비워 두지 않고 왜 없는지(판매하지 않음, 공시에 없음, 검토 대기)를 미리 보기에 적습니다.
- 누르는 자리는 좁은 화면에서 44px 이상으로 합니다.

## 9. 움직임

원칙

- 움직임은 인과를 보여 줍니다. 무엇을 눌러서 무엇이 어디서 나왔는지가 보여야 합니다.
- 입력을 막지 않습니다. 모든 전환은 도중에 끊고 다음 동작으로 넘어갈 수 있습니다.
- 길이: 전환 200~300ms, 처음 한 번 보여 주는 등장 400~600ms. 같은 등장은 다시 보여 주지 않습니다.
- 성능: 위치와 투명도만 움직입니다(레이아웃을 다시 계산하는 속성은 움직이지 않음). 화면 밖은 움직이지 않습니다. 목록은 차례로 나오되 전체 300ms 안에 끝냅니다. 초당 60프레임을 지키지 못하는 효과는 뺍니다.
- 움직임 줄이기 설정(prefers-reduced-motion)을 켠 사람에게는 모두 바로 바뀌게 합니다.

대표 장면

| 장면 | 움직임 | 뜻 |
| --- | --- | --- |
| 브리핑 열림 | 패널 테두리가 선으로 그려지고 숫자가 올라감 | 자료를 불러 조립했다 |
| 조건 변경 | 스캔 선이 한 번 지나가고 달라진 값만 깜빡이며 바뀜 | 이 조건에서 달라진 것은 이것이다 |
| 초점 진입 | 누른 칸이 가운데 노드로 옮겨 가고 연결선이 바깥으로 자람 | 이 값은 이 관계에서 나왔다 |
| 근거 열기 | 서랍이 밀려 나오고 해당 쪽에 괄호가 맞춰짐 | 출처는 여기다 |
| 스캔 켜기 | 열위와 빈자리만 남기고 나머지가 어두워짐 | 봐야 할 곳은 여기다 |
| 말로 묻기 | 풀이된 낱말이 조건 칩으로 날아가 꽂힘 | 질문을 이렇게 이해했다 |

기술: 외부 라이브러리 없이 CSS 전환, Web Animations API, 화면 전환 API(View Transitions, 지원하지 않는 브라우저에서는 바로 전환)를 씁니다. 관계 그림은 노드 300개 이하이면 SVG, 넘으면 캔버스로 그립니다. 긴 표는 보이는 줄만 그립니다.

## 10. 지킬 제약

- 오프라인 단일 HTML, 외부 요청 없음. 글꼴, 라이브러리, 그림을 밖에서 불러오지 않습니다.
- 380px와 1280px에서 잘림과 겹침이 없어야 합니다. 응대 카드는 A4 한 장입니다.
- 사무용 PC의 크롬과 엣지에서 첫 화면이 1초 안에 떠야 합니다.
- 키보드만으로 모든 기능을 쓸 수 있어야 합니다.

## 12. 열린 질문

1. 브리핑, 렌즈, 초점, 근거의 네 단계 흐름이 세 실무자의 실제 일 순서와 맞는가. 빠진 길이나 지나친 단계는 무엇인가.
2. 밝은 바탕을 기본으로 하면서 미래형 콘솔의 인상과 감탄을 내려면 무엇으로 내야 하는가(어두운 바탕의 빛 번짐과 대비 효과를 쓸 수 없음). 어두운 모드를 버전 1에서 빼는 것이 맞는가.
3. 게임 UI 문법 여덟 가지 가운데 실무 도구에 옮겼을 때 효과가 큰 것과 겉멋에 그칠 것은 무엇인가. 빠진 문법은 무엇인가.
4. 감탄이 나오면서도 매일 쓰는 도구로서 질리거나 느려지지 않게 하려면 움직임을 어디에 쓰고 어디에 쓰지 말아야 하는가.
5. 단일 HTML, 외부 요청 없음, 사무용 PC라는 제약에서 초당 60프레임을 지키기 어려운 효과는 무엇이고 대안은 무엇인가.
6. 다음 주 초 버전 1에 넣을 화면과 움직임의 최소 묶음은 무엇인가.
7. 그래프 표현(7절)과 인터랙션(8절)에서 배치, 모양, 선의 규칙이 실무자에게 바로 읽히는가. 포함을 상자로, 건너는 관계만 선으로 그리는 방식과 정해진 배치만 쓰는 방식의 약점은 무엇인가. 회사가 19곳으로 늘 때 어떻게 버티는가.
