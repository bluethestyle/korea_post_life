# 우체국보험 상품·청약 판단 지원 앱 제출 설명 자료 (초안)

기준일은 2026-11-25입니다. 시트 수치는 2026-11-24 14:29의 주간 마감 자료(`data/snapshot/`)에서 세었습니다(화면에 올린 세 회사의 수와 시트 전체의 수가 다른 곳은 나눠 적었습니다). 주간 마감 자료는 매주 일요일에 그 시점의 자료를 통째로 보관한 것입니다(`.github/workflows/weekly-close.yml`, 일요일 23:40). 자료를 고친 뒤에는 같은 작업을 사람이 실행해 보관하기도 하는데, 2026-11-24 자료가 그렇게 보관한 것입니다. 나머지 수치는 `docs/progress.md`, `docs/handoff.md`, `docs/planning.md`에서 가져왔습니다. 한계는 `docs/limitations.md`에 따로 모았습니다.

## 1. 소개

우체국보험 본부의 상품, 영업지원 담당자가 공개된 공시 문서와 시장 소식만으로 민영 보험사 상품과의 차이를 화면에서 바로 판단하도록 돕는 앱입니다.

- 담당자가 나이, 성별, 입원과 수술 이력 같은 조건을 고르면, 분석 화면이 어느 회사의 간편심사로 가입할 수 있는지(인수기준), 같은 담보를 회사마다 어떤 면책, 감액, 지급 조건으로 주는지와 우체국 미보유 담보, 그 차이에서 나온 영업 인사이트를 보여 줍니다. 창구 직원과 설계사에게는 A4 한 장짜리 응대 화법으로 전달합니다.
- 서버와 별도 DB 없이 구글 시트, GitHub Actions, 정적 HTML 한 파일로 돌아갑니다. 개념검증 단계로 1인이 만들었습니다.

## 2. 풀려는 문제

보험사마다 특약 이름, 감액 기간, 면책기간, 가입금액 대비 지급 배수, 고지 질문이 다릅니다. 수백 쪽 공시 문서를 손으로 대조해야 하고, 차이는 가격보다 문장 속 조건에 많습니다. 간편심사 고지 질문이 한 예입니다.

| 상품 | 기간 질문 | 중대질병 질문 |
| --- | --- | --- |
| 우체국간편한건강보험 2606 | 최근 1년, 2년, 5년 이내 입원만 | 6대 질병 |
| 한화생명 시그니처 H통합보험 | 입원 또는 수술(제왕절개 포함) | 7개 질병 |
| 삼성화재 간편보험 새로고침 | 입원 또는 수술 | 5개 질병 |

소비자가 보험료를 비교해 가입하는 서비스는 있습니다. 보험다모아는 금융위원회 보도자료(2016-11-30, 「보험다모아」 1년, 방문자수 100만명 돌파 및 저렴하고 가입도 간편한 온라인 보험 활성화 등 성과, https://www.fsc.go.kr/no010101/72454)에서 "다양한 보험상품의 보험료를 한곳에서 비교조회하고, 가입까지 바로 연결될 수 있는 온라인 보험 슈퍼마켓"으로 소개됐습니다. 실무자 한 명은 영업 기획이나 상품 설계 담당자의 관점에서 회사별 상품을 비교해 주는 도구는 없어서 이 도구가 쓸모 있다고 봤습니다(실무자 1명의 의견 요지, 2026-11-25). 한 사람의 의견이라 사실로 단정하지 않고, 사용검증에서 더 확인합니다.

## 4. 만든 것

### 자료 흐름

1. 수집: GitHub Actions가 각 사 공시실에서 상품요약서와 사업방법서를 받습니다(`scripts/fetch_disclosure.py`). 접속 모듈(`src/postlife/disclosure/`)은 우체국을 포함해 19개 회사에 있고, 그 가운데 14개 회사를 수집 스크립트에 이었습니다. DB손해보험, KB손해보험, 롯데손해보험, NH농협손해보험, 흥국화재는 아직 잇지 않았고, 한화손해보험은 자동 접속 차단 때문에 사람이 문서를 내려받습니다. 시장 소식은 요일마다 기관을 나눠 검색 모델로 모읍니다(`src/postlife/collect.py`).
2. 추출: 생성 모델은 원문 글자만 옮깁니다. 만 원 환산, 개월과 일수 계산, 날짜 대조는 코드가 합니다. 삼성화재 급부표는 모델 없이 코드 규칙으로 읽습니다.
3. 검증과 분기: 코드가 원문 대조를 먼저 하고, 확률 산정 전용 모델이 그 값을 검증합니다. 확률이 0.75 이상이면 확정, 0.40 이상 0.75 미만이면 사람 검토입니다. 0.40 미만은 다른 모델로 다시 뽑고, 그래도 안 되면 시트에 쓰지 않습니다.
4. 저장: 검증을 거친 행만 구글 시트 마스터 데이터(탭 13개)에 쓰고, 모든 단계를 `sys_작업로그`에 남깁니다.
5. 화면: 시트를 정렬된 JSON Lines 파일로 통째로 보관한 주간 마감 자료(`data/snapshot/`)로 분석 화면의 자료를 만들고(`scripts/export_app_data.py`), 한 파일(`site/proto/console4.html`)로 빌드합니다(`proto_src/console4/build.py`). 외부 요청이 없어 파일을 직접 열어도 동작합니다. 초기 버전 판단 화면은 `scripts/build_site.py`가 `site/v1/index.html`로 만듭니다.

## 5. AI 도구와 에이전트를 어떻게 썼는가

### 확률 산정 전용 모델을 검증기로

- `gemini-decision-1`은 2026-11-11에 나온 확률 산정 전용 모델입니다. 글을 쓰지 않고 정해진 선택지(2~255개)에 확률만 매기며, 출력 토큰이 0이고 한 번에 1,000문항까지 받습니다.
- 이 모델을 추출값 정합성 검증, 표준담보 매핑, 시장 소식 선별, 중복 소식 병합에 넣었습니다.
- 문항 짜는 법은 실제 결과를 보고 고쳤습니다. 면책 조건을 진술의 참 거짓으로 물으면 맞는 행도 0.5~0.8에 머물렀습니다. "조건 있음 / 없음" 가운데 고르게 하자 맞는 값은 0.94 이상, 뒤집은 값은 0.06 이하로 갈렸습니다.

### 제미나이: 추출기와 따로 보는 교차 확인

- Claude Code로 옮기기 전 단계에서는 제미나이 웹에 사람이 요청문과 첨부를 넣어 답을 받았습니다. 정답셋(우체국 85항목, 한화생명 25항목, 삼성화재 50항목), 우체국 리뉴얼 전 상품(간편건강보험 2504, 판매 종료) 급부 90줄 교차 확인, 삼성화재 급부 독립 구조화, 한화 추출 결과 표본 대조, 매핑 대기 388종류 분류 의견, 추출과 검증 코드 검토 26건이 여기에 속합니다.
- Claude Code로 넘어온 뒤에는 구독 패널(`gemini-sub` 스킬)로 넘겼습니다. 한화생명 가입조건 정답셋 24항목, 화면 해설 글 틀과 화면 1 구성 지적, 응대 카드 구성안, 수집 스크립트와 배포 워크플로 검토, 이 문서의 초안이 여기에 속합니다. 그 뒤로 비교 대상 회사의 웹 조사, 기획서 개정 초안, 표준담보 사전 확장안 검토, 화면 코드 검토, 글자가 그림으로 든 문서의 문자 추출도 패널에 넘겼습니다.
- 삼성화재 가입조건과 결합 제약의 독립 구조화도 패널에서 했습니다(질문 12개). 가입조건은 THE FIT 8종 특약 279개와 새로고침 7종 특약 244개의 답을 원문 줄과 기계로 맞췄고 모두 일치했습니다. 패널에서도 질문마다 사람이 직접 입력해야 답이 옵니다.
- 제미나이 모델도 일의 성격에 따라 골랐습니다. 기계로 전부 대조할 수 있는 표 구조화는 가벼운 모델(하이드로젠)로 낮춰도 대조 결과가 같았고, 판단이 들어가는 결합 제약 분류는 한 단계 위 모델(네온)에, 검토와 초안은 가장 위 모델(카본)에 맡겼습니다.
- 요청문 틀은 `docs/gemini_requests/`, 받은 결과는 `data/crosscheck/`와 `data/goldset/`에 있습니다.
- 검수 기준: 제미나이의 지적과 결과는 Claude가 직접 확인해 동의한 것만 반영합니다. 근거 문구와 숫자는 원문의 그 쪽에 있는지 기계로 대조하고, 코드 지적은 재현되는 것만 고칩니다. 확인하지 못한 것은 미확인으로 남깁니다.

### Claude Code와 서브에이전트

- 메인 세션은 작업 순서와 범위를 정하고, 위임 결과를 테스트, 재현, 원문 대조로 검수해 커밋합니다. 아끼려는 것은 메인 세션이 쓰는 최상위 모델의 사용량입니다.
- Claude Code로 넘어온 뒤 처음 실행한 구현 에이전트 하나는 모델을 지정하지 않았습니다. 그래서 메인 세션과 같은 최상위 모델, 곧 가장 비싼 모델로 실행됐습니다.
- 이 일을 보고 기준을 세워 `CLAUDE.md`에 적었습니다. 서브에이전트는 모델을 항상 명시하고, 구현과 수정은 opus, 점검은 sonnet, 기계 점검은 haiku에 맡기며, 값이 정해진 기계적 수정은 에이전트 없이 직접 합니다.
- 기준을 세운 직후에는 구현과 수정과 문서 다듬기를 opus 에이전트 셋에, 질문 자료 준비를 sonnet 에이전트 하나에 맡겼고, haiku는 쓰지 않았습니다. 질문을 차례로 넣고 답을 기계로 대조하는 반복 작업은 에이전트 없이 스크립트로 실행했습니다.
- 비교 대상을 넓힐 때는 DB손해보험 하나로 공시 접속 모듈을 먼저 만들어 검수한 뒤, 나머지 16개 회사를 워크플로로 한꺼번에 실행했습니다. 회사마다 opus 에이전트가 공시실 요청을 조사해 접속 모듈과 테스트를 만들고 대표 상품 두 개의 요약서와 사업방법서를 받았고, sonnet 에이전트가 그 모듈로 실제 호출을 해 받아 둔 파일과 해시를 대조했습니다. 메인 세션은 전체 테스트(579개 통과), 바뀐 파일이 회사별 모듈과 시험뿐인지, 받은 문서 58개가 모두 PDF이고 쪽수가 보고와 같은지를 직접 확인했습니다.
- 16개 회사 가운데 15곳은 로그인이나 토큰 없이 문서를 받았습니다. 한화손해보험은 상품 목록 요청이 자동 접속 차단에 걸렸는데, 차단을 우회하지 않기로 해 접속 모듈을 만들지 않았고 이 회사 문서는 사람이 공시실에서 내려받습니다.
- 에이전트의 완료 보고는 그대로 옮기지 않습니다. 예를 들어 화면 1, 해설 글, 응대 카드는 opus 에이전트가 구현했고, 메인 세션이 테스트, 빌드, 브라우저 점검을 다시 실행하고 화면 스크린샷과 카드 PDF를 직접 열어 검수했습니다.
- Claude Code로 옮기기 전 대화 세션에서도 공시실 조사, 화면 구현, PDF 표 추출 모듈과 문구 규칙 작성, 한화 검토 줄 원문 대조, 코드 검토 지적의 재현과 수정을 서브에이전트에 맡겼습니다. 결과는 테스트와 원문 대조로 검수했습니다.

### 글자가 그림으로 든 문서: 두 모델이 따로 읽고 교차 검증하기

- 미래에셋생명 요약서는 본문 글자가 쪽마다 수백 개의 작은 그림으로 들어 있어 글자를 풀 수 없습니다. 쪽 그림을 제미나이 구독 패널과 sonnet 에이전트가 따로 읽게 하고, 코드로 대조해 어긋난 행만 원본에서 확대해 Claude가 직접 보고 확인해 두 요약서 308쪽(공백을 뺀 314,492자)을 확정했습니다. 지급률과 금액은 두 추출 결과가 한 군데도 어긋나지 않았습니다(`docs/progress.md` "기획서 개정, 한화손해보험 조사, 그림으로 된 문서의 글자 옮기기 시험").
- 같은 추출을 되풀이해서는 오류가 잡히지 않았습니다. 제미나이가 같은 쪽을 그림과 PDF로 두 번 읽은 결과는 틀린 곳까지 글자 그대로 같았고, sonnet 에이전트를 새로 실행해 다시 읽혀도 20쪽 가운데 9쪽에서 첫 추출과 같은 식으로 틀렸습니다. 그래서 남은 문서는 sonnet과 opus가 한 번씩 읽습니다. sonnet이 틀렸던 20쪽을 opus가 다시 읽은 결과는 25,048자가 확정본과 한 글자도 다르지 않았고(공백과 따옴표 종류 제외), Claude가 처음 확인할 때 잘못 고친 한 곳도 이때 찾아 원문대로 되돌렸습니다.
- 로컬 OCR(tesseract)은 글자를 풀 수 있는 대조용 쪽에서 1,123자 가운데 100자를 빠뜨리고 110자를 잘못 넣어, 값에는 쓰지 않고 급부 표가 있는 쪽을 찾는 데만 씁니다.

### 사람이 정하는 것

- 담당자 탭 4개(표준담보 사전, 담보 매핑, 기준값, 표준질병군)의 값과 스키마 변경은 사람이 정합니다. 자동 확정 기준을 바꾸거나 사전에 행을 추가하는 일도 사용자 지시가 있어야 합니다.
- 검증 경계값은 모두 기준값 탭에 두어, 코드를 고치지 않고 담당자가 조정할 수 있습니다.

## 6. 안전장치가 실제로 걸러 낸 사례

**틀린 추출값을 확정하지 않고 사람 검토로 넘겼습니다.**
- 우체국 통합건강보험 2504 첫 실행에서 재추출 모델이 재해장해생활자금의 장해지급률 구간 하나를 빠뜨리고 금액을 한 칸씩 밀려 적었습니다. 확률 산정 결과가 0.07과 0.71이라 확정되지 않고 사람 검토로 갔습니다. 틀린 값이 확정된 줄은 없습니다.
- 표적항암약물허가치료특약은 가벼운 모델 둘 다 1,000만 원을 지급액과 감액 양쪽에 적었습니다. 코드 대조가 이를 잡아 상위 모델로 넘겼고, 2,000만 원(1년 미만 1,000만 원)으로 바로잡혔습니다.
- 결합 제약을 묶어서 물으면 잘못 끼어든 특약 2개가 0.80으로 통과했습니다. 특약마다 따로 묻자 0.42와 0.47로 걸렸습니다.

**문서에 없는 값을 임의로 만들지 않았습니다.**
- 우체국 정답셋에서 문서에 없는 급부 2개를 묻는 항목에 추출기는 행을 만들지 않았습니다. 문서에 없는 배타 제약을 묻는 항목도 같았습니다.
- 특약 가입 한도가 공시 문서에 없는 한화생명 종형은 화면이 최대 가입 기준 지급액과 우열 비교 결과를 만들지 않습니다.
- 첫 실제 수집에서 정형화된 소식 27건 가운데 수집 구간 밖 23건을 코드의 날짜 확인이 버렸습니다.

**교차 확인이 추출의 축약과 원문 자체의 오류를 찾았습니다.**
- 제미나이가 우체국 리뉴얼 전 상품(간편한건강보험 2606으로 리뉴얼되기 전의 간편건강보험 2504, 판매 종료)의 급부 90줄을 원문만 보고 다시 확인해 16줄을 짚었습니다. 지급 한도 문구가 줄어든 9줄, 장해지급률 배수가 빠진 2줄, 주석 예외 4줄이 맞는 지적이었고 1줄은 문제가 없었습니다. 지시문과 대조 규칙을 고쳐 다시 뽑자, 우체국 급부 383행의 매핑 대기가 44행에서 22행으로 줄었습니다.
- 삼성화재는 규칙 추출과 제미나이의 독립 구조화를 행마다 맞췄습니다. THE FIT은 339행 중 337행, 새로고침은 342행 중 334행이 일치했습니다. 다른 행은 규칙 추출이 확신 없음으로 표시한 행이거나 괄호 표기 차이였습니다.
- 제미나이가 "확인 필요"로 적은 곳은 요약서 원문의 오류였습니다. 새로고침 105쪽은 본문과 주석의 한도가 엇갈리고, 140쪽은 주석의 담보명이 잘못 적혀 있습니다.

**코드 검토와 결과 파일 보존이 자료 유실을 막았습니다.**
- 제미나이의 추출, 검증 코드 검토 26건을 서브에이전트가 지적마다 재현, 수정, 시험했고, 재현되지 않은 지적은 없었습니다.
- 그 가운데 24번은 급부만 다시 뽑으면 `sys_특약`의 가입 한도 항목이 비워지는 버그였습니다. 가짜 시트에서 실행하면 우체국 특약 한도 166행이 0행이 됐습니다. 예정했던 우체국 급부 재추출을 그대로 실행했다면 모두 사라졌을 것입니다. 고친 뒤 2026-11-19 저녁 실제 우체국 급부 재추출에서 166줄이 그대로인 것을 확인했습니다.

지금의 범위는 생명보험과 손해보험의 대형사, 그리고 건강보험(종합형, 간편형)입니다. 아래는 범위 밖에 둔 것이고, 실무자 사용검증의 의견을 받아 넣을지와 순서를 정합니다.

- 회사를 채우는 순서: 스무 곳을 같은 비중으로 채우지 않고 실무자가 실제로 비교하는 회사부터 넣습니다. 교보생명(생명보험 대형 3사를 채움), 현대해상과 DB손해보험과 KB손해보험(손해보험 대형사), NH농협생명과 NH농협손해보험(창구 기반이라 고객층이 겹침)의 순서이고, 나머지는 사용검증 의견을 보고 정합니다(2026-11-24 결정).
- 가입 조건을 맞춘 비교: 실무자 한 명이 비교 기준이 회사마다 달라(특약마다 필수 가입금액이 다르고, 회사마다 필수로 가입해야 하는 특약과 함께 가입해야 하는 특약이 다름) 같은 보장의 비교가 어렵다고 답했습니다. 지금 특약 가입조건(544행)과 결합 제약(79건)은 우체국만 적재했고 타사는 주계약 가입조건만 있습니다. 타사의 특약 가입조건과 결합 제약을 적재해 가입 조건을 맞춘 비교로 넓힙니다. 회사 확대와 이 일 가운데 무엇을 먼저 할지는 제출 뒤에 정합니다.
- 공제(새마을금고, 신협, 수협): 판매 방식과 고객층이 우체국보험과 겹칠 것으로 보는 곳인데 지금 대상에 없습니다. 공시 문서를 같은 방식으로 받을 수 있는지부터 확인해야 하고, 아직 확인하지 않았습니다.
- 다른 상품 종류: 암보험 단독 상품, 치매와 간병 보험, 어린이보험은 다루지 않습니다. 넣으려면 표준담보 사전(지금은 암, 뇌, 심장, 입원과 수술)을 먼저 넓혀야 합니다.
- 사용검증: 영업 기획과 분석 담당 실무자에게 과제 여섯과 의견 양식으로 받습니다(`docs/validation/`). 양식에서 "견주고 싶은데 빠져 있는 회사나 상품"을 물어 위 후보의 우선순위를 정합니다.

### 향후 계획: 개정 반영과 질병코드 범위

실무자 한 명이 이런 걱정을 전했습니다(요지, 2026-11-25). 보험 상품은 회사마다 다양하고 복잡하며, 약관과 한국표준질병사인분류(KCD)는 고정돼 있지 않고 바뀌는데 그것이 반영되는가 하는 것입니다. 지금 되는 것과 안 되는 것을 코드와 자료로 확인해 나눠 적습니다(기준은 2026-11-24 주간 마감 자료).

**개정 자동 감지와 재추출**
- 지금 되는 것: 종형마다 상품요약서와 사업방법서의 파일 해시를 `sys_상품종형`에 보관합니다(화면에 올린 세 회사의 종형 23개 모두). 약관 별표 해시는 우체국 종형 8개에만 있습니다. 개정 전후 비교는 개정 전과 후의 상품을 둘 다 시트에 적재했을 때 두 상품을 잇는 계보키(종형계보키, 특약계보키)로 코드가 짝을 지어 만듭니다(`src/postlife/site/revision.py`). 지금 있는 짝은 우체국간편건강보험 2504와 우체국간편한건강보험 2606의 종형 세 쌍입니다. 주간 마감 자료의 커밋 이력은 개정 이력으로 남습니다.
- 아직 안 되는 것: 공시 문서 수집(`.github/workflows/fetch-disclosure.yml`)과 추출(`.github/workflows/extract.yml`)은 예약 실행이 아니라 사람이 실행합니다. 새로 받은 문서의 해시를 보관한 해시와 비교해 바뀐 상품을 찾고 그 상품만 다시 추출하는 단계는 아직 없습니다. 그래서 회사가 상품을 개정해도 사람이 수집과 추출을 실행하기 전에는 시트와 화면에 반영되지 않습니다.
- 계획: 기획서가 정한 대로 파일 해시가 바뀐 상품만 다시 추출합니다(`docs/planning.md` 4.1). 주간 배치에서 공시 문서를 받아 해시를 비교하고, 바뀐 상품만 추출과 검증을 거쳐 시트에 적재해 개정 전후 비교에 넣습니다. 약관 별표 해시는 타사 종형에도 채웁니다.

**약관 별표의 질병코드 범위 비교**
- 지금 있는 자료: 표준질병군 초안 22개(KCD-8과 KCD-9를 합쳐 58행)가 담당자 탭(`hum_표준질병군`)에 있고, 회사와 무관한 기준표입니다. 담보별 질병코드 탭(`sys_급부질병코드`)은 0행입니다. 추출기는 상품요약서와 사업방법서만 읽고 약관 별표는 읽지 않습니다(`docs/limitations.md` 1절).
- 한계: 같은 이름의 담보라도 회사마다 보장하는 질병코드 범위가 다를 수 있고, KCD 개정으로 그 범위가 달라질 수 있습니다. 지금 화면은 담보 이름을 표준담보로 맞춰 비교하므로 이 차이를 보여 주지 못합니다.
- 계획: 약관에서 별표 구간만 읽어 담보마다 질병코드 범위(시작코드, 끝코드, 포함 여부)를 KCD 버전과 함께 적재하고, 회사끼리 코드 단위로 비교합니다. 표준질병군 초안을 비교 대상 약관의 별표와 대조하는 일도 함께 합니다. 적재할 탭의 열(KCD버전, 시작코드, 끝코드, 포함여부, 별표명)은 스키마에 이미 있습니다.

## 9. 시연 순서 제안

분석 화면의 탭 여섯을 담당자의 일 순서대로 네 단계(넓게 보기, 좁혀 확인, 결론, 내보내기)로 보입니다. 발표 덱 6장의 구분과 같고, 사용검증 과제의 조작 순서(`docs/validation/사용검증_안내와_과제.md`)와도 맞춥니다.

1. 넓게 보기(전체 요약, 고객군과 시장): 첫 화면의 영업 분석 요약에서 기본 조건(50세 남성, 입원과 수술 이력 없음, 기준 2종(간편가입325))의 핵심 수를 읽습니다. 이어서 "조건 변경"으로 최종 입원 시점을 3개월~1년 전으로 옮기면, 우체국 간편심사는 가입 제한이라 일반심사 대상이고 타사 가운데 한화생명만 우체국에 없는 간편심사 유형(3·0·5, 간편가입형(0년))으로 가입 가능하다는 것이 보입니다. 1~2년 전으로 옮기면 세 회사 모두 가입 가능으로 바뀝니다.
2. 좁혀 확인(인수기준 비교, 담보 비교, 관계 그래프): 인수기준 비교에서 간편심사 유형마다 통과하는 회사 수와 고지 범위가 다른 타사를 봅니다. 담보 비교에서 암 수술비 행을 열어 면책기간, 감액기간, 기준 가입금액과 함께 적은 지급액을 확인합니다(우체국 1종은 기준 가입금액 1,000만원에 300만원, 면책 90일, 1년 안 50% 감액). 관계 그래프에서 암보장을 펼쳐 일반암 진단비가 우체국의 어느 특약에 들어 있는지 따라갑니다.
3. 결론(영업 인사이트): 분류 다섯 가운데 한 건을 골라 근거 문서와 쪽수를 확인하고 "응대 화법에 추가"를 클릭합니다.
4. 내보내기(응대 화법 A4 패널): 같은 탭의 응대 화법 A4 패널을 인쇄하거나 복사해, 본부 담당자의 판단이 창구 직원과 설계사에게 한 장으로 전달되는 모습으로 마칩니다. 맨 위의 대외 배포 금지 문구도 함께 보입니다.
