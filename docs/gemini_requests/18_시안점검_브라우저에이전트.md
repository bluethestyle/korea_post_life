# 요청 18. 시안을 브라우저로 직접 눌러 보는 점검 (Antigravity 브라우저 에이전트용)

Antigravity의 브라우저 에이전트(`/browser`)에 사람이 붙여 넣어 돌리는 점검 지시문입니다. 구독 패널의 제미나이는 Claude가 찍어 넘긴 정지 사진만 보기 때문에, 움직임 도중의 장면을 결함으로 잘못 본 일이 있었습니다(2026-11-20). 실제로 눌러 가며 보는 점검은 이 지시문으로 Antigravity 쪽에 맡깁니다. 화면은 모두 공개 주소라 저장소를 받지 않아도 되고, Antigravity에서는 빈 폴더로 프로젝트를 만들면 됩니다. 점검이 끝나면 보고 글을 Claude Code 대화에 붙여 넣어 주세요. Claude가 지적을 직접 확인해 동의한 것만 고칩니다.

요청 17은 운영 화면(`/`)을 보는 지시문이고, 이 요청은 시안(`/proto/`)을 봅니다.

아래 줄부터 끝까지를 그대로 붙여 넣습니다.

---

/browser 아래 네 주소를 차례로 열어 시나리오대로 실제로 눌러 보고, 본 것을 보고해 주세요.

- 시안 3: `https://bluethestyle.github.io/korea_post_life/proto/console3.html`
- 그래프 탐색: `https://bluethestyle.github.io/korea_post_life/proto/graph2.html`
- 화면 흐름도: `https://bluethestyle.github.io/korea_post_life/proto/flow.html`
- 글꼴 견본: `https://bluethestyle.github.io/korea_post_life/proto/fonts2.html`

이 화면을 쓰는 사람은 보험사 본부의 영업 기획과 분석 담당자입니다. 우체국보험 상품을 한화생명, 삼성화재 상품과 견주어 어디가 비고 어디가 다른지를 보고 영업 자료를 만듭니다. 시안이라 자료의 옳고 그름은 판단하지 않습니다. 볼 것은 네 가지입니다: 무엇을 눌러야 할지 바로 알 수 있는가(직관성), 글자가 편하게 읽히는가(가독성), 움직임이 부드럽고 반응이 빠른가, 미래 배경 콘솔 게임의 계기판 같은 인상이 나는가. 다른 사이트로 이동하거나 로그인하지 않고, 파일을 만들거나 고치지 않습니다.

## 점검 조건

- 창 크기 1280x800에서 한 번, 380x780(휴대폰 너비)에서 한 번 더 합니다.
- 단계마다 화면 사진을 남깁니다. 움직임이 끝난 뒤의 장면을 찍고, 움직임 도중의 장면은 따로 표시합니다.
- 눌렀는데 반응이 없거나 늦은 곳, 글자가 잘리거나 겹치는 곳, 무엇을 눌러야 할지 알기 어려운 곳을 적습니다.
- 브라우저 콘솔에 오류가 나오면 그 글을 그대로 적습니다.

## 화면 1: 시안 3

1. 처음 열릴 때 화면이 조립되는 움직임이 보이는지, 얼마나 걸리는지 적습니다. 다 열린 첫 화면에서 3초 안에 눈에 들어오는 것 세 가지를 적습니다.
2. 조건 줄에서 나이를 − 와 + 단추로 바꾸고, 눈금 손잡이를 끌어 65로 맞춥니다. 성별과 병력 고지(1년, 2년, 5년)도 바꿉니다. 숫자와 목록이 바뀌는지, 바뀐 곳이 표시되는지 봅니다.
3. "우리에게 없는 담보"의 첫 항목을 누릅니다. 오른쪽 패널이 밀려 들어오는지, 관계 그림이 처음부터 보이는지, 그림 속 글자가 겹치지 않는지 봅니다. "범례 보기"를 눌러 범례가 그림을 가리지 않는지 봅니다. "그림"과 "목록"을 바꿔 봅니다. 닫기 단추로 닫고, 다시 열어 Esc로 닫습니다.
4. "조건이 다른 담보"의 항목 하나를 눌러 패널의 견줌 줄을 읽습니다.
5. "담보 비교" 탭을 열어 표를 훑고 칸 하나를 누릅니다.
6. 위 띠의 "짙은 화면"을 눌러 스킨을 바꾸고 글자가 읽히는지 봅니다. "움직임" 단추를 눌러 끔과 켬의 차이를 봅니다.
7. 380 너비에서 조건을 펼쳐 바꾸고, 아래 탭 막대로 탭을 옮기고, 항목을 눌러 아래에서 올라오는 판을 엽니다.
- 물음: 분석 담당자가 "우체국 상품이 두 회사와 견주어 어디가 비고 어디가 다른지"를 1분 안에 말할 수 있었습니까? 어디서 막혔습니까?

## 화면 2: 그래프 탐색

1. 시작 카드에서 "우체국보험"을 고릅니다. 시작 카드가 다른 영역을 덮는지 봅니다.
2. 가운데 노드를 누릅니다. 노드 둘레의 호와 숫자, 화면 아래 띠의 관계 단추가 나오는지 봅니다. 단추를 눌러 이웃을 펼치고, 새로 나온 노드를 골라 두 번 더 넘어갑니다.
3. 선 하나를 눌러 관계의 속성(관계 이름, 확정 여부, 확률)이 보이는지 봅니다.
4. "여러 홉", "되돌리기", "처음", 확대와 축소와 맞춤, 작은 전체 지도를 써 봅니다.
5. "거르기"와 이름 찾기를 써 봅니다. 밝은 스킨으로 바꿔 봅니다.
6. 380 너비에서 1~3을 다시 합니다.
- 물음: 아래 띠의 단추가 어느 노드의 것인지 헷갈리지 않았습니까? 단추, 패널, 거르기 상자가 그래프를 가리는 곳이 있습니까? 노드가 많아졌을 때 이름이 읽힙니까?

## 화면 3: 화면 흐름도

1. 오른쪽에서 "문의 응대"와 "주간 점검"을 번갈아 고르고, 걸음을 하나씩 눌러 봅니다.
2. 아래의 변경 표에서 "바뀌는 것"과 "그대로인 것"을 걸러 봅니다.
3. 380 너비에서 같은 조작을 합니다.
- 물음: 화면이 어떤 순서로 이어지는지 10초 안에 읽혔습니까? 두 길이 구별됩니까?

## 화면 4: 글꼴 견본

1. 짝 일곱의 카드를 훑고, 아래의 "한글 비교"와 "숫자 비교"를 봅니다. 밝은 화면과 짙은 남색을 바꿔 봅니다.
- 물음: 짝마다 한글 제목과 숫자가 어울리는지, 숫자 열이 가지런한지를 한 줄씩 적어 주세요.

## 보고 형식 (마크다운)

1. 요약: 직관성, 가독성, 움직임, 게임 인상을 각각 1~5점으로 매기고 이유를 두 줄씩.
2. 화면별 결과: 단계마다 "됨, 안 됨, 헷갈림"과 본 것 한 줄, 물음에 대한 답.
3. 문제 목록: 심한 것부터 스무 개 이내. 문제마다 어느 화면의 어느 자리인지, 무엇이 일어났는지, 창 너비, 사진 이름.
4. 움직임과 반응 속도: 처음 열릴 때, 패널이 열릴 때, 조건을 바꿀 때, 그래프에서 이웃을 펼칠 때의 느낌(바로, 조금 늦음, 늦음, 끊김)과 가장 거슬린 곳.
5. 분석 담당자가 처음 열었을 때 가장 먼저 헷갈릴 것 다섯 가지.

직접 눌러 본 것만 "됨, 안 됨"으로 적고, 추측은 추측이라고 적습니다.
