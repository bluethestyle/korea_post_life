# 요청 31. 담보 비교가 판정과 쌍 수를 자료에서 읽게 바꾸기 (Antigravity 개발 에이전트용)

Antigravity에 이 한 줄을 넣습니다.

## 무엇이 올라왔나

뜻과 읽는 법은 `proto_src/console4/API.md`의 두 절에 있습니다. 먼저 그 두 절을 읽습니다.

| 절 | 자료의 새 값 | 지금 화면이 하던 일 |
| --- | --- | --- |
| "담보 비교의 쌍판정" | `CV.b[기준종형ID].쌍판정`(담보와 상대 쌍마다의 까닭과 사유), `CV.판정표`(까닭마다의 판정 이름과 칩 종류), `CV.판정차례`, `CV.b[기준종형ID].판정요약`(회사마다 판정 이름별 쌍 수) | `verdictOf`가 판정을 스스로 만들었습니다 |
| "담보 비교의 범위별 쌍 수" | `S.기준별[ID].보류요약.기관별`과 `보류요약.대분류[].기관별`(상대 회사마다의 공통 담보 쌍, 뺀 쌍, 견준 쌍, 사유별) | `scopedPairs`가 쌍 기록을 세었습니다 |

- 기둥이 쓰는 `판정기관코드`와 `판정상대수`는 이제 쌍판정을 모은 값입니다. 우리에게는 있고 상대는 관계 담보로 덮는 쌍에 새 까닭 "관계 담보로 덮음"(판정 이름은 우열을 매기지 않음)이 더해졌습니다(담보 줄 27개). 그 밖의 기존 값은 바뀌지 않았습니다.
- 왜 바꾸나: 어제 점검에서 기준 종형 다섯의 담보와 상대 쌍 778개 가운데 52개에서 기둥과 칩이 어긋났습니다. 44개는 칩이 맞았고(관계 담보로 덮는 쌍) 8개는 기둥이 맞았습니다(항암약물치료비. 칩이 "검토 대기"였는데 자료의 규칙으로는 "우체국에 없음"). 판정을 한 군데(자료)에서만 정하면 둘이 어긋날 수 없습니다.

## 고칠 것

1. 판정을 만들지 않고 읽습니다. `tab4.src.js`의 `verdictOf`를 없애거나 쌍판정을 그대로 돌려주는 얇은 함수로 바꾸고, 그것을 쓰던 곳을 모두 쌍판정으로 바꿉니다: `model`(줄마다의 `row.verd`), `verdFor`, `chip`, `chipText`, `defaultStepFor`, `condTable`(판정 묶음과 "상대 미보유" 수), `rowEvidence`(판정 배지와 뺀 것 목록), `journeyPick`, `relSVG`, `tableRows`, `tableHTML`(요약 수는 `판정요약`에서), `tableBand`, `copyTable`, 범례. `core.js`의 `coverStageStacks`, `tab5.js`의 `pickPoint`도 같습니다.
2. 기둥(`rowStackMetrics`와 전체 띠의 눈금): 높이를 `보유기관코드`의 수가 아니라 `판정상대수`의 합(범위를 좁혔으면 `판정기관코드`의 목록마다 고른 범위와 겹치는 수를 더한 값)으로 잡습니다. 그래야 층을 쌓은 높이와 기둥의 높이가 같습니다. 중립 층에는 "지급 형태 다름"과 "관계 담보로 덮음"이 들어갑니다. "우체국만 가진 담보"(금색 마름모)는 우리에게 확정 급부가 있고 이 합이 0인 담보입니다. 이름표와 범례의 말도 이 뜻에 맞춥니다(기둥의 높이는 "같은 담보를 가졌거나 관계 담보로 덮는 상대의 비율").
3. 범위별 쌍 수: `scopedPairs`, `pendingHTML`(대분류 줄을 다시 세던 부분 포함), `midBand`, `concl`, `core.js`의 `renderScope`, `ringTabMetrics`가 고른 회사의 `기관별` 값을 더해 씁니다. 범위를 좁히지 않았으면 지금처럼 전체 값을 씁니다.
4. 금액 하나로 적을 수 없는 급부를 적는 자리는 API.md의 "금액 없는 급부" 절이 함수 이름으로 가리킵니다. 이 가지에서 이미 고친 자리가 그 절과 맞는지만 확인합니다.

## 고칠 수 있는 파일과 고치면 안 되는 파일

- 고칠 수 있는 파일: `proto_src/console4/tab4.src.js`, `tab4.css`, `core.js`, `tab5.js`, 필요하면 `tab1.js`(첫 화면의 담보 비교 묶음이 판정을 쓰는 곳), `docs/antigravity_log.md`.
- 고치면 안 되는 파일: 자료(`proto_src/console4/*.json`), `API.md`, `src/`, `scripts/`, `tests/`, `data/`. 자료가 틀려 보이면 고치지 말고 PR 글에 적습니다.
- `tab4.js`와 `site/proto/console4.html`은 `python proto_src/console4/gen_cover.py --assemble`과 `python proto_src/console4/build.py`로 다시 만듭니다.

## 끝내는 기준

1. 화면 원본에 판정을 만들거나 쌍을 세는 코드가 없습니다(`verdictOf`가 쌍판정을 읽기만 하고, `scopedPairs`가 `기관별` 값을 더하기만 합니다).
2. 기준 종형 다섯의 모든 담보와 상대 쌍에서 칩의 판정 이름이 `CV.판정표[쌍판정의 까닭].판정`과 같고, 기둥의 층별 수가 `판정상대수`와 같습니다(어긋나는 쌍 0). 재는 스크립트의 출력을 PR 글에 적습니다.
3. "표로 보기"의 요약 수가 `판정요약`에서 고른 회사의 값을 더한 수와 같습니다.
4. 비교 범위 넷(전체, 생명보험만, 손해보험만, 직접 고름)에서 고리 탭과 첫 화면과 결론 줄의 담보 비교 수가 `기관별`을 더한 값과 같습니다.
5. 네 회사 자료(`python scripts/export_app_data.py --orgs all --out out/console4_all`)와 가상 스무 회사 자료에서도 2~4가 같습니다.
6. 요청 28의 기준은 그대로입니다(프레임, 레이아웃 속성 전환 0, 콘솔 오류 0, 외부 요청 0, 원본에서 다시 합친 화면이 커밋된 것과 같음, `python -m pytest -q` 통과).
