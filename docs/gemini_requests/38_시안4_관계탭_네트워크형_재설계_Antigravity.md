# 요청 38. 시안 4: 관계 그래프 탭을 네트워크형으로 재설계 (Antigravity 개발 에이전트용)

관계 그래프 탭(지금 화면 코드 `proto_src/console4/tab6.js`, `tab6.css`)을 일곱 열 레이어 구조에서 네트워크형 구조로 재설계하는 요청입니다. 사용자(보험 실무자)의 말(2026-11-24)을 그대로 옮깁니다.

- "관계지도도 보면 그래프 표현을 순서도처럼 해놔서 엣지끼리 겹치고 직관적으로 뭔가 보이지도 않는 것 같아. 그래프 표현방식을 좀 더 네트워크처럼 볼 수 있는 방향으로 수정해야되지 않을까?"
- "그래프 쪽에서 노드랑 엣지 스키마가 담보대응, 종형구성, 시장소식에 맞게 디자인 된건지 다시 검토해봐"

Claude가 스키마와 화면을 검토하고 레이아웃 세 안을 실제 자료로 계산해 비교했습니다(`docs/proposals/관계그래프_재설계_검토.md`). 사용자는 그 권고를 승인했습니다("권고대로 가자"). 승인한 내용은 셋입니다.

1. 기본 화면은 보유 조합 그룹 네트워크로 합니다. 종형은 앵커, 표준담보는 보유 회사 조합이 같은 것끼리 그룹 원 안에 두고, 보유 엣지는 번들 엣지로 그립니다.
2. 우체국이 보유하지 않았지만 넓은 담보나 부분 담보로 보장하는 담보는 판정(우체국 미보유)을 바꾸지 않고 구분 표시만 합니다.
3. 시장 동향 보기는 회사별 동향만 보입니다. 종형이나 표준담보와 연결해 그리지 않습니다.

선행 요청: 이 요청서는 요청 35(`docs/gemini_requests/35_시안4_배포화면_사용자의견_반영_Antigravity.md`)와 요청 37(`docs/gemini_requests/37_시안4_화면문구를_실무용어로_Antigravity.md`)의 PR이 머지된 `main`에서 시작합니다. 표시 이름 함수 `App.label`과 `App.addLabels`, 확정 이름 상수 `App.TERM`(`core.js` 안에서는 `TERM`), 문구 표 `COPY`의 `gr` 접두어 키는 요청 37의 5절과 4절에서 정한 이름 그대로 씁니다.

아래 레이아웃 수치는 Claude가 파이썬으로 계산해 겹침과 교차를 확인한 값입니다(계산은 2026-11-23 스냅샷으로 했습니다). 브라우저에서 재 보지 않았으므로 실제 화면에서 조정해야 할 값과 계산으로 검증하지 않은 값은 "시작값"이라고 적었습니다. 건수는 모두 빌드 시점의 데이터에서 읽는 값이고, 이 문서의 예시 건수는 2026-11-24T14:29:59+09:00 스냅샷의 값입니다. 이 스냅샷에서 그룹 구성(3.4절), 표지(5.3절), 판정 필터(5.4절)의 기대값을 다시 계산해 2026-11-23 계산과 같음을 확인했고, 시장 동향 건수(7절)는 이 스냅샷의 값으로 고쳤습니다. 시작값을 바꾸면 바꾼 값과 이유를 PR 글에 적어 주세요. 설계 문서와 이 요청서가 다르면 이 요청서를 따릅니다(다르게 정한 것은 12절 끝에 모았습니다). 계산에 쓴 스크립트와 좌표 파일은 저장소 밖에 있어 볼 수 없습니다. 필요한 규칙과 수치는 모두 이 문서에 옮겼습니다.

## 1. 지금 화면의 문제

1. 시장 동향, 회사, 종형, 특약, 급부, 표준담보, 보장 대분류의 일곱 열을 1.5px 직각 꺾은선으로 잇습니다. 같은 노드와 엣지(타사 2개사, 기준 종형 우체국 간편한건강보험 1종)를 이 구조로 그리면 교차가 보장 대분류를 하나씩 펼친 다섯 화면의 합으로 약 2,472, 한 화면에 모두 세우면 약 12,397입니다(근사 계산). 같은 선 위에 겹쳐 그려지는 세로 선분이 굵은 세로 다발로 보이고, 담보를 모두 펼치면 높이가 약 2,550px라 스크롤해야 합니다. 사용자가 짚은 "순서도처럼 보인다"는 인상이 여기서 나옵니다.
2. 화면이 보유 여부만으로 "우체국 단독 보유"와 "우체국 미보유"를 붙여(`stdOwnershipClass`) 담보 비교 탭의 판정과 다릅니다. 기준 종형 다섯의 합으로 "우체국 단독 보유"로 그리는 25행(서로 다른 담보 7개) 가운데 17행(담보 5개)은 담보 비교에서 두 타사 모두 `관계 담보로 덮음`(관련 담보로 보장)입니다. "우체국 미보유"로 그리는 269행 가운데 64행(담보 14개)은 우체국이 넓은 담보나 부분 담보로 보장하는데 아무 표시가 없습니다. 여기서 "행"은 (기준 종형, 표준담보) 한 건입니다.
3. 종형과 표준담보 사이 엣지가 자료에 없어, 화면이 시작할 때 23개 종형의 경로 색인을 만들어 보유를 세고, 매핑 엣지 번호를 빌려 보유 연결을 그립니다. 그래서 상세 패널에 보유 연결의 선 모양이 "실선 (자동확정 매핑)"으로 나옵니다. 표준담보 카드의 "연결 급부 N"은 매핑 엣지가 있는 종형 19개 전부를 세어, 화면에 놓인 종형 기준 급부 수와 86개 담보 가운데 80개가 다릅니다(기준 1종의 화면에 놓이는 79개는 모두 다름. 일반암 진단비 38 대 7. 2026-11-24 스냅샷).
4. 종형 구성 보기의 특약 그룹 기준(`담보구분`)은 값이 주계약 19, 선택특약 2,724뿐이라 사실상 한 그룹이고, 화면은 자료에 없는 값(`비갱신특약`, `갱신특약`)을 기다립니다(`RIDER_GRP_ORDER`). 특약 부가 조건과 직전 개정 대비가 그래프에 없었습니다.
5. 시장 동향 보기는 같은 회사라는 이유만으로 시장 동향에서 회사를 거쳐 종형까지 연결해 그려 관련 상품처럼 보입니다. 이번 주차 선별을 통과했는지도 구분하지 않습니다(2026-11-24 스냅샷에서 그래프는 26건 전부, 고객군과 시장 탭은 7건).

일곱 열 구조, 처음 상태(보장 대분류 다섯과 그룹 엣지), 보장 대분류에서 표준담보, 특약과 급부로 가는 세 단계 펼침은 Claude가 요청 28의 4.2절과 4.3절에서 지정한 것이었습니다. 이번에 철회합니다.

## 2. 화면이 읽는 자료

관계 그래프 자료의 스키마 개정 1단계는 `main`에 머지되어 있습니다. 규약 전체는 `proto_src/graph/API.md`의 "스키마 개정 1단계 (2026-11-24)" 절에 있습니다. 화면 쪽에서 알아야 할 것은 다음과 같습니다. 건수는 빌드 시점의 데이터에서 읽는 값이고, 표의 건수는 2026-11-24T14:29:59+09:00 스냅샷의 예시입니다. 화면 코드에 건수를 적어 두지 않습니다.

| 키 | 내용 |
| --- | --- |
| `kinds`, `ekinds` | 바꾸지 않는 자료 이름입니다. 노드 종류는 회사, 종형, 특약, 급부, 표준담보, 보장 대분류, 시장 동향(0~6)이고, 엣지 종류는 판매, 포함, 매핑, 분류, 담보 관계, 발표(0~5) 뒤에 보유, 결합제약, 개정, 언급 담보, 언급 상품(6~10)이 붙었습니다. 화면은 종류를 번호가 아니라 이 이름으로 찾습니다 |
| `kindLabels`, `ekindLabels` | 같은 차례의 화면 이름입니다. 자료 이름과 다른 것은 결합제약의 화면 이름 "특약 부가 조건"뿐입니다 |
| `edges2` | 엣지 종류 6~10만 담은 새 배열(857건)입니다. 형식은 `edges`와 같습니다. 화면은 `edges`와 `edges2`를 함께 색인합니다 |
| 보유 엣지(6) | 종형→표준담보 849건. 속성 `급부수`, `특약수`, `대표급부ID`(모두), `매핑검수대기급부수`(23건에만), `추출검수대기급부수`(144건에만). 키가 없으면 0입니다. 담보 비교 탭과 같은 계산에서 나온 값입니다 |
| 결합제약 엣지(7) | 기준 특약→대상 특약 5건(모두 `선행가입`. 우체국 종형 5개). 속성 `제약유형`, `근거문구` |
| 개정 엣지(8) | 직전 종형→현행 종형 3건. 속성 `신설`, `변경`, `종료`(화면 이름 삭제). 담보 단위의 수입니다 |
| 언급 담보(9), 언급 상품(10) | 지금 0건입니다. 이번에는 그리지 않습니다 |
| 노드 속성 | 회사: `기관구분`(규약상 보험회사, 감독기관, 협회, 업계 공통. 지금 자료에는 협회가 없음), `업권`(생명보험, 손해보험, 우체국. 보험회사에만), `비교대상`. 종형: `개정판ID`, `모상품ID`, `종형계보키`, `비교역할`, `판매종료일`. 특약: `특약계보키`, `보장대분류`(목록, 매핑된 급부가 있는 2,025개에만), `가입금액연동`(74개에만). 급부: `매핑상태`(`대기` 69, `대상외` 2,267), `추천표준담보ID`(69개), `추출검수대기항목`(705개, 열 이름 목록). 시장 동향: `수집주차`, `선별상태`(규약상 `passed`, `below`, `undecided`. 지금 자료에는 앞의 둘만 있음) |
| `summary.특약계보` | `{기관코드: {특약계보키: [종형 노드 번호, ...]}}`. 둘 이상 종형에 걸친 계보 482개, 계보는 회사 안에서만 나눴습니다 |
| `표시명` | 값과 속성 이름의 화면 이름입니다. 이번에 대기 → 매핑 검수 대기, passed → 통과, below → 통과 기준 미달, undecided → 판정 없음, 종료 → 삭제가 더해졌습니다. 요청 37에서 정한 대로 `App.addLabels(raw['표시명'])`를 거쳐 `App.label()`로 읽습니다 |

```js
const RAW = JSON.parse(document.getElementById('graph-data').textContent);
const NK = Object.fromEntries(RAW.kinds.map((n, i) => [n, i]));    // { 회사: 0, 종형: 1, 특약: 2, 급부: 3, 표준담보: 4, '보장 대분류': 5, '시장 동향': 6 }
const EK = Object.fromEntries(RAW.ekinds.map((n, i) => [n, i]));   // { 판매: 0, 포함: 1, 매핑: 2, 분류: 3, '담보 관계': 4, 발표: 5, 보유: 6, 결합제약: 7, 개정: 8, ... }
const dec = p => Object.fromEntries(Object.entries(p || {}).map(([k, v]) => [RAW.keys[+k], v]));
const N = RAW.nodes.map(([id, k, l, o, p], i) => ({ i, id, k, l, o, p: dec(p) }));
const E = RAW.edges.concat(RAW.edges2 || []).map(([s, t, k, p], i) => ({ i, s, t, k, p: dec(p) }));
const byId = new Map(N.map(n => [n.id, n.i]));
const REL_TARGET_IS_WIDE = true;   // 담보 관계 엣지는 지금 자료에서 도착 노드가 넓은 담보다. 3단계에서 자료와 함께 바꾼다

const c = App.ctx();               // c.baseId: 기준 종형, c.peerIds: 비교 범위로 거른 비교 대상 종형(summary.맞붙는종형과 같은 차례)
const types = [c.baseId, ...c.peerIds].map(id => byId.get(id));
const held = E.filter(e => e.k === EK['보유'] && types.includes(e.s));   // 화면에 놓을 (종형, 표준담보)
```

- 담보 관계 엣지 32건의 방향은 이번 단계에서 바뀌지 않았습니다(좁은 담보→넓은 담보, 속성 `관계`는 포함 19, 통합 13). 화면은 방향에 기대지 말고, 어느 쪽이 넓은 담보인지가 필요하면 위의 상수 하나로 읽습니다.
- 속성이 없다는 것을 "해당 없음", "연동 없음", "검수 완료"로 보이지 않습니다.
- 화면은 수를 새로 세지 않습니다. 급부 수와 특약 수는 보유 엣지의 속성, 보장 대분류별 수는 `summary.종형[종형ID].보장분야별`, 미매핑 급부 수는 `summary.종형[종형ID].미연결급부`에서 읽습니다. 화면이 하는 일은 엣지를 따라가는 탐색과 집합 연산(그룹 구성원 수, 필터 결과 수 같은 집합의 크기 포함)뿐입니다.
- 회사 이름은 지금 `orgLabel`의 순서를 유지합니다. 그래프의 회사 노드 이름(`G.orgNames[기관코드]`)을 먼저 쓰고, 없으면 `txt.orgShort(기관코드)`를 씁니다. `txt.orgShort`는 등록되지 않은 기관코드를 그대로 돌려주므로(`core.js`의 `orgShort`), 먼저 쓰면 회사 이름 대신 기관코드가 보입니다. 가상 자료에서는 그래프의 회사 노드 이름이 기관코드 그대로(`SYNFIRE01` 따위)이므로, 노드 이름이 기관코드와 같을 때도 `txt.orgShort`를 씁니다.

## 3. 기본 화면: 담보별 연결

### 3.1 그래프 영역과 해상도

- W, H는 관계 그래프 탭 가운데 영역에서 탐색 경로 행을 뺀 그래프 영역의 폭과 높이입니다(화면에서 잽니다). 아래 수치의 기준은 945x620(1920x1080 화면의 그래프 영역)입니다. 요청 35가 머지되면 실제 크기가 달라질 수 있으므로 모든 위치는 W, H의 비율로 계산합니다.
- 크기 비율 k = min(1, sqrt((W x H) / (945 x 620)))입니다. 노드 반지름, 앵커 반지름, 한 종형만 보유한 담보의 목표점 거리(62px)는 k배로 줄이고, 노드 외곽 사이 최소 간격은 k < 1이면 3px, 아니면 4px입니다. 그룹 원 사이 간격 14px, 여백 20px, 라벨 글자 13px는 그대로 둡니다. 945x620보다 크면 모두 그대로입니다. 계산 결과(타사 2개사, 기준 1종): 945x620 겹침 0과 그룹 분리 최소 1.44, 620x480(1280x800 화면) 겹침 0과 1.48(노드 반지름 3.6~7.1px), 1450x620 겹침 0과 1.44입니다.
- 선택이나 상세 패널의 내용 때문에 그래프 영역 크기가 바뀌면 안 됩니다(선택 때 기존 노드 이동 0px 조건이 깨집니다). 브라우저 리사이즈가 일어나면 150ms 뒤 한 번 다시 계산하고 트랜지션 없이 바꿉니다.
- 1,000px 미만은 8.3절의 목록으로 바꿉니다. 확대와 이동은 넣지 않습니다(4.8절).

### 3.2 화면에 두는 노드

- 기준 종형 하나, 비교 대상 종형(`c.peerIds`, 타사마다 하나), 이 종형들이 보유한 표준담보(보유 엣지로 정합니다). 간편한건강보험 1~4종 기준 79개, 통합건강보험 기준 73개입니다.
- 어느 종형도 보유하지 않은 담보, 보장 대분류 노드, 회사 노드는 그리지 않습니다. 보장 대분류는 노드 채움과 그룹 안 구역으로 보입니다.
- 노드는 그래프 영역 네 변에서 20px 안쪽에만 둡니다.

### 3.3 앵커(종형)

- 기준 종형: (0.15W, H/2), 945x620에서 (142, 310). 반지름 15px, 라벨은 앵커 위에 둡니다.
- 비교 대상 종형: 기준 앵커를 중심으로 한 타원(가로 반지름 0.80W, 세로 반지름 0.40H) 위에, 각도 −θ에서 +θ까지 같은 간격으로 둡니다(x = 기준 x + 0.80W x cos(각도), y = H/2 + 0.40H x sin(각도), 화면 좌표라 아래가 +). θ는 타사 1개사 0도, 2~3개사 50도, 4개사 이상 min(74, 50 + 3(n − 3))도입니다. 반지름 12px, 라벨은 앵커 오른쪽에 두고, 라벨이 오른쪽 여백 안에 들어오도록 앵커 x를 `W − 20 − 라벨 폭 − 반지름 − 8` 이하로 줄입니다. 945x620, 타사 2개사이면 한화생명 (628, 120), 삼성화재 (628, 500)입니다.
- 차례는 `c.peerIds`의 차례(기관코드 순)입니다. 그래서 기준 종형을 바꿔도 같은 회사는 같은 위치에 옵니다. 트랜지션에서 앵커를 대응시키는 키는 기준 앵커가 `base`, 타사 앵커가 기관코드입니다.
- 라벨: 기준 종형은 1행 "우체국(기준 종형)", 2행 종형명. 타사는 1행 회사 이름, 2행 종형명. 타사 4개사 이상이면 회사 이름 한 행입니다. 종형명이 14자를 넘으면 말줄임하고(시작값) 전체 이름은 호버와 상세 패널에 보입니다. 라벨 폭은 글자 수로 어림하지 말고 실제 글꼴로 잽니다(`measureText`나 SVG `getComputedTextLength`).

### 3.5 1단계: 그룹 원 배치

1. 담보마다 목표점을 정합니다. 우체국과 타사가 보유하면 0.5 x 기준 앵커 + 0.5 x 보유 타사 앵커의 평균, 타사만 보유하면 보유 타사 앵커의 평균, 한 종형만 보유하면 그 앵커에서 바깥쪽으로 62px입니다. 바깥쪽은 타사면 기준 앵커에서 그 앵커로 향하는 방향, 우체국이면 110도(화면 좌표, 0도 오른쪽, 90도 아래)입니다. 180도에 두면 그 그룹의 라벨이 6개 가운데 2개만 붙습니다.
2. 그룹 하나를 원 하나로 보고 배치합니다. 그룹의 목표점은 구성원 목표점의 평균이고, 그룹 원 반지름은 2단계(3.6절)에 맞춰 R = sqrt(Σ(r + 3)² / 0.60)이고, 최소 가장 큰 구성원 반지름 + 1입니다. r은 구성원의 충돌 반지름입니다(3.7절).
3. 시뮬레이션: 목표점 힘 세기 0.10, 충돌(그룹 원끼리와 그룹 원과 앵커 사이 간격 14px, 세기 0.8), 반발력 −30(중심 거리 40px 안에서만), 앵커 라벨 영역 안으로 들어오면 밖으로 밀기, 여백 20px 안으로 자르기를 300회 반복합니다. alpha는 1에서 0.001로 줄이고(반복마다 alpha ← alpha + (0 − alpha)(1 − 0.001^(1/300))), 속도 감쇠는 0.4(속도 x 0.6)입니다. d3-force의 forceX, forceY, forceManyBody(distanceMax), forceCollide와 같은 형식입니다. 초기 좌표는 목표점 + 그룹 키의 해시 지터(±5px, 3.12절)입니다.
4. 반복 뒤 위치만 옮겨 겹침과 간격 부족이 없어질 때까지 되풀이합니다(최대 300회).
5. 계산 결과: 그룹 원 사이 최소 간격 14px, 그룹 분리(두 그룹 중심 거리 / 두 그룹 반경 합)의 최솟값이 타사 2개사 1.44(간편 1~4종)와 1.33(통합), 3개사 1.16, 20개사 1.19입니다. 그룹 원을 먼저 두지 않고 노드만 한 번에 배치하면 3개사 0.70, 20개사 0.05로 그룹이 섞였습니다. 두 단계 방식을 지킵니다.

### 3.6 2단계: 그룹 안 배치

- 기준: 노드 겹침 0, 노드 외곽 사이 4px 이상(k < 1이면 3px), 그룹 원 밖 노드 0, 그룹 원 사이 14px 이상, 결정적(3.12절). 같은 보장 대분류는 그룹 안에서 한 구역에 모이고, 구역 차례는 모든 그룹에서 같습니다(그룹 중심에서 위쪽부터 시계 방향으로 암보장, 뇌혈관보장, 뇌심장보장, 심장보장, 공통보장. 담보 4개 이상인 그룹에 적용). 보장 대분류 최근접 이웃 일치(담보마다 같은 그룹 안에서 가장 가까운 담보의 보장 대분류가 같은 비율)가 타사 2개사 기준 1종에서 0.60 이상입니다. 계산값은 0.81이었습니다. 재는 방법은 12절 10번입니다.

### 3.7 노드 크기와 호버 판정

- r = 5 + 5 x sqrt(min(b, 16) / 16), 즉 5~10px. b는 화면에 놓인 종형의 보유 엣지 `급부수` 합입니다(크기에만 쓰고 수로 화면에 적지 않습니다).
- 충돌 반지름: 표지(5.3절)가 붙는 노드와 타사 4개사 이상의 링 차트가 있는 노드는 r + 3px로 계산합니다(시작값). 겹침과 간격 기준은 노드 반지름 r로 잽니다.
- 호버 판정: 포인터에서 가장 가까운 노드 중심까지의 거리가 max(r + 4, 12)px 이하면 그 노드를 호버로 봅니다. 판정 영역이 겹치면 가장 가까운 노드입니다. 620x480에서는 노드가 지름 7~14px라 이 규칙이 꼭 필요합니다. 이번에 바꾸는 기준입니다: 요청 28의 클릭 대상 폭 24px 이상 기준을 관계 그래프의 노드에는 적용하지 않고 이 반지름 규칙으로 바꿉니다(4.10절의 표).

### 3.8 엣지

- 담보별 연결의 엣지는 모두 직선입니다. 직각으로 꺾지 않습니다.
- 기본 화면에는 보유 번들 엣지만 그립니다. (종형, 그룹)마다 엣지 하나를 앵커 가장자리에서 그룹 원 가장자리까지 두 중심을 잇는 선 위에 그리고, 굵기는 0.6 + 0.18 x n(최대 6px)입니다. n은 그 그룹에서 그 종형이 보유한 담보 수입니다(타사 3개사 이하에서는 그룹의 담보 수). 엣지 수는 타사 2개사 12, 3개사 25입니다.
- 계산 결과(노드 가장자리에서 자른 직선, 끝 노드를 공유하는 엣지는 세지 않음): 타사 2개사의 번들 엣지끼리 교차는 기준 종형 다섯과 945x620, 620x480, 1450x620 모두 0입니다. 3개사는 4이고 모두 타사 번들 엣지가 낀 교차입니다(기준 종형 번들만 그리면 0).

- 앵커 라벨과 그룹 라벨은 늘 보입니다. 그룹 라벨은 두 행입니다(11절의 형식. 예: 1행 "한화생명, 삼성화재 보유", 2행 "담보 32개, 우체국 미보유").
- 그룹 라벨 위치: 담보 수가 많은 그룹부터, 그룹 원 바깥 4px(시작값) 위치의 위, 아래, 오른쪽, 왼쪽, 대각 넷의 여덟 곳, 그다음 같은 방향으로 22px 더 떨어진 여덟 곳(그룹 원까지 지시선)을 차례로 보고, 다른 라벨, 그룹 원, 앵커, 앵커 라벨, 그래프 영역 밖과 겹치지 않는 첫 위치를 씁니다. 모두 막히면 그룹 원 위쪽 테두리에 담보 수만 쓴 배지로 바꾸고 전체 라벨은 호버로 보입니다. 타사 3개사 계산 그림에서 그룹 라벨이 서로 겹친 사례가 있어 이 규칙을 둡니다.
- 담보 이름 라벨: 우체국만 보유, 우체국과 타사 보유, 타사만 보유 차례로, 같은 구분 안에서는 큰 노드부터(같으면 표준담보 사전 차례) 노드 오른쪽, 왼쪽, 위, 아래(노드에서 2px)를 차례로 보고 다른 라벨, 노드, 앵커, 앵커 라벨, 그룹 라벨과 겹치지 않을 때만 붙입니다. 나머지 이름은 호버와 상세 패널에서 보입니다.
- 13px로 다시 센 담보 이름 라벨 수(같은 계산 스크립트, 글자 폭은 어림): 945x620에서 간편 1종 36/79, 통합 37/73, 620x480에서 18/79와 23/73, 1450x620에서 41/79와 40/73입니다. 실제 글꼴로 잰 수를 PR 글에 적어 주세요.

### 3.11 왼쪽 영역과 범례

- 왼쪽 영역의 차례: 보기 방식(담보별 연결, 종형 구성, 시장 동향), 보기마다의 필터(담보별 연결은 판정 필터 5.4절, 종형 구성은 6절, 시장 동향은 7절), 범례, 검색, 탐색 이동(실행 취소, 초기화).
- 범례: 보유 구분 셋(그룹 원 모양), 보장 대분류 다섯(노드 채움, 관계 그래프 안의 차례), 표지(5.3절), 엣지(3.8절의 표). 범례 그림은 인라인 SVG로 그리고 24x20px보다 작게 둡니다(본문 사각 면 기준).
- 범례의 보유 구분과 보장 대분류 항목은 클릭하면 그 항목의 담보만 강조하는 필터로 씁니다(판정 필터와 같은 강조 방식이고, 판정 필터와 합쳐 한 번에 하나만 켭니다).
- 범례 창(`ui.registerLegend('graph', ...)`)도 같은 내용으로 바꿉니다.

### 3.12 결정성과 계산 시간

- 난수를 쓰지 않습니다(`Math.random` 0). 지터는 FNV-1a 32비트 해시(초깃값 `0x811C9DC5`, 곱하는 수 `0x01000193`, `salt + ':' + 키`의 UTF-8 바이트)를 2^32로 나눈 값 u로 정합니다. 지터 = (u − 0.5) x 범위. salt는 그룹 원이 `gx`, `gy`, 노드가 `x`, `y`입니다.
- 반복 횟수는 고정하고, 처리 차례는 정렬 키(그룹 키 차례, 표준담보 사전 차례 = graph.json 표준담보 노드 차례)로 정합니다. DOM 차례나 시간에 기대지 않습니다. 같은 입력이면 같은 좌표가 나와야 합니다.
- 좌표는 (보기 방식, 기준 종형, 비교 범위, W, H)를 키로 캐시합니다. 조건이 바뀌면 트랜지션을 시작하기 전에 계산을 끝냅니다. 탭에 들어오면 지금 화면의 `requestIdleCallback` 예열과 같은 방식으로, 기준 종형 다섯 x 비교 범위 셋(전체, 생명보험, 손해보험)의 15개 상태를 모두 지금 보기 방식과 그래프 영역 크기로 미리 계산합니다. 지금 조건의 상태부터 계산합니다. 예열이 끝나기 전에 조건이 바뀌면 그 조건의 계산을 프레임당 8ms 이하로 나눠 실행하고, 계산이 끝난 뒤 트랜지션을 시작합니다. 조건마다 첫 계산 시간(보통 속도, CPU 4배 느림)을 PR 글에 적어 주세요. 브라우저 계산 시간은 아무도 재지 않았습니다.
- 외부 라이브러리 없이 직접 구현합니다(오프라인 단일 HTML, 외부 요청 0). 라이브러리를 인라인으로 넣어야 한다면 PR 글에 이유와 라이선스를 적어 주세요.

### 3.13 측정용 data 속성

검수와 측정 스크립트가 화면 코드를 거치지 않고 읽을 수 있게 다음 속성을 답니다.

- 노드: `data-gr-id`(노드 ID), `data-gr-kind`(`kinds`의 자료 이름), `data-gr-r`(반지름), 표준담보는 `data-gr-group`(그룹 키), `data-gr-cls`(`only`, `shared`, `peer`), `data-gr-mark`(표지를 공백으로 이은 것: `sole`, `peer-rel`, `ours-wide`, `ours-part`, `wait`).
- 그룹 원: `data-gr-group`, `data-gr-count`(라벨에 적은 담보 수).
- 엣지: `data-gr-ekind`(`ekinds`의 자료 이름, 번들은 `보유` 뒤에 `data-gr-bundle="1"`), `data-gr-s`, `data-gr-t`(양 끝 노드 ID, 번들의 도착은 그룹 키).

## 4. 인터랙션

### 4.1 호버

- 담보 노드: 그 노드, 개별 보유 엣지와 그 앵커, 담보 관계 엣지와 그 엣지로 연결된 담보, 관련 담보 근거 경로(5.3절)를 강조하고 나머지 노드, 그룹 원, 엣지는 불투명도 .35로 낮춥니다(120ms). 툴팁에는 담보 이름, 보장 대분류, 그룹 이름, 표지 설명, 타사별 판정 칩(`App.cover.chip(v)`. 세 개사까지, 넘으면 "외 n개사"), 회사별 급부 수(보유 엣지 `급부수`)를 적습니다. 툴팁은 포인터를 따라 옆 노드로 옮겨 가고 화면 가장자리에서 잘리지 않습니다.
- 앵커: 그 종형의 개별 보유 엣지와 보유 담보를 강조합니다(타사 4개사 이상은 8.1절). 툴팁에는 회사, 종형명, 보유 담보 수, 보장 대분류별 수(`summary.종형[종형ID].보장분야별`)를 적습니다.
- 그룹 원과 그룹 라벨: 그룹 원과 그 그룹으로 가는 번들 엣지를 강조합니다. 툴팁에는 그룹 이름, 담보 수, 보장 대분류별 수, "클릭하면 담보 목록"을 적습니다.
- 엣지: 엣지 가운데 종류 이름 칩(`ekindLabels`)을 보입니다(지금 기능 유지).

### 4.2 그룹 선택

- 그룹 원이나 그룹 라벨을 클릭하면 그 그룹을 선택 표시하고 구성원 밖은 불투명도 .45로 낮춥니다(220ms).
- 상세 패널: 그룹 이름, 담보 수, 보장 대분류별 수, 담보 목록(보장 대분류 차례, 그 안에서 표준담보 사전 차례). 목록의 행마다 담보 이름, 표지, 타사별 판정 칩을 두고, 행을 클릭하면 그 담보를 선택합니다(4.3절).

### 4.3 담보 선택: 특약과 급부 펼치기

1. 기존 노드는 이동하지 않습니다(0px). 선택한 담보와 그 담보와 담보 관계로 연결된 담보만 원래 크기로 두고, 나머지 표준담보는 반지름 3px로 줄여(transform) 불투명도 .45로 낮춥니다.
2. 선택한 담보를 보유한 종형마다 특약 열과 급부 열을 둡니다. 특약 열은 앵커에서 담보로 가는 선분의 30% 지점, 급부 열은 68% 지점입니다. 열은 세로로 쌓고(특약 간격 17px와 반지름 6px, 급부 간격 15px와 반지름 5px), 앵커에서 담보로 가는 방향의 가로 성분이 0.5 미만이면 가로로 늘어놓습니다. 특약과 급부는 graph.json 노드 차례이고, 급부는 특약 차례대로 두어 특약에서 급부로 가는 엣지가 나란하게 합니다. 특약은 종형마다 12개까지, 넘으면 열 끝에 "+N" 노드를 둡니다.
3. 펼친 노드는 계획한 위치를 목표점(세기 0.15)으로 두고 충돌(간격 4px)과 약한 반발력(−4, 30px 안)만으로 160회 정리한 뒤 겹침을 없애는 정리를 합니다. 기존 노드(줄인 반지름), 앵커, 앵커 라벨은 고정 장애물입니다.
4. 엣지: 종형→특약, 특약→급부(포함), 급부→담보(매핑). 그 종형에서 선택한 담보를 `추천표준담보ID`로 가진 매핑 검수 대기 급부도 그 열에 두고 테두리와 담보로 가는 선을 점선으로 그립니다. 추출 검수 대기 급부(`추출검수대기항목`이 있음)에는 검수 대기 표지를 붙입니다.
5. 특약 라벨은 그 종형의 특약이 6개 이하일 때만 그래프에 붙입니다. 많으면 열 옆에 "한화생명 특약 12, 급부 14"처럼 적고(보유 엣지 `특약수`, `급부수`), 전체 이름은 상세 패널에 그래프 열과 같은 차례로 보입니다. 앞 16자가 같은 특약이 많아 잘라 보이면 구분되지 않기 때문입니다.
6. 타사 4개사 이상이거나 펼칠 급부 노드가 39개를 넘으면(시작값) 우체국 종형만 펼치고, 타사 종형은 종형마다 요약 노드 하나("한화생명 특약 12개, 급부 14개", 보유 엣지 속성)로 접습니다. 요약 노드는 앵커에서 담보로 가는 선분의 50% 지점(시작값)에 두고, 클릭하면 그 종형 하나만 펼칩니다.
7. 계산 결과(타사 2개사, 기준 1종): 암 수술비(우체국 특약 1과 급부 2, 한화생명 12와 14, 삼성화재 5와 5) 펼친 엣지 60, 교차 1, 겹침 0, 최소 간격 4.0px. 일반암 진단비(특약 6, 급부 7) 펼친 엣지 20, 교차 0. 특약 라벨이 앵커를 덮는 경우가 암 수술비 3건, 일반암 진단비 1건 있었고 5번 규칙으로 줄입니다.
8. 상세 패널: 담보 이름, 보장 대분류, 그룹 이름, 표지, 타사별 판정 칩과 까닭(`v.why`), 회사별 특약 수와 급부 수, 대표 급부(`대표급부ID`의 급부 노드 이름), 특약과 급부 목록(그래프 열 차례, 급부역할, 검수 상태), 담보 관계로 연결된 담보(넓은 담보, 부분 담보. 클릭하면 그 담보 선택), 다른 탭으로 가는 버튼(담보 비교에서 보기, 인수기준 비교에서 보기. 지금 동작 유지).
9. 다른 담보를 선택하면 지금 펼침을 접고 새 담보를 펼칩니다. Esc나 빈 영역 클릭으로 선택을 풉니다.

### 4.4 종형 선택

- 앵커를 클릭하면 그 종형의 종형 구성 보기(6절)로 넘어갑니다. 앵커는 가운데 상자로, 그 종형이 보유한 표준담보 노드는 바깥 원의 위치로 위치 트랜지션(4.9절의 시간과 이징)으로 옮기고, 다른 노드는 흐려지며 빠지고 특약과 급부는 나타납니다.
- 탐색 경로나 실행 취소로 담보별 연결에 돌아오면 캐시한 좌표로 같은 화면이 됩니다.

### 4.5 엣지 선택

엣지를 클릭하면 상세 패널에 속성을 보입니다. 속성 이름과 값은 `App.label()`을 거칩니다. 선 모양 설명(`lineStyleLabel`)은 엣지 종류의 자료 이름으로 정하고, 모르는 종류를 "실선 (판매 또는 포함)"으로 적는 기본값을 없앱니다.

| 엣지 | 상세 패널 |
| --- | --- |
| 보유, 번들 | 종형, 그룹, 그 종형이 보유한 그룹의 담보 목록 |
| 보유, 개별 | 급부 수, 특약 수, 대표 급부 이름, 매핑 검수 대기 급부 수, 추출 검수 대기 급부 수(키가 있을 때만) |
| 담보 관계 | 관계(포함, 통합), 넓은 담보와 부분 담보의 이름(방향 상수로 읽음), 이중 추출의 확신 두 값 |
| 매핑 | 검수 상태, 매핑확률(있을 때만), 확정방식 |
| 포함(특약→급부) | 급부역할 |
| 특약 부가 조건 | 제약유형, 근거문구(스냅샷 값 그대로) |

### 4.6 검색

지금의 검색 상자와 추천 목록을 유지하고, 결과를 선택했을 때의 동작을 바꿉니다.

- 표준담보: 지금 보기에 있으면 담보별 연결에서 그 담보를 선택합니다. 지금 기준 종형과 비교 대상 종형이 보유하지 않은 담보면 노드를 만들지 않고 "현재 기준 종형과 비교 대상 종형이 보유하지 않은 담보입니다"를 알립니다.
- 종형: 지금 앵커에 있으면 그 앵커를, 아니면 그 종형의 종형 구성 보기를 엽니다(판매종료 종형과 인수기준만 수집한 종형 포함).
- 특약과 급부: 그 종형의 종형 구성 보기를 열고 그 노드를 선택합니다.
- 회사와 시장 동향: 시장 동향 보기를 열고 그 노드를 선택합니다.

### 4.7 키보드와 터치

- 노드는 roving tabindex로 다룹니다. Tab으로 그래프에 들어오면 마지막에 포커스한 노드(없으면 기준 앵커)로 가고, 다시 Tab이면 다음 영역으로 나갑니다.
- 화살표: 그 방향 ±45도 안에서 중심이 가장 가까운 포커스 대상(앵커, 그룹 라벨이나 배지, 담보, 펼친 특약과 급부)으로 옮깁니다. 없으면 그대로 둡니다. Home은 기준 앵커, End는 마지막 그룹 라벨입니다.
- Enter와 Space는 선택(담보는 펼치기, 그룹은 그룹 선택, 앵커는 종형 구성), Esc는 선택 해제이고 포커스는 선택했던 노드로 돌아갑니다. 선택 뒤 포커스가 `body`로 빠지지 않습니다. Z는 실행 취소(지금 동작 유지)입니다.
- 포커스는 호버와 같은 포커스 표시로 보입니다.
- 터치: 탭이 선택이고, 호버로 보이던 강조와 툴팁 내용은 선택 상태와 상세 패널에 함께 보입니다. `pointer` 이벤트 하나로 마우스, 터치, 펜을 다룹니다.

### 4.8 확대와 이동은 넣지 않습니다

휠 확대, 드래그 이동, 노드 드래그는 넣지 않습니다.

1. 레이아웃을 그래프 영역 크기에 맞춰 계산하므로 기본 화면, 선택 상태, 종형 구성(우체국 종형)이 스크롤 없이 한 화면에 들어갑니다(계산 결과).
2. 확대하면 겹침 0과 라벨 위치를 맞춘 좌표가 의미를 잃고 영역 밖으로 나가는 노드가 생깁니다.
3. 휠 확대는 요청 35의 안쪽 영역 스크롤과 충돌합니다.
4. 노드 드래그는 같은 입력에서 같은 좌표라는 원칙과 선택 때 기존 노드 이동 0px 원칙을 깹니다.

노드가 작은 1280x800은 호버 판정 반지름, 툴팁, 상세 패널로 해결합니다. 특약이 200개를 넘는 타사 종형의 종형 구성은 보장 대분류 필터와 상세 패널 목록으로 봅니다.

### 4.9 조건을 바꿀 때(기준 종형, 비교 범위)

1. 지금 보기 방식을 유지하고 새 좌표를 계산한 뒤 위치 트랜지션으로 옮깁니다. 표준담보 노드는 표준담보ID, 그룹 원은 그룹 키, 앵커는 3.3절의 키로 대응시킵니다.
2. 트랜지션: 시간 480ms(시작값, `--dur-graph-move`), 이징은 요청 28의 위치 이동 이징 `cubic-bezier(0.65, 0, 0.35, 1)`(`--ease-move`, `--ease-graph-move`로 다시 둡니다). 두 변수는 `tab6.css`의 `:root`에 두어 사용자가 보고 조정할 수 있게 합니다. 이동하는 노드와 그룹 원은 모두 같은 시각에 시작하고 같은 시간에 끝나며 직선 경로로 이동합니다. 사라지는 노드는 처음 40% 동안 제자리에서 흐려지며 빠지고(`--ease-out`), 새 노드는 마지막 50% 동안 도착 위치에서 불투명도 0과 크기 0.6배에서 나타납니다(`--ease-in`). 번들 엣지와 라벨은 처음 25% 동안 흐려지며 빠지고, 노드가 도착한 뒤 엣지는 앵커에서 그룹 쪽으로 그어지고(`stroke-dashoffset`, 320ms) 라벨은 다시 배치해 120ms에 나타납니다.
3. 애니메이션 설정이 줄임이면 시간을 0.55배(`App.motionScale()`)로 줄여 위치 트랜지션을 짧게 남기고, 끔일 때만 트랜지션 없이 바꿉니다(요청 28과 35의 설정 규칙).
4. 선택한 담보가 새 조건에서도 화면에 있으면 선택을 유지하고(펼침을 접고, 이동하고, 새 위치에서 다시 펼침), 없으면 선택을 풉니다.
5. 계산 결과(안 A, 타사 2개사): 간편 1, 2, 3종 사이 이동 0px. 3종과 4종 사이 평균 0.7px. 4종에서 통합건강보험으로 바꾸면 공통 담보 72개 가운데 59개가 같은 그룹에 남아 평균 10.8px, 13개가 그룹을 옮겨 평균 269px 이동하고, 4종에만 있는 7개가 사라지며 1개가 새로 생깁니다. 그룹을 옮기는 담보는 보유 조합이 바뀐 담보이므로 트랜지션이 그 변화를 보여 줍니다. 비교 범위를 2개사에서 3개사로 바꾸면 평균 65.5px이고 73%가 10px 넘게 이동합니다.

| 일곱 열의 노드 모양(종류별 직각 사각 노드 일곱 종류), 이웃 펼치기 버튼과 12개 단위 "+N 더" 열 | 철회. 원형 노드(표준담보, 특약, 급부), 원형 앵커, 종형 구성의 가운데 상자로 바꾸고, 펼침은 4.3절과 6절의 규칙으로 |

| 1,000px 미만에서 선택한 노드의 경로만 세로 한 열로 세움 | 8.3절의 그룹 카드 목록으로 바꿈 |

### 4.11 탐색 경로, 실행 취소, 다른 탭에서 들어올 때

- 탐색 경로, 실행 취소(Z), 초기화는 유지합니다. 경로의 항목 이름은 보기 이름("담보별 연결", "종형 구성", "시장 동향"), 선택한 담보나 그룹 이름, 종형 구성의 종형명입니다.
- 요청 28에서 사용자가 정한 두 원칙(노드를 클릭해 단계를 넘어가며 넓혀 가는 탐색, 엣지 속성 보기)은 유지합니다. 이번 구조에서 그 탐색은 담보에서 회사별 특약과 급부로, 앵커에서 종형 구성으로, 종형 구성의 표준담보에서 담보별 연결의 그 담보로, 펼친 특약에서 상세 패널의 "종형 구성에서 보기"로, 회사에서 시장 동향으로 넘어가는 길입니다.
- 다른 탭에서 들어오는 `focus()`의 대상(`std:`, `var:`, `org:`, `news:`)을 유지합니다. `std:`는 담보별 연결에서 그 담보 선택, `var:`는 4.6절의 종형 규칙, `org:`와 `news:`는 시장 동향 보기입니다.
- 요약 복사는 지금 보기의 노드를 표로 복사합니다(담보별 연결: 그룹, 담보, 보장 대분류, 표지, 타사별 판정. 종형 구성: 특약, 급부, 표준담보. 시장 동향: 회사, 발표일자, 분류유형, 핵심요약, 선별상태).

## 5. 판정과 표시

### 5.1 원칙

- 화면은 판정을 만들지 않습니다. 판정은 graph.json에 없고, 담보 비교 탭과 같은 cover.json을 `App.cover`로 읽습니다. 같은 판정을 두 파일에 두지 않기 위해서입니다.
- 그룹 위치는 직접 매핑 기준의 보유만 말합니다. 판정과 관련 담보 표시는 노드에 표지로 덧붙입니다.
- 타사만 보유하고 우체국은 넓은 담보나 부분 담보로 보장하는 64행의 판정은 그대로 `우체국에 없음`(우체국 미보유)입니다. 판정 규칙을 바꾸지 않고 관계 그래프에서 표시만 더한다는 것이 사용자가 승인한 내용입니다.

### 5.2 읽는 법

```js
const c = App.ctx(), baseId = c.baseId;
const pv = App.cover.peerVerdicts(baseId, sid, c) || [];          // [{ peer: 타사 종형ID, v }], 비교 범위로 거름. v 가 null 이면 양사 미보유
const meta = App.cover.rawMeta().table;                              // 까닭(v.cause) → { 판정, 칩, 표시명 }
const row = (App.cover.rawB(baseId) || { rows: [] }).rows.find(r => r[0] === sid);
const ours = row && row[1][0];                                       // 우체국 셀. i 가 비지 않으면 보유, w 만 있으면 매핑 검수 대기
const oursRel = ours && typeof ours === 'object' && !(ours.i && ours.i.length) && ours.c;   // ['넓은 담보' | '부분 담보', [덮는 표준담보ID...], 일부만 가짐]
const peerRel = k => row && row[1][k] && row[1][k].c;                // k 번째 비교 대상 종형(App.cover.peerCols(baseId)[k]) 쪽 관련 담보 근거
// 칩과 글은 App.cover.chip(v), App.cover.chipText(v), 까닭 설명은 v.why 를 그대로 쓴다
```

- 까닭(`v.cause`)은 자료의 키입니다: `나음`, `같음`, `못함`, `엇갈림`, `판정 보류`, `단정 주의`, `지급 형태 다름`, `관계 담보로 덮음`, `검토 대기`, `우체국에 없음`, `상대에 없음`. 까닭마다의 화면 이름은 sales.json `표시명`의 값(`App.label(까닭)`)으로, 차례대로 우위, 동일, 열위, 우열 혼재, 판정 보류, 단순 비교 불가, 지급 형태 상이, 관련 담보로 보장, 검수 대기, 우체국 미보유, 타사 미보유입니다. cover.json 판정표의 `표시명`은 이것과 다른 값으로, 판정 칩의 분류 이름입니다(예: `나음`은 우체국 우위, `엇갈림`, `단정 주의`, `지급 형태 다름`, `관계 담보로 덮음`은 모두 단순 비교 불가, `상대에 없음`은 우체국 단독 보유). 이 요청의 필터와 표지 이름은 까닭의 화면 이름을, 칩은 `App.cover.chip(v)`를 씁니다. 화면 코드는 글자가 아니라 까닭 키와 판정표의 `칩`으로 가릅니다.
- `App.cover.hasRow(baseId, sid)`가 거짓이면 판정 자료가 없는 담보입니다. 표지와 필터에서 빼고 "판정 자료 없음"을 지어 적지 않습니다.

### 5.3 표지

| 표지(`data-gr-mark`) | 붙는 담보 | 자료 조건 | 모양(시작값) | 툴팁과 상세 패널 |
| --- | --- | --- | --- | --- |
| 우체국 단독 보유(`sole`) | 우체국만 보유 그룹 | 비교 범위의 어느 타사에도 까닭 `관계 담보로 덮음`이 없음 | 금색 마름모(한 변 6px, 면 `--gold`, 테두리 `--gold-line`), 노드 오른쪽 위 가장자리 | 판정 칩(`App.cover.chip(v)`, 까닭 `상대에 없음`) |
| 타사 관련 담보로 보장(`peer-rel`) | 우체국만 보유 그룹 | 까닭 `관계 담보로 덮음`인 타사가 하나 이상. "우체국 단독 보유"로 부르지 않음 | 같은 위치의 속이 빈 마름모(테두리 1.2px `--gold-line`) | 그 타사의 판정 칩과 `v.why` |
| 우체국은 넓은 담보로 보장(`ours-wide`) | 타사만 보유 그룹 | `oursRel[0]`이 `넓은 담보` | 지름 6px 속이 찬 원(`--ink-0`), 노드 오른쪽 아래 가장자리 | "우체국은 넓은 담보인 {덮는 담보 이름}로 보장" |
| 우체국은 부분 담보로 보장(`ours-part`) | 타사만 보유 그룹 | `oursRel[0]`이 `부분 담보` | 같은 위치의 지름 6px 원, 왼쪽 반만 채움 | "우체국은 부분 담보인 {덮는 담보 이름}로 보장" |
| 검수 대기(`wait`) | 모든 그룹 | 화면에 놓인 종형의 보유 엣지에 `매핑검수대기급부수`나 `추출검수대기급부수`가 있음 | 노드 테두리 1px 점선 `--unknown-edge`(담보 비교의 검수 대기 칩과 같은 선) | 회사별 매핑 검수 대기와 추출 검수 대기 급부 수 |

- 다섯 표지는 흑백으로 찍어도 구분되어야 합니다.
- 근거 경로: `ours-wide`, `ours-part` 담보를 호버하거나 선택하면 덮는 담보(`oursRel[1]`)까지, `peer-rel` 담보는 그 타사의 덮는 담보(`peerRel(k)[1]`)까지 담보 관계 엣지를 그립니다. 바로 연결되는 엣지가 없으면 화면에 있는 담보 가운데 중간 담보 하나를 거치는 경로(담보 관계 엣지 둘)를 찾아 함께 그립니다. 지금 자료에서 64행 가운데 53행은 바로 연결되고, 11행(담보 3개: `면역항암약물허가치료비`, `항암양성자·중입자방사선치료비`, `표적항암약물허가치료비`)은 `항암약물치료비`나 `항암방사선치료비`를 거쳐 `항암방사선·약물치료비(통합)`에 이릅니다. 엣지 둘 안에 경로가 없으면 선을 그리지 않고 툴팁에 덮는 담보 이름만 적습니다.
- 우체국과 타사 보유 그룹의 담보에는 판정 표지를 붙이지 않습니다. 판정은 툴팁, 상세 패널, 판정 필터로 봅니다.

### 5.4 판정 필터

- 버튼 다섯: 우위, 열위, 단순 비교 불가, 검수 대기, 관련 담보로 보장. 이름은 판정 표시명, 곧 `App.label()`로 읽은 자료의 표시명을 씁니다(`나음`, `못함`, `단정 주의`, `검토 대기`, `관계 담보로 덮음`의 표시명). 버튼 이름을 화면 코드에 글자로 적지 않습니다.
- 조건(비교 범위의 타사 가운데 1개사라도 해당하면 그 담보를 강조): 우위는 까닭 `나음`, 열위는 `못함`, 단순 비교 불가는 판정표의 `칩`이 `diff`인 까닭(담보 비교 탭의 칩과 같음), 검수 대기는 까닭 `검토 대기`이거나 `wait` 표지, 관련 담보로 보장은 까닭 `관계 담보로 덮음`이거나 `oursRel`이 있음.
- 켠 필터의 담보는 그대로, 나머지 노드와 엣지는 불투명도 .35. 한 번에 하나만 켜고, 다시 클릭하면 끕니다. 버튼 옆에 강조된 담보 수를 적습니다. 타사별 판정은 호버와 상세 패널에서 타사마다 보입니다.

### 5.5 검수 대기와 급부 수

- 표준담보 카드와 상세 패널의 급부 수는 화면에 놓인 종형의 보유 엣지 `급부수`를 회사별로 적습니다. 지금처럼 매핑 엣지가 있는 종형 전부를 세지 않습니다.
- 상세 패널에는 회사별 매핑 검수 대기 급부 수(보유 판단과 관련 있음)와 추출 검수 대기 급부 수(급부 값의 확인 상태)를 따로 적고, 펼친 급부에는 `매핑상태`(표시명 매핑 검수 대기, 매핑 대상 외)와 `추출검수대기항목`(열 이름 목록)을 적습니다. 키가 없으면 0이고 "검수 완료"로 적지 않습니다.

### 5.6 표시 이름

- 노드 이름은 자료의 이름(`n.l`)을 그대로 씁니다. 종류 이름은 `kindLabels`, `ekindLabels`, 값과 속성 이름은 `App.label()`, 판정은 `App.cover.chip(v)`와 `chipText(v)`, 회사 이름은 2절의 `orgLabel` 순서(그래프의 회사 노드 이름 먼저, 없거나 기관코드와 같으면 `txt.orgShort(기관코드)`)입니다.
- 상세 패널 속성 표에서 ID를 가리키는 속성은 이름으로 바꿔 보입니다(`대표급부ID` → 대표 급부 이름, `추천표준담보ID` → 추천 표준담보 이름). 해시와 내부 키(`특약계보키`, `종형계보키`, `개정판ID`, `모상품ID`)와 노드 ID는 상세 패널 아래의 접힌 "ID" 영역에만 둡니다. 속성 표, 툴팁, 라벨, 요약 복사에는 내보이지 않습니다.

## 6. 종형 구성 보기

종형 하나의 특약, 급부, 표준담보를 방사형으로 보입니다. 보기 방식에서 선택하면 기준 종형으로 시작하고, 앵커 클릭, 검색, 상세 패널의 "종형 구성에서 보기"로도 들어옵니다.

1. 가운데에 종형 상자(168x46px, 시작값)를 두고 1행 회사 이름, 2행 종형명을 적습니다. 상자 안에 미매핑 급부 수(`summary.종형[종형ID].미연결급부`)를 적고, 상자를 클릭하면 상세 패널에 종형 속성(비교역할은 `App.label()`), 보장 대분류별 수, 직전 개정, 특약 부가 조건 수, "인수기준 비교에서 보기"를 보입니다. 판매종료 종형과 인수기준만 수집한 종형은 지금 화면의 안내 문장(담보 비교 대상이 아니라는 문장)을 함께 보입니다.
2. 기준 타원: 그래프 영역 가운데를 중심으로 가로 반지름 W/2 − 14, 세로 반지름 H/2 − 14. 동심 타원 셋에 특약(정규화 반지름 0.36), 급부(0.63), 표준담보(0.90)를 둡니다.
3. 방향: 타원 둘레 길이의 비율 t(0이 12시, 시계 방향)로 정합니다. 둘레를 720등분한 누적 길이 표를 한 번 만들고, t를 각도로 바꿀 때 이진 탐색과 선형 보간을 씁니다. 같은 t는 어느 타원에서나 가운데에서 본 방향이 같습니다.
4. 표준담보: 보장 대분류 부채꼴을 12시부터 시계 방향으로 암보장, 뇌혈관보장, 뇌심장보장, 심장보장, 공통보장 차례로 둡니다. 부채꼴 크기는 (그 대분류의 표준담보 사전 담보 수와 10 가운데 큰 값) + 1에 비례하고, 수는 graph.json의 표준담보 노드에서 셉니다(지금 31, 11, 8, 13, 23이라 둘레의 0.344, 0.129, 0.118, 0.151, 0.258). 종형이 바뀌어도 그대로입니다. 부채꼴 [a, b] 안의 담보는 사전 차례로 목표 t = a + (b − a)(i + 1)/(n + 1)(사전 전체 기준, 고정)를 받고, 부채꼴마다 차례를 지키는 1차원 최소제곱 배치(PAVA, 간격 16px, 부채꼴 양끝에서 12px 안쪽)로 간격을 맞춥니다. 반지름 6px입니다.
5. 급부의 목표 방향은 매핑된 표준담보 방향(여럿이면 원형 평균), 특약의 목표 방향은 그 특약의 매핑된 급부 방향의 원형 평균입니다. 그래서 특약이 보장 대분류 부채꼴에 모이고, 뇌혈관과 심장에 걸친 특약은 그 사이의 뇌심장 쪽에 놓입니다. 매핑된 급부가 없는 특약(주계약 포함)은 특약 타원에서 가장 큰 빈 구간에 같은 간격으로 두고 구간 제목을 "표준담보 매핑 대상 외"로 적습니다. 매핑되지 않은 급부는 부모 특약 방향을 씁니다. 특약(반지름 5px)과 급부(반지름 4.5px)는 각 타원에서 차례를 지키며 간격 14px 이상으로 폅니다.
6. 표시 한도: 특약 타원 수용량(둘레/14px, 945x620에서 61개)이나 급부 타원 수용량(107개)을 넘으면 표준담보마다 급부 k개까지(특약 차례, 주급부 먼저 필터를 켜면 `급부역할` 주급부 먼저)만 보이고, k를 두 타원에 들어갈 때까지 1씩 줄입니다(최소 1). 나머지는 표준담보 노드의 "+N" 배지로, 표준담보에 매핑되지 않은 급부는 가운데 상자의 미매핑 급부 수로만 보입니다.
7. 엣지: 종형→특약, 특약→급부(포함), 급부→표준담보(매핑), 표준담보끼리(담보 관계), 특약 부가 조건(기준 특약→대상 특약, 점선 화살표, 지금 우체국 종형 5개에 1건씩). 담보 관계는 2차 베지어 후보 여섯(직선, 왼쪽과 오른쪽으로 엣지 길이의 0.2배와 0.45배 휜 곡선, 꼭짓점을 두 노드 가운데 안쪽 타원보다 0.12 더 안으로 당긴 곡선) 가운데 점수(다른 노드를 지나는 수 x 100 + 교차 수 + 길이 x 0.01)가 가장 낮은 것을 씁니다. 짧은 엣지부터 정하고, 모두 정한 뒤 한 번 더 정하며, 그래프 영역을 벗어나는 후보는 뺍니다. 직각으로 꺾지 않습니다.
8. 가입금액연동: 값이 있는 특약(74개)에 작은 배지를 붙이고 툴팁에 값(스냅샷 문구 그대로)을 보입니다. 값이 없는 특약에 "연동 없음"을 적지 않습니다(공시에 없는지 추출하지 않았는지 확인하지 않았습니다).
9. 필터: 갱신형, 비갱신형(특약 `갱신여부`), 주급부 먼저(`급부역할`), 보장 대분류(특약이 많은 타사 종형용, 한 번에 하나).
10. 직전 개정 대비: 개정 엣지가 들어오는 종형(지금 간편한건강보험 2종, 3종, 4종)에만 토글을 둡니다. 켜면 가운데 상자 아래에 "직전 개정 대비 담보 신설 4, 변경 15, 삭제 4"처럼 개정 엣지 속성을 적고(`종료`는 표시명 삭제), 특약마다 `summary.특약계보[기관코드][특약계보키]`에 직전 종형이 없으면 "직전 개정에 없음" 표지를 붙입니다. 직전 종형에만 있는 특약은 그래프에 그리지 않고 상세 패널에 목록으로 보입니다. 특약 노드는 종형마다 따로 있으므로 계보가 같아도 하나로 통합하지 않습니다.
11. 라벨(13px): 보장 대분류 부채꼴 라벨("암보장 12", 수는 `summary.종형[종형ID].보장분야별`), 그다음 표준담보와 특약 라벨을 바깥 방향을 먼저, 그다음 오른쪽, 왼쪽, 위, 아래, 대각 넷, 같은 아홉 방향으로 8px 더 떨어진 위치(모두 18곳)를 차례로 보고, 다른 라벨, 노드, 상자와 겹치지 않는 첫 위치에 둡니다. 없으면 숨기고 호버로 보입니다. 특약과 급부 라벨은 앞의 "무배당 "을 떼고 16자까지(넘으면 말줄임) 보이고 전체 이름은 호버와 상세 패널에 보입니다.
    - 특약 라벨의 갱신 여부: 요청 35의 7절 5번(관계 탭 특약 노드의 아래 줄이 말줄임으로 잘려 갱신 여부가 안 보임)이 이 요청서로 넘긴 항목입니다. 16자 말줄임은 이름 본문에만 적용하고, 갱신 여부 표기(11절의 갱신형, 비갱신형)는 말줄임 뒤에 따로 붙여 잘리지 않게 합니다(예: `{이름 본문 16자}… (갱신형)`). 값은 특약 노드 속성 `갱신여부`에서 읽습니다. `proto_src/graph/API.md`의 특약 속성에 적힌 값은 `갱신`과 `비갱신` 둘이고, `갱신`은 갱신형, `비갱신`은 비갱신형으로 적습니다(지금 자료는 특약 2,743개 모두 값이 있고 `갱신` 2,002개, `비갱신` 741개). 속성이 비어 있으면 붙이지 않습니다. 호버 툴팁과 상세 패널에는 전체 이름과 갱신 여부를 늘 보입니다.
12. 급부 표지: 매핑 검수 대기 급부는 점선 테두리, 추출 검수 대기 급부는 검수 대기 표지(5.3절과 같은 모양)입니다.
13. 계산 결과: 우체국 간편한건강보험 1종은 노드 97, 엣지 116, 교차 20, 특약 22/22와 급부 49/49(매핑 없는 급부 5 포함)가 모두 보이고 겹침 0입니다(일곱 열로 끝까지 펼치면 교차 1,458). 한화생명 간편가입형(1년)은 특약 45/213, 급부 59/896, "+N" 배지 합 486, 교차 59입니다. 특약이 200개 넘는 타사 종형은 어떤 배치로도 한 화면에 다 넣을 수 없으므로 보장 대분류 필터와 상세 패널 목록으로 봅니다.
14. 담보별 연결과 오갈 때 같은 노드(종형, 표준담보)는 4.9절의 위치 트랜지션으로 옮깁니다.

## 8. 타사가 많을 때와 작은 화면

### 8.1 타사 4개사 이상

1. 보유 조합이 늘어나므로(4개사면 최대 31, 가상 20개사 자료 실제 41~46) 보유 타사 수 구간으로 그룹을 나눕니다. n은 비교 범위의 타사 수, k는 그 담보를 보유한 타사 수, h는 n/2 올림입니다.
   - 우체국 보유: 우체국만(k = 0), 우체국과 타사 소수(1 ≤ k < h), 우체국과 타사 다수(h ≤ k < n), 모두 보유(k = n)
   - 우체국 미보유: 타사 전부(k = n), 타사 다수(h ≤ k < n), 타사 소수(2 ≤ k < h), 타사 1개사만(k = 1)
   - 구간 경계(h = n/2 올림)는 시작값입니다. 이 여덟 구간으로 배치를 계산하지 않았습니다(2번).
   - 그룹 키는 `bin:` 뒤에 구간 이름입니다. 구성원이 없는 구간은 그리지 않습니다. 라벨은 범위를 적습니다(11절. 예: 1행 "타사 10~19개사 보유", 2행 "담보 35개, 우체국 미보유"). 범위가 한 값이면 그 값만 적습니다.
   - 고정 구간(1개사, 2~5개사, 6~14개사, 15개사 이상)을 쓰지 않습니다. 4~6개사에서 대부분이 한 구간에 들고 "모두 보유"와 "타사 전부"를 가르지 못합니다.
2. 배치는 3.5절과 3.6절을 그대로 씁니다. 구간 그룹의 목표점도 구성원 목표점의 평균입니다. 가상 20개사를 고정 구간으로 계산한 결과는 겹침 0, 그룹 분리 최소 1.19, 보유 구분과 x 위치의 어긋남 0이었습니다. 위의 여덟 구간을 이 배치로 계산하지는 않았으므로 PR 글에 측정값을 적어 주세요.
3. 앵커: θ = min(74, 50 + 3(n − 3))도, 20개사면 74도이고 945x620에서 인접 앵커 간격이 최소 32.5px입니다. 라벨은 회사 이름 한 행입니다.
4. 기본 화면 엣지는 기준 종형의 번들 엣지만입니다(20개사 4개, 교차 0). 타사 번들 엣지는 그 타사 앵커를 호버할 때만 그립니다(모두 그리면 86개에 교차 317).
5. 어느 타사가 보유했는지는 위치로 드러나지 않으므로, 표준담보 노드 둘레에 보유 비율 링 차트를 그립니다(반지름 r + 2px, 두께 2px, 바탕 원 `--line-2`, 채운 호 `--ink-0`, 12시부터 시계 방향으로 보유 타사 수 / n. 시작값). 툴팁에는 "타사 20개사 가운데 14개사 보유"처럼 적습니다. 담보를 호버하면 보유 회사 앵커를, 앵커를 호버하면 그 회사의 보유 담보와 번들 엣지를 강조합니다.
6. 비교 범위 필터로 3개사와 4개사를 오가면 그룹 기준이 바뀌어 배치 전체가 바뀝니다. 4.9절의 위치 트랜지션으로 옮기고, 범례에 "그룹 기준이 바뀌었습니다: 타사 4개사 이상은 보유 타사 수 구간으로 나눕니다"를 보입니다.
7. 구간 그룹의 크기가 바뀌면 같은 그룹에 남은 담보도 이동합니다(안 A, 20개사, 기준 종형을 바꿀 때 평균 51px). 이번에는 줄이지 않고 측정값만 적어 주세요.
8. 선택 상태는 4.3절 6번(우체국 종형만 펼치고 타사는 요약 노드)입니다. 20개사에서 요약 노드 20개의 위치는 계산하지 않았으므로 시작값(앵커에서 담보로 가는 선분의 50% 지점)으로 두고 겹침 0을 확인해 주세요.

### 8.2 1280x800과 다른 해상도

- 그래프 영역이 620x480이면 k = 0.713입니다(노드 3.6~7.1px, 앵커 10.7px와 8.6px, 한 종형만 보유한 담보의 목표점 거리 44px, 노드 간격 3px). 계산 결과 겹침 0, 그룹 분리 최소 1.48(간편 1종)과 1.45(통합), 담보 이름 라벨 13px 18/79와 23/73입니다.
- 1600x900, 1366x768도 같은 규칙입니다. 완료 기준은 해상도 넷(1920x1080, 1600x900, 1366x768, 1280x800)에서 봅니다.

### 8.3 1,000px 미만과 380px
