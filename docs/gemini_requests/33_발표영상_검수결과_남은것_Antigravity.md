# 요청 33. 발표 영상(PR 7번) 요청 29 반영분의 검수 결과: 남은 것 (Antigravity 개발 에이전트용)

PR 7번(`presentation_animation/`, Manim 발표 영상)의 가지 `antigravity/presentation-animation`에 올라온 요청 29 반영 커밋(4d5f24d, "요청 29 반영: 발표 영상의 모든 수치와 문구를 facts.json에서 읽도록 수정")을 Claude가 검수했습니다. 요청 29는 영상의 숫자를 사실 자료 `presentation_animation/facts.json`에서 읽게 고치는 일감입니다.

잘된 것이 많습니다. 요청 29의 끝내는 기준에 적은 검사 스크립트(화면 글에 박힌 숫자를 세는 것)를 그대로 돌리니 `숫자가 든 글: 0`이 나왔습니다. 고치기 전에는 219개였습니다. 코드가 읽는 `fact()` 열쇠 114종을 구문 분석으로 모두 뽑아 보니 `facts.json`에 없는 열쇠가 0개, 하위 열쇠를 잘못 짚은 곳이 0곳, 실행 중에 만든 열쇠가 0곳이고, fact 결과의 문자열 첨자 150곳도 모두 값에 있습니다. 요청 29가 지우거나 바꾸라고 한 문구 45개(저장소에 근거가 없던 모델 이름, 출시 이야기, 비율, 낡은 건수 따위)는 영상 글과 README, storyboard 에서 검색해 0건이고, 화면 금지어 18개도 0건입니다. `facts.json`은 `main`과 바이트까지 같고 가지에서 고친 흔적이 없으며, `python scripts/export_presentation_facts.py --check`가 `같음`을 찍었습니다.

아래에 남은 것 8건을 적었습니다. 이것을 고치면 PR 7번을 `main`에 합칩니다.

## Claude가 `main`에서 더한 것 (facts.json)

PR 글의 "필요한 값" 셋 가운데 사본이나 화면 자료에서 그대로 읽을 수 있는 둘을 실었습니다. 영상 코드는 이 열쇠를 읽어 씁니다.

1. `segment_map_grid`: 고객군 지도(전체 지도, 남성 기준, `sales.json`의 `지도.전체`)의 칸마다의 값입니다. 행 12개의 목록이고 차례는 `segment_map_rows`와 같습니다. 행마다 `row`(행 이름)와 `cells`(열 차례는 `segment_map_columns`와 같음)가 있고, 칸마다 `column`(열 이름), `label`(칸의 라벨, `segment_map_labels` 가운데 하나), `sub`(칸의 보조 줄. 닫힌 칸은 "일반심사 확인"), `gate_only`(그 칸의 상대가 우리에게 없는 고지 유형, 곧 관문만 수집한 종형으로만 열렸는지)가 있습니다. 화면 자료의 값을 옮기기만 했고 다시 판정하지 않았습니다. 칸별 값을 센 수가 기존 열쇠(`segment_map_cell_count`, `segment_map_open_together_cells`, `segment_map_ours_closed_cells`, `segment_map_ours_only_open_cells`, `segment_map_gate_only_cells`)와 같은지는 시험(`tests/test_presentation_facts.py`)이 봅니다.
2. `relation_covered_coverages`: 화면이 처음 여는 기준 종형(`default_base_variant`)이 그 담보의 확정 급부도 매핑 대기 급부도 없이, 관계 담보(넓은 담보나 부분 담보)로만 덮는 표준담보입니다. 담보 비교 자료(`proto_src/console4/cover.json`)의 우리 칸에서 읽었습니다. 값은 `count`(지금 13)와 `items`(담보마다 `id`, `name`, `kind`, 덮는 우리 담보 이름 `via`, 부분 담보 가운데 일부만 가졌는지 `partial`)입니다. note가 붙어 있습니다: 이 담보들은 보유 담보 수(`held_coverage_count`)에 들지 않고, 관계 담보로 덮는 것이지 그 담보를 가진 것이 아닙니다. 8장 관계 탐색에서 "관계로 덮는 담보"를 말할 때 이 값을 쓰고 note의 뜻을 함께 적습니다.

싣지 못한 것: 사전 확장 단계마다 새로 더한 담보 이름(PR 글의 필요한 값 2번, 7장 확장 ②). 사본의 표준담보 사전 탭에는 줄을 더한 날이나 몇 번째 확장인지가 없고 화면 자료에도 없어서, 다시 세지 않고는 만들 수 없습니다. 7장 확장 ②의 담보 이름은 지금처럼 "(사전 수록 담보 연결 예시 그림)" 표시를 둔 채로 씁니다.

`facts.json`이 `main`에서 바뀌었으므로 가지를 `origin/main` 위에 올린 뒤에 `--check`를 다시 돌립니다. 요청 29의 끝내는 기준(가지와 `main` 사이에 사실 자료와 만드는 쪽 파일의 차이가 없음)은 올린 뒤에 그대로 지켜집니다.

### 3. 작은 것

4. 값처럼 읽히는데 "예시 그림" 표시가 없는 점과 칸이 셋 남았습니다(직접 확인). 장식으로 그리는 점과 칸은 실제 값이 없으면 수치처럼 보이게 그리지 않는다는 규칙(요청 29 1절의 다섯째 규칙)에 걸립니다.
   - 3장 소식 선별 장면: 구간 안 점은 `n_in_win`(facts 값) 개수지만, 날짜로 떨어지는 점이 5개(`part2_collect_extract.py` 568줄 `range(5)`), 주제로 떨어지는 점이 2개(572줄 `range(2)`)입니다. 같은 장면의 글은 "27건 중 구간 밖 23건 버림, 구간 안 4건"이고, 주제로 버린 건수는 facts 에 없습니다. 날짜 탈락 점을 `first_collect_news`의 `out_of_window` 개수로 그리거나, 점 무리에 "예시 그림"을 적습니다. 주제 탈락 점은 수가 없으므로 "예시 그림"으로 둡니다.
