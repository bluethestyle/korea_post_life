# 요청 34. 발표 애니메이션의 화면 문구를 실무 용어로 교체 (Antigravity 개발 에이전트용)

발표 애니메이션(PR 7번, 브랜치 `antigravity/presentation-animation`)의 화면 문구에 대한 요청입니다. 사용자(보험 실무자)의 지시(2026-11-24)를 그대로 옮깁니다.

> "직역체나 비실무적 용어를 다 보험실무 용어로 대체해야돼. 갈래라는 둥 누를 차례라는 둥 이상한 용어를 너무 많이 써. 앱에서도 그런 용어 다 고칠거야"

애니메이션의 문구에는 Claude가 내부 문서에서 쓰던 조어(판독, 사본, 정본, 관문, 묶음, 조각 등)가 그대로 들어가 있습니다. 원인은 Claude가 쓴 문서와 요청서의 표현이고, 이번에 프로젝트 지침(`CLAUDE.md`의 "용어" 절)을 고쳤습니다. 애니메이션, 앱 화면, 발표 슬라이드가 같은 용어를 쓰도록 맞춥니다.

## 사람이 할 일

Antigravity에 이 한 줄을 넣습니다.

> 브랜치 `antigravity/presentation-animation`에서 `git fetch origin` 뒤 `origin/main`을 머지하고, `docs/gemini_requests/34_발표영상_문구를_실무용어로_Antigravity.md`를 읽어 화면 문구를 수정해 같은 PR에 커밋을 추가하라. `presentation_animation/facts.json`은 수정하지 않는다.

---

## 1. 원칙

1. 화면 문구는 보험 실무 용어와 IT 현장 용어로 씁니다. 지어낸 우리말 조어, 직역체, 내부 문서에서만 쓰던 표현을 쓰지 않습니다. 기준은 `CLAUDE.md`의 "용어" 절과 아래 2절의 교체표입니다.
2. 쉬운 설명과 조어는 다릅니다. 심사위원 가운데 보험이나 AI를 모르는 분이 있어도, 말을 지어내지 않고 통용되는 용어에 짧은 설명을 붙입니다. 예: "인수기준(가입 심사 기준)", "스냅샷(특정 시점의 데이터 복사본)". 설명은 처음 나올 때 한 번만 붙입니다.
3. 한 개념에는 한 용어만 씁니다. 같은 것을 장마다 다르게 부르지 않습니다. 앱 화면과 슬라이드도 같은 용어를 씁니다. 화면 용어의 확정안은 `docs/proposals/용어_대조표.md`에 올라옵니다(작성 중). 올라오면 그 표가 2절보다 우선합니다.
4. 보험 용어는 공시 문서와 약관의 표기를 따릅니다. 예: 상품요약서, 사업방법서, 약관, 주계약, 특약, 담보, 급부, 보험금 지급사유, 면책기간, 감액기간, 보장개시일, 가입한도, 가입연령, 갱신형, 비갱신형, 간편심사, 일반심사, 계약 전 알릴 의무(고지사항).
5. 문장은 짧은 평서문이나 명사형으로 통일합니다. 한 화면 안에서 "~합니다"와 "~함"을 섞지 않습니다. 구어체("~해요", "딱", "쏙")와 과장 표현은 쓰지 않습니다.
6. 요청 29와 요청 33의 규칙은 그대로입니다. 수치는 `facts.json`에서만 읽고, 근거 없는 주장과 성과 과장을 넣지 않습니다. 여러 항목의 나열은 쉼표로 하고, 엠대시를 쓰지 않습니다.

## 3. 구현 방식

- 용어를 장면 코드 곳곳에 문자열로 흩어 두지 말고 `common.py`에 용어 상수(예: `TERM = {"snapshot": "스냅샷", ...}`)를 두고 재사용합니다. 대조표가 확정돼 용어가 바뀌어도 한 곳만 고치면 됩니다.
- 용어가 길어져 레이아웃이 깨지는 곳은 글자 크기를 줄이지 말고 문장을 줄이거나 두 줄로 나눕니다. 기준 해상도에서 겹침과 잘림이 없어야 합니다.
- `storyboard.md`와 `README.md`의 문구도 같은 용어로 고칩니다.

## 4. 수정할 수 있는 파일

- 수정 가능: `presentation_animation/` 아래의 `*.py`, `storyboard.md`, `README.md`.
- 수정 금지: `presentation_animation/facts.json`, `scripts/`, `tests/`, `data/`, `src/`, `docs/`(이 문서 포함), `proto_src/`, `site/`.

## 5. 완료 기준

1. 화면 문구(AST로 추출한 한글 문자열 전체)에서 2절 "지금 표현" 열의 용어가 0건입니다(그대로 두기로 한 예외 제외). 검사 스크립트의 출력을 PR 글에 적습니다.
2. 같은 개념을 두 가지 이상으로 부르는 곳이 없습니다(예: 스냅샷과 사본이 함께 나오지 않음).
3. 수정 전후 문구 목록(파일, 줄, 수정 전, 수정 후)을 PR 글에 표로 첨부하거나 요약합니다.
4. 네 장면이 렌더링되고, 문구가 길어진 장면의 캡처를 장마다 한 장 이상 확인합니다(요청 33의 렌더링 확인과 함께).
5. 요청 29의 검사(화면 문구에 직접 적은 수치 0건, `facts.json` 미수정)가 그대로 통과합니다.
