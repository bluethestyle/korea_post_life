# 요청 17. 공개 화면을 브라우저로 직접 눌러 보는 점검 (Antigravity 브라우저 에이전트용)

Antigravity의 브라우저 에이전트(`/browser`)에 사람이 붙여 넣어 돌리는 점검 지시문입니다. PC의 Antigravity와 크롬이 있어야 합니다(태블릿에서는 안 됩니다). 화면은 공개 주소라 저장소를 받지 않아도 됩니다. 점검이 끝나면 보고 글을 Claude Code 대화에 붙여 넣거나 파일로 전해 주면, Claude가 지적을 직접 확인해 동의한 것만 고칩니다.

아래 줄부터 끝까지를 그대로 붙여 넣습니다.

---

`https://bluethestyle.github.io/korea_post_life/` 를 브라우저로 열어 아래 시나리오를 차례로 실제로 눌러 보고, 본 것을 보고해 주세요. 이 화면은 보험 실무자(영업 지원, 청약 심사, 상품 개발)가 우체국보험 상품을 한화생명, 삼성화재 상품과 견주는 도구입니다. 다른 사이트로 이동하거나 로그인하지 않습니다. 화면에 적힌 금액과 조건이 맞는지는 판단하지 않습니다(자료 검증은 따로 합니다). 볼 것은 쓰기 쉬운지, 읽기 쉬운지, 깨지는 곳이 있는지입니다.

## 점검 조건

- 창 너비 1280px에서 한 번, 가능하면 380px(휴대폰 너비)에서 한 번 더 합니다.
- 단계마다 화면 사진을 남기고, 눌렀는데 반응이 없거나 늦은 곳, 글자가 잘리거나 겹치는 곳, 무엇을 눌러야 할지 알기 어려운 곳을 적습니다.
- 브라우저 콘솔에 오류가 나오면 그 글을 그대로 적습니다.

## 시나리오 1: 영업 지원 (고객 문의에 답하기)

1. 화면 위쪽의 나이에 60을 넣고 성별을 남으로 둡니다.
2. "3 담보 비교표" 탭을 엽니다. 기준 상품이 우체국간편한건강보험이고 기준 종형이 2종(간편가입325)인지 봅니다. 아니면 그렇게 고릅니다.
3. 비교 종형으로 한화생명과 삼성화재가 하나씩 체크되어 있는지 봅니다. 표 머리의 판정 요약(나음, 못함, 빈자리 수)을 읽습니다.
4. "암 수술비" 줄에서 삼성화재 칸을 눌러 근거(원문 특약명, 문서, 쪽)가 열리는지 봅니다. 닫습니다.
5. "표 모두 보기"를 눌러 펼치고, 다시 접습니다.
6. "응대 카드" 단추를 눌러 미리 보기를 열고, A4 한 장에 들어가는지 봅니다. 닫습니다.
- 물음: 이 고객에게 우체국 상품이 나은 점과 못한 점을 1분 안에 말할 수 있었습니까? 어디서 막혔습니까?

## 시나리오 2: 청약 심사 (가입할 수 있는지 보기)

1. "2 가입 적격·간편심사 관문" 탭을 엽니다. 나이를 68로 바꿉니다.
2. 종형마다 나이 막대와 "가입 가능" 표시가 바뀌는지 봅니다. 회사 거르기 단추를 하나씩 눌러 봅니다.
3. 아래의 간편심사 고지 관문 표에서 세 회사의 고지 질문 차이를 읽습니다.
4. "4 특약 조합별 지급액" 탭을 엽니다. 회사와 종형을 하나 고르고, 특약 두세 개를 체크하고, "최대로 담기"를 누릅니다.
5. 결과 막대와 표가 바뀌는지, "모두 보기"로 펼쳐지는지 봅니다.
- 물음: 68세 고객이 가입할 수 있는 종형을 바로 알 수 있었습니까? 삼성화재 종형에서 무엇이 보이고 무엇이 비어 있습니까?

## 시나리오 3: 상품 개발 (경쟁 구도 보기)

1. "1 이번 주 달라진 점" 탭에서 시장 소식을 다음 쪽으로 넘겨 봅니다.
2. "3 담보 비교표" 탭에서 보장 분야를 암보장, 뇌혈관보장, 심장보장, 공통보장, 전체로 바꿔 봅니다. 찾기 칸에 "수술"을 넣어 봅니다.
3. 비교 종형 체크를 더하고 빼 봅니다. 종형을 넷 이상 켰을 때 표가 읽히는지 봅니다.
4. "5 개정 전후 비교" 탭에서 비교할 종형 쌍을 바꿔 봅니다.
5. "6 AI 작업 내역" 탭에서 단계와 결과 거르기, 찾기, 쪽 넘기기를 해 봅니다.
- 물음: 우체국에 없고 두 민영사에 모두 있는 담보가 무엇인지 찾을 수 있었습니까? 몇 번 눌렀습니까?

## 보고 형식 (마크다운)

1. 요약: 직관성과 가독성을 1~5점으로 매기고 이유를 세 줄씩.
2. 시나리오별 결과: 단계마다 "됨, 안 됨, 헷갈림"과 본 것 한 줄, 누른 횟수, 물음에 대한 답.
3. 문제 목록: 심한 것부터 열다섯 개 이내. 문제마다 어느 탭의 어느 자리인지, 무엇이 일어났는지, 창 너비, 사진 이름.
4. 반응 속도: 탭 전환과 나이 변경 뒤 화면이 바뀌는 데 걸린 시간의 느낌(바로, 조금 늦음, 늦음)과 가장 늦은 곳.
5. 실무자가 처음 열었을 때 가장 먼저 헷갈릴 것 다섯 가지.

추측은 추측이라고 적고, 직접 눌러 본 것만 "됨, 안 됨"으로 적습니다.
