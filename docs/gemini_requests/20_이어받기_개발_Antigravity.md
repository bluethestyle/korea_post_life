# 요청 20. Antigravity가 이어받아 개발할 일 (2026-11-20 밤 기준)

Claude Code의 주간 한도가 차면 Antigravity의 에이전트가 이어받을 수 있는 일을 골라 적은 지시문입니다. 화면에 보이고, 브라우저로 스스로 확인할 수 있고, 시트와 추출 배치를 건드리지 않는 일만 넣었습니다. 최종 검수는 Claude가 합니다. 그래서 `main`에 바로 올리지 않고 가지에 커밋해 두면, 한도가 풀린 뒤 Claude가 검수해 합칩니다.

## 사람이 먼저 할 일

- Antigravity에서 이 저장소 폴더(WSL의 `/data/projects/post_life`)를 그대로 엽니다. GitHub에서 새로 받으면 안 됩니다. 시안의 원본과 글꼴이 git 제외 폴더(`local/`)에 있고, 합치는 스크립트가 이 경로를 씁니다.
- 아래 "붙여 넣을 지시문"의 가로줄 아래부터 끝까지를 에이전트에 붙여 넣습니다. 일은 1번부터 차례로 하나씩 맡기는 편이 좋습니다(지시문 끝의 "이번에 할 일" 줄만 바꿉니다).

## 지금 Claude 쪽에서 돌고 있는 것 (건드리면 안 되는 범위)

- 시안 4(`site/proto/console4.html`)를 만드는 작업이 진행 중입니다. 탭 넷을 채우는 단계이고, 끝나면 점검과 보완 단계가 이어집니다. 이 작업이 끝났는지는 사용자가 Claude Code 대화에서 확인해 알려 줍니다. 끝나기 전에는 아래 2번을 시작하지 않습니다.
- 종형 표의 열 둘 추가, 일반심사 규칙 변경, 영업 인사이트 문장 수정이 한 묶음으로 진행 중입니다. 그래서 아래 "고치면 안 되는 파일"은 손대지 않습니다.

---

이 저장소는 우체국보험 상품과 청약 판단 지원 앱입니다(공모전 제출용, 공개 저장소). 먼저 `CLAUDE.md`, `docs/handoff.md`, `docs/progress.md`의 맨 위 절(가장 나중에 쓴 절이 `### 스타일 합의안 확정, 시안 4 제작 중, …` 근처에 있습니다)을 읽고 시작하세요. 이용자는 보험사 본부의 영업 기획과 분석 담당자입니다.

## 반드시 지킬 것

1. 공개 저장소입니다. API 키, 서비스 계정 키, 스프레드시트 ID, 사람 이름, PC의 폴더 경로를 파일, 커밋, 문서 어디에도 쓰지 않습니다.
2. `local/` 아래 파일은 커밋하지 않습니다(`git add -f` 금지). 공시 문서 원문을 리포나 시험 자료에 옮기지 않습니다.
3. 고치면 안 되는 파일(다른 작업이 고치는 중이거나 사용자 승인이 필요한 것): `src/postlife/site/sales.py`, `src/postlife/site/insights.py`, `src/postlife/extract/` 전체, `src/postlife/schema.py`, `src/postlife/validate.py`, `src/postlife/ids.py`, `data/targets/`, `data/snapshot/`, `data/seed/`, `docs/planning.md`, `docs/limitations.md`, `docs/proposals/`, `.github/workflows/`, `scripts/add_column.py`, `site/index.html`.
4. 시트에 쓰는 일, GitHub Actions 실행, Gemini API 호출을 하지 않습니다.
5. `main`에 커밋하거나 푸시하지 않습니다. `antigravity/<주제>` 가지를 만들어 커밋만 해 둡니다. 커밋 글은 한국어로 무엇을 왜 바꿨는지 적습니다.
6. 화면은 외부 요청이 없는 단독 HTML 한 파일이어야 합니다. 스크립트, 글꼴, 그림을 바깥 주소에서 불러오지 않습니다. 시안에는 `noindex` 메타 태그와 맨 위 고지 "공모전 시연용 화면이며 영업 자료가 아닙니다"가 있어야 합니다.
7. 숫자와 판정, 문장을 화면에서 지어내지 않습니다. 자료(`sales.json`, `data/snapshot/`)에서 읽은 값만 씁니다. 우열을 단정하는 말과 금지어(업계, 유일, 독점, 최초, 최고, 가장, 유리, 우수, 저렴, 추천 따위)를 쓰지 않습니다.
8. 한국어 문장: 번역투를 쓰지 않고, 나열은 쉼표로 하며(가운뎃점으로 잇지 않음), 엠대시를 쓰지 않습니다. 버전을 뜻하는 "판"과 "판올림"을 쓰지 않습니다.
9. 커밋 전에 전체 시험을 돌리고 통과 수를 그대로 적습니다: `.venv/bin/python -m pytest -q` (기준 967개 통과). 출력을 `head`나 `tail`로 가리지 않습니다.
10. 한 일, 확인한 방법, 확인하지 못한 것을 `docs/progress.md` 맨 위 절 바로 위에 새 절로 적습니다(절 제목에 날짜와 "Antigravity"를 넣습니다).

## 할 일 (차례대로, 하나씩)

### 1. 화면 흐름도 고치기 (`site/proto/flow.html`)

- 원본: `local/postlife_local_assets/proto_src/flow/flow.tpl.html`. 합치기: `.venv/bin/python -I local/postlife_local_assets/proto_src/flow/build.py` (결과가 `site/proto/flow.html`).
- 브라우저 점검(요청 19의 보고, 2026-11-20)에서 나온 것을 고칩니다. 고치기 전에 하나씩 직접 재현하고, 재현되는 것만 고칩니다.
  1. 장면 1과 장면 2에서 조건 줄로 되돌아가는 걸음 때문에 번호 고리의 순서가 뒤섞이고 가로 선 세 줄이 겹쳐 보입니다. 되돌아가는 선은 다른 높이와 모양(점선)으로 그려 겹치지 않게 합니다.
  2. 세 장면의 길이 같은 색이라 고리 모양으로만 구별됩니다. 장면마다 선의 모양(실선, 긴 점선, 짧은 점선)을 달리하고 범례에 장면 이름을 적습니다. 색을 늘리지는 않습니다.
  3. 380px에서 걸음을 눌러도 해당 탭 카드로 화면이 옮겨 가지 않습니다. 걸음을 누르면 그 카드가 보이게 옮기고, 카드 사이에 아래 방향 화살표를 둡니다.
  4. 380px의 아래 고정 걸음 막대가 흐름도 구역을 벗어난 뒤에도 남아 글을 가립니다. 흐름도 구역이 화면에 보일 때만 나오게 합니다.
  5. 브리핑 와이어프레임의 "자세히 > 탭 N"과 "기준 종형", "비교 상대"가 누를 수 있는 것처럼 보입니다. 눌리지 않는 모형이라는 것이 보이게 화살표와 단추 테두리를 뺍니다.
  6. "간편 1종 값으로"를 눌러도 (나) 줄의 첫 칸이 "구현이 정한 셈법의 값"으로 남습니다. 아래 "새 숫자"의 값으로 채웁니다.
  7. "된다", "일부", "안 된다" 표시가 테두리 모양으로만 갈립니다. 기호와 면으로 구별되게 합니다(예: 된다는 짙은 면, 일부는 반만 채운 면, 안 된다는 빗금). 색을 늘리지는 않습니다.
  8. "탭마다 영역" 표의 긴 칸(고객군과 시장, 영업 인사이트)을 위와 아래로 나눠 줄을 바꿉니다.
  9. 380px에서 맨 위 "사용자 원칙" 단추의 이동 대상 이름이 숨겨집니다. 이름이 보이게 합니다.
- 예시 숫자를 새 값으로 바꿉니다(2026-11-20 밤에 한화생명 간편가입형 네 유형을 적재한 뒤의 값). 새 숫자: 고객군 36칸 가운데 우리 간편만 열림 0칸, 함께 열림 22칸, 우리 간편 닫힘 14칸, 간편 모두 닫힘 0칸. 우리 간편 닫힘 14칸 가운데 6칸은 상대가 한화생명 간편가입형(0년)으로만 열립니다. 개정으로 달라진 담보는 23건(신설 4, 변경 15, 종료 4), 시장 소식은 9건입니다. 흐름도 안의 "우리 간편만 열림 2칸" 글을 모두 찾아 바꿉니다.
- 끝내는 기준: 1920x1080, 1280x800, 380x780에서 콘솔 오류 0건, 외부 요청 0건, 가로 넘침 0건. 장면 셋의 걸음을 끝까지 눌러 글과 그림이 맞는지 봅니다. 고치기 전과 뒤의 사진을 남깁니다(사진은 커밋하지 않습니다).

### 2. 시안 4를 눌러 보고 고치기 (`site/proto/console4.html`)

Claude 쪽의 시안 4 작업이 끝났다는 말을 들은 뒤에 시작합니다.

- 원본: `local/postlife_local_assets/proto_src/console4/` (규약은 그 폴더의 `API.md`). 합치기: `.venv/bin/python -I local/postlife_local_assets/proto_src/console4/build.py`. 사진과 잰 값: 같은 폴더의 `shoot.py`.
- 먼저 자료를 새로 뜹니다(적재 뒤의 사본으로): `.venv/bin/python scripts/dev/export_sales.py --snapshot data/snapshot --out local/postlife_local_assets/proto_src/console4/sales.json`. 그다음 다시 합칩니다. 브리핑 첫 줄이 "우리 간편만 열리는 곳은 없고, 함께 열리는 곳은 22칸, …"으로 나와야 합니다.
- 기준 화면은 1920x1080입니다. 1600x900, 1280x800(하한), 380x780도 봅니다. 탭 다섯(브리핑, 고객군과 시장, 가입 관문, 담보 비교, 영업 인사이트)을 차례로 열어 조건 줄을 바꾸고, 지도의 칸과 목록의 행을 눌러 근거 기둥(좁은 화면에서는 올라오는 판)을 봅니다.
- 스타일의 기준은 어쌔신 크리드 신디케이트의 메뉴 화면이고, 확정한 규칙은 `docs/progress.md`의 "스타일 합의안" 항목에 있습니다. 요지: 안개 회색 바탕, 거의 흰 면은 화면의 10% 안쪽, 빨강은 고른 것과 눈금과 원문 확인 표식에만(판정에 쓰지 않음), "우체국 나음"은 금색 면 칩과 ▲, "우체국에만 있음"은 마름모와 옅은 금빛 면, "우체국 못함"은 화면에서 하나뿐인 짙은 면 칩과 ▼, 모서리 반경 0, 한글 SUIT와 숫자 Saira Semi Condensed. 이 규칙을 바꾸지 않습니다. 화면의 구성(탭 다섯과 순서, 조건 줄, 범위 띠, 근거 기둥)도 바꾸지 않습니다.
- 고칠 것: 눌러도 반응이 없는 곳, 잘리거나 겹치는 글자, 가로 넘침, 본문과 근거 기둥의 판정이 다른 곳, 종형 ID 같은 내부 값이 그대로 찍힌 곳, 지도 칸에서 상대가 관문만 수집한 종형(한화생명 간편가입형(0년))으로만 열린 칸에 그 표시가 없는 곳.
- 더할 것 하나: 처음 보는 사람이 뜻을 알기 어려운 말 다섯(범위 띠, 관계와 근거 패널, 기준 종형과 선택 종형, 치료 여정 격자, 단정 주의와 검토 대기)에 짧은 풀이를 답니다. 이름 옆 작은 물음표를 누르면 한두 문장이 나오는 꼴로, 화면을 가리지 않게 합니다.
- 끝내는 기준: 네 가지 창 크기에서 콘솔 오류 0건, 외부 요청 0건, 가로 넘침 0건. `build.py`의 검사 통과. 고친 곳마다 전후 사진.
