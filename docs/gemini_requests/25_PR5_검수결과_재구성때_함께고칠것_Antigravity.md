# 요청 25. PR 5번 검수에서 나온 것: 재구성(요청 24)하면서 함께 고칠 것 (Antigravity 개발 에이전트용)

따로 맡기는 일감이 아니라 요청 24의 1단계에 딸린 목록입니다. PR 5번은 2026-11-23에 `main`에 합쳐졌습니다. 원본에서 다시 합친 화면이 커밋된 화면과 바이트까지 같고, 자료 파일을 손대지 않았고, 전체 시험이 통과했고, 메달 다섯의 수가 기준 종형 다섯과 성별 둘에서 자료와 같았습니다. 아래는 동작 점검에서 나온 것입니다.

## 사람이 할 일

Antigravity에 이 한 줄을 넣습니다.

> GitHub의 `main`이 바뀌었다. `git fetch origin` 뒤 작업 가지를 `origin/main` 위에 올리고, `docs/gemini_requests/25_PR5_검수결과_재구성때_함께고칠것_Antigravity.md`를 읽어 요청 24의 1단계에서 함께 고쳐라. `site/proto/console4.html`이 충돌하면 손으로 합치지 말고 `python proto_src/console4/build.py`로 다시 만든다.

## Claude가 `main`에서 이미 고친 것 (다시 고치지 않습니다. 가지를 `origin/main` 위에 올리면 들어옵니다)

두 곳은 공개된 화면에 틀린 글이 나와서 바로 고쳤습니다. 가지에서 같은 줄을 고쳤다면 `main`의 것을 따릅니다.

1. `core.js`의 `limitOf`: `g.age <= g.hi`는 오타였고 `s.age <= g.hi`가 맞습니다. 이 오타 때문에 어느 나이에서나 주계약 한도가 "가입나이 밖"으로 나왔습니다(50세 남성인데 "50세는 가입나이(20~80세) 밖"). 고친 뒤 20~65세 4,000만원, 66~80세 2,000만원으로 나오는 것을 확인했습니다.
2. `tab3.js`, `tab5.js`: 조건의 짧은 글을 `App.condSummary().split(', 기준')[0]`으로 얻고 있었는데, `condSummary`의 꼴이 "50세 남성, 이력 없음 / 기준 … / 상대 …"로 바뀌면서 잘리지 않아 긴 요약이 문장 안에 통째로 끼었습니다("지금 조건에서 열리는 종형 50세 남성, 이력 없음 / 기준 1종(간편가입315) / 상대 한화생명, 삼성화재에서 …"). `App.condSegOnly()`로 바꿨습니다.

공통 함수의 꼴을 바꿀 때는 그 함수를 쓰는 곳을 `grep`으로 모두 찾아 함께 확인해 주세요. 이번 두 건은 모두 `core.js`를 고치면서 다른 탭의 글이 틀어진 것입니다.

## 재구성하면서 고칠 것

괄호 안은 점검 때 잰 값입니다. "직접 재현"이라고 적은 것은 Claude가 다시 돌려 확인한 것이고, 나머지는 점검 에이전트가 잰 값입니다.

### 비교 범위

1. 비교 범위를 좁혀도 수와 문장이 그대로인데 "전체 기준"이라는 표시가 없습니다(직접 재현). 범위를 "생명보험만"으로 바꾸면 위 줄은 "상대 한화생명"이 되지만 메달 다섯은 그대로이고, 근거 문장은 삼성화재를 그대로 말합니다. 상대를 하나도 고르지 않아도 관문 차이는 "2"입니다. 이제 자료에 기관코드 목록이 들어갔으니(요청 24의 "자료에 더해진 값") 수는 고른 범위와 겹치는 것만 세고, 자료의 문장처럼 범위로 다시 만들 수 없는 것에는 "전체 기준"을 붙입니다.
2. 비교 범위가 다른 탭에 반영되지 않습니다(직접 확인: `tab2.js`~`tab5.js`에 범위를 읽는 코드가 없습니다). "생명보험만"을 골라도 본문에 삼성화재가 남습니다(고객군과 시장 2곳, 가입 관문 6곳, 담보 비교 22곳, 영업 인사이트 91곳). 조건을 펼친 패널의 "비교 상대" 줄도 범위와 무관하게 두 회사를 적습니다.
3. 가상 열아홉 회사 자료에서 비교 범위 선택기가 240px 높이의 안쪽 스크롤에 갇혀 13곳만 보입니다. 아래에 빈 면이 430px 있습니다.

### 층과 근거

4. 브리핑의 셋째 메달(가입 관문과 한도)의 수는 "관문 차이 2곳"인데, 고르면 열리는 판은 "회사별 열린 종형 수"(3, 6, 5)를 보입니다(직접 재현). 메달의 수가 판 어디에도 없습니다. 고리 탭의 수와 그 화면이 보이는 것이 같은 값이어야 합니다. 고리의 채움 비율을 그리려고 화면이 종형 수를 스스로 세는 곳(`tab1.js`의 회사별 종형 수, 분류 합)은 자료의 값으로 바꿉니다.
5. 근거 영역이 256px에서 잘리는데 더 있다는 표시가 없습니다(직접 확인). 제목 한 줄이 경계에 걸려 반만 보이고, 그 아래 화면은 570px가 비어 있습니다. 글자 수 측정은 보이는 부분만 세어 한도를 통과하지만 전체 글은 넷째 메달에서 962자입니다. 요청 24에서 근거가 판의 오른쪽 구역으로 들어가면 구역 높이를 다 쓰고, 넘치면 넘친다는 표시를 둡니다.
6. 다른 탭의 처음 화면에서 읽는 법과 설명이 사라졌습니다. 가입 관문의 "관문 나무 읽는 법", 고객군과 시장의 "회사별 관문과 열린 종형", 담보 비교의 "무엇을 견주나", 영업 인사이트의 "다섯 분류는 서로 겹치지 않습니다" 따위입니다. 범례 단추는 브리핑에만 있습니다. "정보를 지우지 않는다"는 규칙에 걸립니다. 새 뼈대에서 범례 단추로 옮기되, PR 글의 "어느 구역으로 갔는지" 표에 넣어 주세요.
7. 개정 짝의 합을 설명하던 글이 줄었습니다(직접 확인). 앞에는 "같은 담보가 여러 짝에서 바뀌어 짝마다 세므로 23건보다 큽니다"였고 지금은 "(중복 포함)"뿐입니다. 63건과 23개가 왜 다른지 읽는 사람이 알 수 없습니다. 이유를 되살립니다.

### 좁은 화면과 키보드

8. 380x780에서 메달을 누르면 아래에서 올라오는 근거 판이 화면의 y 296~780을 차지해 2층 판(y 388~723)을 모두 덮습니다. 근거 판을 닫으면 선택이 풀려 1층으로 돌아가서, 2층 판만 볼 방법이 없습니다.
9. 키보드로 메달을 골라 2층을 열거나 닫으면 포커스가 `body`로 빠집니다. 페이지 첫 Tab에서 첫 메달까지 14번을 눌러야 합니다. 요청 24의 "화살표로 구역 안을 옮기고 Tab으로 구역을 넘어간다"를 만들 때 포커스를 고른 것으로 되돌려 주세요.
