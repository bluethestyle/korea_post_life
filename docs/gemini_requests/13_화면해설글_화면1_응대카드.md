# 질문: 판단 화면의 해설 글 초안, 화면 1 구성 검토, 응대 카드 구성

우체국보험 상품·청약 판단 지원 앱(공모전 제출용)의 화면 작업이다. 오프라인 단독 HTML 하나(`site/index.html`)이고, 자료 가공은 Python(`src/postlife/site/*.py`)이 빌드할 때 끝내고 화면(`assets/app.js`)은 그리기만 한다. 구현은 Claude가 하고, 너는 아래 세 가지를 맡는다. 답은 짧고 기계로 뽑아 쓸 수 있는 꼴이어야 한다(전체 220줄 이내).

## 읽을 파일 (리포 루트 기준)

- `src/postlife/site/assets/app.js`: 화면 1은 417~451줄, 화면 2는 452~599줄, 화면 3은 600~940줄, 화면 4는 941~1176줄, 화면 5는 1177~1312줄, 화면 6은 1313~1430줄
- `data/snapshot/hum_기준값.jsonl` (대표 조건 `REP_WEEKLY_*`, 응대 카드 표식 `TEXT_CARD_BANNER`)

## 배경

- 지금 자료: 우체국 종형 8개(통합건강보험 2504, 간편한건강보험 2606의 네 종, 직전 개정판 세 종), 한화생명 종형 4개. 삼성화재는 아직 없다. 보험료 자료와 질병코드 자료는 없다.
- 화면 1은 지금 건수만 적은 자리다. 화면마다 해설 글은 아직 없다. 응대 카드도 없다.
- 모델 호출은 지금 못 쓴다. 그래서 해설 글은 미리 써 둔 문장 틀에 화면이 자료 값을 끼워 넣는 방식으로 만든다.

## 맡길 일 1: 화면별 해설 글 틀

기획 3.4대로 화면마다 다섯 항목을 쓴다: 결론 한 줄, 읽는 법, 이유 설명, 실무 유의점, 출처.

규칙
- 글 속에 숫자를 직접 쓰지 않는다. 숫자와 자료에 따라 바뀌는 이름(상품명, 종형명, 회사명, 날짜)은 모두 `{변수이름}` 자리로 둔다. 변수 밖에 아라비아 숫자가 하나라도 있으면 코드가 그 글을 버린다. "화면 3" 같은 말도 숫자 없이 "담보 비교표"처럼 화면 이름으로 쓴다.
- 변수는 `build.py`의 payload에 이미 있는 값이거나 거기서 바로 셀 수 있는 값만 쓴다. 화면마다 변수는 8개 이내.
- 화면 3(담보 비교표)의 결론과 이유는 우위, 대등, 열위 세 벌을 쓴다. 고른 기준 종형(우체국)과 비교 종형 한 쌍의 판정 집계(`compare.py`가 만드는 나음, 같음, 못함, 엇갈림 수)로 어느 벌을 보여 줄지 고르는 규칙도 한 줄로 제안한다. 방향(누가 나은 것인지)은 `compare.py`의 `verdict`를 읽고 맞춘다.
- 자료가 비어 변수 값이 없는 경우(예: 이번 주 소식 0건, 비교 종형 없음)에 보여 줄 대체 문장이 필요한 항목은 `"없을때"`로 함께 쓴다.
- 문장은 항목마다 한두 문장. 한국어 실무 말투, 번역투 금지("~됨" 식 압축, 직역 용어), 나열은 가운뎃점이 아니라 쉼표, 엠대시 금지, "최초", "유일" 같은 확인 못 할 표현 금지. 병력으로 인수 가부를 단정하는 말 금지(기획 3.1).
- 출처 항목은 자료의 출처 종류를 적는다(공시 문서 종류, 수집 경로). 주소는 적지 않는다.

답의 꼴: JSON 코드 블록 하나. 최상위 키는 `s1`~`s6`, 각 값은 `{"결론": "...", "읽는법": "...", "이유": "...", "유의점": "...", "출처": "...", "없을때": {"결론": "..."}}`. `s3`만 `"결론"`과 `"이유"`가 `{"우위": "...", "대등": "...", "열위": "..."}`이다.

그 뒤에 변수 표 하나: `| 화면 | 변수 | 뜻 | 계산 근거(모듈과 키, 또는 세는 방법) |`.

## 맡길 일 2: 화면 1 구성 검토

내 계획은 이렇다. 빠진 것, 틀린 것만 10줄 이내로 지적한다(동의하는 항목은 적지 않는다).

1. 맨 위에 코드가 채운 요약 한 줄(해설 글의 결론 틀). 모델이 쓰는 주간 요약 문장은 나중에 붙이고, 지금은 "코드가 집계한 요약"이라고 표시한다.
2. 카드 묶음 셋(기획 8장의 세 가지):
   - 이번 주에 등록되거나 판매가 끝난 개정판: 자료 기준 시각이 속한 ISO 주에 적용시작일이나 판매종료일이 든 종형. 없으면 "이번 주에는 없음"과 가장 최근 개정 한 건.
   - 이번 주차의 시장 소식: 수집주차가 이번 주이고 선별 확률이 통과 기준 이상인 소식을 카드로(기관, 분류, 발표일, 핵심 요약, 매체, 출처 주소는 글자로).
   - 대표 조건에서 우열 표시가 바뀐 표준담보: 지난주 사본과 견줘야 하는데 지난주 사본이 아직 없다. 빌드에 지난주 사본 폴더를 넘기는 인자를 만들고, 없으면 "지난주 사본이 없어 이번 주는 비교하지 않음"으로 적는다.
3. 지금 있는 "들어 있는 자료", "아직 없는 자료" 묶음은 아래로 내려 접어 둔다.

## 맡길 일 3: 응대 카드 구성

기획 3.5: A4 한 장으로 인쇄, 상단에 "내부 교육·비교 참고용(대외 배포 금지)" 표식 고정. 창구 직원과 FC에게 전달하는 한 장이다. 화면에서 "응대 카드 인쇄" 단추를 누르면 브라우저 인쇄로 PDF를 만든다.

- 어느 화면의 어떤 선택 상태에서 카드를 만들지, 카드에 들어갈 묶음(위에서 아래로), 묶음마다 넣을 값과 최대 줄 수를 20줄 이내의 목록으로 제안한다. A4 한 장을 넘지 않게 줄 수 상한을 정한다.
- 보험료와 질병코드 자료가 없다는 점, 한화생명은 특약 가입 한도 자료가 없다는 점을 반영한다.
- 카드에 고정으로 들어갈 안내 문구(예: 인수 여부는 심사 결과에 따른다는 말)는 숫자 없이 문장으로 적어 준다.

## 답의 순서

`## 1. 해설 글` (JSON 블록, 변수 표, 화면 3 고르는 규칙 한 줄) → `## 2. 화면 1 지적` → `## 3. 응대 카드`. 자료나 코드에서 확인하지 못한 것은 지어내지 말고 "확인 필요"라고 적는다.
