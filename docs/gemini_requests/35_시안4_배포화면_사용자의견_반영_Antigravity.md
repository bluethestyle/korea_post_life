## 0. Claude가 main에서 이미 고친 것

- 사용자의 말: "고객군과 시장 화면에서 수직 스크롤이 안 먹는 영역이 있는데?"
- 원인은 `.z-left`, `.z-center`, `.ev-body`의 `overscroll-behavior:contain`이었습니다. 안에 스크롤할 내용이 없어도 휠 스크롤이 페이지로 넘어가지 않았습니다. 세 곳에서 제거했습니다(커밋 `ea7d6b3`, `proto_src/console4/style.css`). 이 속성을 다시 넣지 않습니다.

## 1. 페이지 구조: 데스크톱에서는 페이지가 스크롤되지 않고, 제목 줄과 탭 줄은 제자리

**사용자의 말**: "분류를 눌렀을 때 해당 위치로 스크롤이 이동하면서 최상단 메뉴도 같이 스크롤이 내려가는 방식인데 최상단 메뉴는 놔두는게 좋지 않을까?"

**지금 상태**

| 해상도 | 문서 높이 | 페이지 스크롤 | 영업 인사이트에서 목차 클릭 뒤 |
| --- | --- | --- | --- |
| 1920x1080 | 1,149px(담보 비교에서 상세 패널을 열면 1,205px) | 69px(125px) | `window.scrollY` 69, 탭 줄 y 126 → 57 |
| 1366x768 | 973px | 205px | 탭 줄이 화면 밖으로 나감 |

목차를 클릭하면 가운데 영역(`#z-center`, 내용 높이 6,146px)이 스크롤되는 것과 함께 페이지도 끝까지 내려갑니다.

**바꿀 내용**

1. 가로 1280px 이상에서는 문서 높이를 화면 높이에 맞춥니다. 상단 안내 바, 제목 줄, 탭 줄은 늘 제자리에 있고, 그 아래 영역이 남은 높이를 나눠 쓰며 안쪽에서만 스크롤됩니다.
2. 하단 고지문(`#foot`, 높이 124px)을 정리합니다. 글꼴 라이선스 문단은 도움말(`?`) 창으로 옮깁니다. "공모전 시연용 화면이며 영업 자료가 아닙니다"는 상단 안내 바에 이미 있습니다. 나머지 고지 문장과 자료 기준 시각은 화면에서 늘 보이는 한 줄(높이 24px 이하)로 둡니다(상단 안내 바의 오른쪽 또는 화면 맨 아래 고정 줄). 자료 기준 시각은 사라지면 안 됩니다.
3. 목차나 분류를 클릭했을 때는 해당 스크롤 영역만 움직입니다(`scrollIntoView` 대신 그 영역의 `scrollTo`).
4. 380px 폭의 좁은 화면은 지금처럼 페이지 스크롤을 씁니다.

요청 32의 3-1이 영업 인사이트에 정한 머지 조건(문서 높이가 머지 전과 같음, 조작 줄이 첫 화면 안에 있음, 구역 이동 목록을 되살리거나 가운데 위 바로가기 줄이 대신함)은 이번 1절, 2절, 6절로 바뀝니다. 문서 높이는 화면 높이에 맞추고(1절), 조작 버튼은 제목 줄로 옮기고(2절), 가운데의 이동 버튼은 없애고 왼쪽 목차만 둡니다(6절 2번).

**완료 기준**

- 전체 요약과 다섯 탭, 해상도 넷(1920x1080, 1600x900, 1366x768, 1280x800), 상세 패널을 열기 전과 뒤 모두에서 `document.documentElement.scrollHeight === innerHeight`.
- 영업 인사이트의 목차 다섯 항목을 차례로 클릭했을 때 `window.scrollY`가 0이고 탭 줄(`#rtabs`)의 y가 변하지 않으며, 가운데 영역의 `scrollTop`만 변합니다.
- 어느 탭에서도 내용이 잘려 닿을 수 없는 곳이 없습니다(각 스크롤 영역의 끝까지 휠과 키보드로 이동).

## 2. 버튼 줄을 상단으로

**사용자의 말**: "그리고 뒤로, 표로보기 등 버튼들이 상단에 배치해야되지 않나?"

**지금 상태**: 하단 버튼 줄(`#actbar`, 높이 39px에 위 간격 10px)의 윗변은 1920x1080에서 y 916(영업 인사이트와 관계 지도는 926)이고, 담보 비교에서 상세 패널을 열면 y 982로 내려갑니다. 1600x900 이하에서는 상세 패널을 열기 전에도 화면 아래에 걸치거나 화면 밖에 있습니다(1366x768 가입 관문은 y 768.9). 탭 이름 "가입 관문"과 "관계 지도"는 지금 화면의 이름입니다(확정 이름은 9절). 380x780에서는 버튼이 고객군과 시장, 담보 비교에서 세 행(높이 111px), 나머지 화면에서 두 행(75px)으로 쌓입니다. 탭별 위치와 문서 높이, 이 줄을 없앨 때 문서 높이가 줄어드는 양(해상도와 탭에 따라 0~121px)은 부록 5.2절과 5.3절에 있습니다.

| 화면 | 왼쪽 버튼 그룹의 버튼 | 폭 |
| --- | --- | --- |
| 전체 요약 | 문장으로 보기(`home-text-btn`), 요약 복사(`act-copy`), 범례 | 272px |
| 고객군과 시장 | 뒤로(`act-back`), 표로 보기(`mk-btn-tally`), 개정과 시장(`mk-btn-rev`), 요약 복사, 범례 | 386px |
| 가입 관문 | 뒤로, 표로 보기(`gt-btn-tbl`), 요약 복사, 범례 | 300px |
| 담보 비교 | 뒤로, 표로 보기(`cv-btn-tbl`), 비교표 복사(`data-act=cv-copy-table`), 요약 복사, 범례 | 406px |
| 영업 인사이트, 관계 지도 | 뒤로, 요약 복사, 범례 | 206px |

오른쪽 버튼 그룹은 모든 화면에서 화면 스킨 전환(`#skin`)과 애니메이션 설정(`#motion`)이고 폭 150px입니다.

**바꿀 내용**

1. 왼쪽 버튼 그룹을 제목 줄 오른쪽의 버튼 줄(`.th-cond-btns`: 조건 바꾸기, 비교, 범위, `?`가 있는 줄)로 옮깁니다. 이 줄의 남는 폭은 1920px에서 1,157px, 1280px에서 559px라, 가장 넓은 그룹(406px)도 1,280px 이상의 네 해상도에서 한 줄에 들어갑니다. 기존 버튼과는 구분선이나 간격으로 그룹을 나눕니다. 줄 높이 28px와 머리 영역 높이(96px, 1600px 미만은 86px)는 그대로입니다.
2. 오른쪽 버튼 그룹(화면 스킨, 애니메이션 설정)은 상단 안내 바의 오른쪽 끝으로 옮깁니다. 제목 줄에 함께 넣으면 1280x800의 고객군과 시장, 담보 비교에서 9px와 29px가 모자랍니다.
3. 하단의 `#actbar`는 없앱니다. 버튼의 id와 동작, 키보드 단축 동작은 그대로 둡니다. 탭 줄 왼쪽의 "전체 요약" 링크와 "뒤로" 버튼의 동작이 같다면 "뒤로"는 없앱니다(다르면 PR 글에 차이를 적고 둘 다 둡니다).
4. 380px에서는 버튼을 아이콘만 보이게 하거나 한 버튼 안의 메뉴로 접습니다.
5. 가로 1,024~1,279px에서 버튼 줄이 한 줄에 들어가지 않는 폭이면 화면 버튼 그룹(왼쪽 버튼 그룹)을 메뉴 버튼 하나로 접습니다(4번의 380px와 같은 방식). 담보 비교는 1,180x820에서 여유 37px로 들어가고 1,024x768에서 119px 모자랍니다(부록 5.4절). 1절의 "문서 높이 = 화면 높이"는 1,280px 이상에만 적용하며 이 구간에는 적용하지 않습니다.

**완료 기준**

- `#actbar`가 DOM에 없거나 높이 0입니다. 표의 버튼이 모두 제목 줄에서 동작합니다(화면마다 클릭 결과가 지금과 같음).
- 여섯 화면, 해상도 넷에서 제목 줄의 버튼 줄이 한 줄(높이 28px)이고 버튼과 조건 요약 문장이 잘리지 않습니다.
- 1,180x820에서도 여섯 화면의 제목 줄이 한 줄을 유지합니다. 1,024x768에서는 화면 버튼 그룹을 메뉴 버튼으로 접은 상태로 한 줄을 유지합니다.
- 키보드 Tab 순서가 상단 안내 바의 설정 버튼(화면 스킨, 애니메이션 설정), 제목 줄의 버튼, 탭 줄, 본문 순서입니다(부록 5.5절).

## 3. 조건 바꾸기 패널과 큰 영역 전환의 애니메이션

**사용자의 말**: "조건 바꾸기 접기 모션이 너무 갑작스러워 좀 더 조정이 필요할 것 같아", "조건바꾸기 버튼 패널 나오는 모션 너무 빨라", "부드러운 느낌이 없잖아"

**지금 상태**(1920x1080, 담보 비교 탭, `requestAnimationFrame`으로 프레임마다 측정)

| 동작 | 측정값 |
| --- | --- |
| 열기 | 패널(높이 89px)이 첫 프레임에 전체 높이로 나타나고, 아래 콘텐츠가 같은 프레임에 97px 밀립니다. 애니메이션은 불투명도 0.4 → 1과 6px 이동뿐이고(`style.css` 195~196행 `layerDrop` 200ms), 불투명도의 100ms 진행률이 95%(5회 93~97%), 90% 도달이 78ms(5회 70~89ms)입니다. 1600x900, 1366x768, 1280x800에서는 패널이 두 행 166px로 접히고 아래 콘텐츠가 174px, 380x780에서는 패널 498px에 아래 콘텐츠가 506px 밀립니다. |
| 접기 | `hidden` 속성으로 한 프레임에 사라지고(`core.js` 1220~1231행 `setCondOpen`, 1223행 `el.hidden`), 아래 콘텐츠가 97px 한 번에 올라옵니다. 조건을 바꿔 자동으로 접힐 때(`core.js` 798행)와 Esc나 "뒤로"로 접힐 때(2484행 `stepUp`)도 같습니다. |

가장 큰 변화(패널이 펼쳐지는 것과 아래 콘텐츠가 밀리는 것)가 한 프레임에 끝나고, 눈에 보이는 것은 6px짜리 이동뿐입니다. 밀리는 아래 콘텐츠는 `.shell` 안에서 `#cond` 뒤에 오는 요소 전부입니다: `#scope`, `#rtabs-wrap`, 전체 요약의 본문 `#home-panel`, `#board`, `#actbar`, `#foot`. 전체 요약에서도 `#home-panel`이 97px 밀립니다. 탭별 값은 부록 2.3절에 있습니다.

**바꿀 내용**

1. 패널이 높이 0에서 실제 높이까지 이어서 펼쳐지고, 아래 콘텐츠가 같은 곡선으로 함께 움직입니다. 접을 때는 같은 애니메이션을 거꾸로 합니다. 조건을 바꿔 자동으로 접힐 때도 같습니다.
2. 시간은 열기 400ms, 접기 320ms에서 시작합니다. 사용자가 보고 조정할 수 있게 시간과 이징을 CSS 변수 한 곳에서 정합니다(예: `--dur-panel-open`, `--dur-panel-close`, `--ease-panel`). 이징은 변화가 초반에 몰리지 않는 곡선을 씁니다. 권장 곡선은 `cubic-bezier(.2, 0, .8, 1)`입니다. 요청 28 2.2절의 들어옴 곡선(`cubic-bezier(0.16, 1, 0.3, 1)`, 지금의 `--ease`와 `--ease-in`)과 나감 곡선(`cubic-bezier(0.7, 0, 0.84, 0)`)은 이 전환들에 쓰지 않습니다. 들어옴 곡선은 100ms에 82.6%가 끝나고, 두 곡선 모두 174px를 옮길 때 한 프레임에 41~51px를 움직입니다(부록 3.2절). 호버, 클릭, 선택 같은 작은 반응과 도형 애니메이션은 요청 28의 곡선을 그대로 씁니다. 접기 320ms는 사용자가 정한 값이라 요청 28 2.2절의 "나갈 때 들어올 때 길이의 60%"보다 우선합니다. 요청 28 2.2절의 구역 안 전환 320ms도 이 전환들에서는 아래 완료 기준의 시간 규칙에 따라 이동 거리만큼 길어질 수 있습니다(600ms 이하).
3. 패널 안의 항목은 펼침이 절반쯤 진행된 뒤 불투명도로 들어옵니다.
4. 요청 28의 성능 기준(33ms를 넘는 프레임 0개)은 그대로입니다. 애니메이션하는 속성 규칙은 범위를 이렇게 정합니다. 위치와 크기를 바꾸는 애니메이션은 `transform`, `opacity`, `stroke-dashoffset`, `clip-path`만 씁니다. 색 전환(`color`, `background`, `border-color`)은 레이아웃을 일으키지 않으므로 허용합니다. 요청 32의 4-3에서 색 전환까지 문제로 삼았던 것은 이 범위로 완화합니다(7절 10번). 높이를 직접 전환하지 말고, 최종 레이아웃을 먼저 잡은 뒤 `transform`과 `clip-path`로 이전 위치에서 새 위치로 옮기는 방식(FLIP)을 권합니다. 1절에 따라 아래 영역이 화면 높이에 맞춰지므로, 패널이 열릴 때 아래 영역이 어떻게 줄어드는지도 같은 방식으로 이어지게 합니다.
5. 큰 영역이 바뀌는 다른 전환도 같은 기준으로 고칩니다. 대상은 측정에서 한 프레임에 끝나는 것으로 나온 여덟 종과 6절의 오른쪽 열 전환입니다(부록 4.1절: 범위 패널 열기와 접기, 비교 드롭다운과 범례와 도움말 팝오버, 오른쪽 열 상세 패널 열기와 닫기, 담보 비교 하단 상세 패널 열기와 닫기, 상세 패널의 접이식 항목, 표로 보기 모달, 탭 전환, 담보 비교 필터). 이미 기준을 지키거나 이번 범위가 아닌 다섯 종(부록 4.2절: 담보 비교의 단계 전환, 같은 상세 패널 안의 내용 교체, 영업 인사이트의 분류 이동, 다크 모드 전환, 관계 탭의 프리셋 전환)은 고치지 않고 지금보다 나빠지지 않게만 봅니다.

**완료 기준**(전환마다 `requestAnimationFrame`으로 700ms 동안 나타나는 요소와 밀리는 요소의 위치를 기록. 시간을 늘린 전환은 명목 시간에 300ms를 더한 동안. 지표의 정의는 부록 1절)

- 한 프레임 최대 이동이 12px 이하입니다(60Hz 기준). 이동 거리가 크면 시간을 늘려 맞춥니다. 권장 곡선 `cubic-bezier(.2, 0, .8, 1)`에서 한 프레임 최대 이동은 약 `20.8 x 이동 거리(px) / 시간(ms)`px이므로, 12px 이하가 되려면 시간이 `1.74 x 이동 거리`ms 이상이어야 합니다(부록 3.3절, Claude 계산).

  | 이동 거리 | 해당하는 전환의 예 | 시간 | 기준 |
  | --- | --- | --- | --- |
  | 184px 이하 | 1920x1080 조건 바꾸기 패널(밀림 97px), 1600x900 이하 두 행 패널(밀림 174px), 데스크톱의 범위 패널 | 열기 400ms, 접기 320ms 그대로(계산 값: 97px 5.1px와 6.3px, 174px 9.1px와 11.3px) | 12px 이하 |
  | 185~345px | 담보 비교 하단 상세 패널의 높이를 애니메이션할 때(230~300px), 380x780 범위 패널(274px) | 열기는 400ms와 `1.74 x 이동 거리`ms 가운데 긴 쪽, 접기는 320ms와 `1.74 x 이동 거리`ms 가운데 긴 쪽(600ms 이하) | 12px 이하 |
  | 345px 초과 | 380x780 조건 바꾸기 패널(밀림 506px) | 600ms를 넘기지 않습니다 | 한 프레임 최대 이동이 이동 거리의 3.5% 이하(506px이면 17.6px) |

- 위 기준은 애니메이션 설정 "켬"에서 잽니다. "줄임"(지금 화면 표기 "차분")은 시간이 약 0.55배라 두 행 패널에서도 12px를 넘으므로(접기 176ms에서 20.6px), 이동 거리 기준을 적용하지 않고 컷 0개와 닫기 애니메이션만 봅니다.
- 시작 100ms 시점의 진행률이 50% 이하입니다.
- 닫기에도 열기와 같은 종류의 애니메이션이 있습니다(한 프레임에 사라지는 전환 0개).
- 33ms를 넘는 프레임 0개(보통 속도, 세 번 실행한 가장 나쁜 값).
- 애니메이션 설정이 "끔"이면 즉시 전환됩니다(지금 동작 유지).
- PR 글에 전환별 측정표(전환, 시간, 한 프레임 최대 이동, 100ms 진행률, 닫기 애니메이션 유무)를 고치기 전과 후로 적습니다.

## 4. 담보 비교: 요약 바는 단계 선택과 위치 표시만

**사용자의 말**: "담보비교 화면에서 어차피 담보별 상세내용을 화면 중단에서 표현한다면 상단에 있는 요약 담보 리스트에서도 상세내용 표시 인터랙션을 넣는건 불편하기만 하고 굳이 라는 생각이 드네"

**지금 상태**: 요약 바의 눈금 79개마다 호버 툴팁(`.hud-tip`, 222x82px, 담보 이름과 보유 여부와 판정 칩)이 떠서 탭 줄을 가립니다. 눈금 위를 드래그하며 탐색하는 인터랙션도 있습니다. 같은 내용을 바로 아래 상세 영역의 막대와 하단 상세 패널이 보여 줍니다. 눈금을 클릭하면 담보가 선택되고 하단 상세 패널이 열리며, 구간 버튼의 네 곳(라벨 영역, 눈금 영역 두 곳, 버튼 가운데)을 클릭했을 때 단계 전환에서 그치는 곳은 라벨 영역 하나뿐입니다. 구간 버튼에서 Enter나 Space를 눌러도 그 단계의 첫 담보가 선택됩니다(부록 8.2절).

**바꿀 내용**

1. 요약 바는 단계 선택과 현재 위치 표시만 맡습니다. 구간(진단, 수술, 치료, 입원, 통원)을 클릭하면 상세 영역이 그 단계로 바뀝니다. 구간 전체가 하나의 버튼입니다(호버, 포커스, 선택 상태 표시).
2. 눈금별 호버 툴팁과 드래그 탐색을 없앱니다. 요청 32의 4-1(요약 바 높이 전체가 드래그 탐색에 반응)은 철회합니다. Claude가 지정한 인터랙션이 역할을 겹치게 만들었습니다. 요청 28 3.1절의 "구간이나 눈금을 누르면 그 단계로" 가운데 눈금 부분과, 2.3절의 클릭할 수 있는 도형 목록에 든 "전체 띠의 눈금"도 같은 이유로 철회합니다(같은 절의 막대 호버 때 눈금이 진해지는 것은 그대로).
3. 반대 방향의 연동만 둡니다. 상세 영역에서 막대에 호버하거나 선택하면 요약 바의 해당 눈금이 강조됩니다(전체에서의 위치 표시).
4. 눈금의 판정 표시(채움, 윤곽)는 그대로 둡니다. 측정해 보니 필터는 막대를 숨기지 않고 흐리게만 하므로(불투명도 0.18) 필터 상태에서도 모든 담보를 막대로 선택할 수 있습니다. 예외는 비교 범위를 한 회사로 좁힌 경우입니다. 두 회사 모두 없는 담보(한화생명만 선택하면 10개, 삼성화재만 선택하면 12개)는 "둘 다 없음" 비활성 막대가 되어 막대 클릭과 Enter로는 선택되지 않고(`core.js` 3117행), 지금은 눈금 클릭으로만 선택됩니다. 눈금 클릭을 없애면 이 담보를 선택할 경로가 없어지는데, 비활성 막대 규칙과 같아지므로 그대로 둡니다(지금 눈금으로 선택해도 하단 상세 패널의 모든 항목이 "값이 있는 회사 없음"입니다). 새 선택 경로를 만들지 않고, PR 글에 이 동작을 적습니다(부록 8.4절).
5. 담보 선택의 키보드 경로는 상세 영역의 막대입니다(좌우 화살표로 이동, Enter로 선택).

**완료 기준**

- 요약 바의 어느 지점에 호버해도 `.hud-tip`이 0개입니다.
- 구간 다섯 개의 클릭 영역이 구간 전체(이름표 줄 포함)이고, 클릭하면 상세 영역의 단계가 바뀝니다. 클릭, Enter, Space 뒤 선택한 담보가 바뀌지 않고 하단 상세 패널이 새로 열리지 않습니다(부록 8.5절의 K3, K4, K5).
- 상세 영역의 막대 호버와 선택이 요약 바의 눈금 강조와 1:1로 대응합니다(막대 수만큼 확인).
- 오전 재검수의 두 건이 해소됩니다: 툴팁의 대표 판정 칩을 화면이 정하던 것(`tab4.src.js` `rowStackMetrics`의 `domChip`), 구간 이름표와 겹친 눈금이 클릭되지 않던 것. 상세 영역의 막대 툴팁이 같은 칩을 쓴다면(지금 `tab4.src.js` 526행이 같은 `domChip`을 씁니다) 데이터에서 읽게 고칩니다. 담보별 판정과 건수는 `CV.b[기준종형ID].판정상대수[표준담보ID]`, 판정의 화면 이름은 `CV.판정표`의 `표시명`에 있습니다(`판정요약`은 회사별로 담보 전체를 센 값이라 담보 하나의 칩에는 맞지 않습니다).

## 5. 담보 비교: 하단 상세 패널을 세로로 넓게

**사용자의 말**: "담보비교 밑에 상품 상세내용 하단에 나오는거 수직으로 좀 더 넓어도 되겠어 어차피 하단 버튼들 전부 상단으로 올릴거잖아"

**완료 기준**

- 분류 소개 줄에 내부 분류 코드가 보입니다("G1 … 0, G2 … 0, G3 … 3").

**바꿀 내용**

1. 요약은 가운데 영역 맨 위의 한 행(높이 32px 이하)으로 줄입니다. 전체 건수와 응대 화법에 추가한 건수만 적습니다. 분류별 건수는 왼쪽 목차에만 둡니다. 요약 문장 전체는 "요약 복사" 버튼으로 복사할 수 있게만 남깁니다(화면에 펼쳐 보이지 않음).
2. 가운데 영역의 이동 버튼(`.ins-jump`)을 없앱니다. 왼쪽 목차와 같은 기능입니다.
3. 오른쪽 열의 기본 내용을 응대 카드 미리 보기로 바꿉니다. 인사이트 목록은 가운데 열 전체 폭을 씁니다.
4. 인사이트 항목의 근거를 열면 오른쪽 열이 상세 패널로 바뀌고, 닫으면 미리 보기로 돌아옵니다. 이 전환은 3절의 기준을 따릅니다. 상세 패널이 열려 있는 동안에도 미리 보기로 돌아가는 버튼이 보입니다.
5. 목록에서 항목을 추가하면 오른쪽 미리 보기의 해당 위치에 항목이 삽입되는 애니메이션이 있고(펼쳐지며 들어오고 한 번 강조), 미리 보기가 그 위치로 스크롤됩니다. 제외하면 접히며 빠집니다. 추가한 건수 표시도 함께 바뀝니다.
6. 내부 분류 코드(G1~G3, A1, A2, Q1~Q3)는 화면에 보이지 않게 합니다. 분류 이름과 세부 이름만 적습니다.

**완료 기준**

- 화면에 분류별 건수가 한 곳(왼쪽 목차)에만 있습니다. `.ins-jump` 없음.
- 첫 번째 인사이트 항목의 윗변 y가 지금보다 150px 이상 위입니다(1920x1080에서 지금 약 545).
- 오른쪽 열에 미리 보기가 폭 480px 이상으로 보입니다(1920x1080).
- 항목을 추가한 뒤 600ms 안에 그 항목이 미리 보기의 보이는 영역 안에 있습니다. 추가와 제외를 번갈아 다섯 번 해도 목록과 미리 보기의 항목 수가 같습니다.
- 화면의 보이는 글자에 `G1`, `G2`, `G3`, `A1`, `A2`, `Q1`, `Q2`, `Q3`가 없습니다.
