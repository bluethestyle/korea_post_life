## 0. Claude가 main에서 이미 고친 것

- 사용자의 말: "고객군과 시장 화면에서 수직 스크롤이 안 먹는 영역이 있는데?"
- 원인은 `.z-left`, `.z-center`, `.ev-body`의 `overscroll-behavior:contain`이었습니다. 안에 스크롤할 내용이 없어도 휠 스크롤이 페이지로 넘어가지 않았습니다. 세 곳에서 제거했습니다(커밋 `ea7d6b3`, `proto_src/console4/style.css`). 이 속성을 다시 넣지 않습니다.

## 1. 페이지 구조: 데스크톱에서는 페이지가 스크롤되지 않고, 제목 줄과 탭 줄은 제자리

**사용자의 말**: "분류를 눌렀을 때 해당 위치로 스크롤이 이동하면서 최상단 메뉴도 같이 스크롤이 내려가는 방식인데 최상단 메뉴는 놔두는게 좋지 않을까?"

**지금 상태**

| 해상도 | 문서 높이 | 페이지 스크롤 | 영업 인사이트에서 목차 클릭 뒤 |
| --- | --- | --- | --- |
| 1920x1080 | 1,149px(담보 비교에서 상세 패널을 열면 1,205px) | 69px(125px) | `window.scrollY` 69, 탭 줄 y 126 → 57 |
| 1366x768 | 973px | 205px | 탭 줄이 화면 밖으로 나감 |

목차를 클릭하면 가운데 영역(`#z-center`, 내용 높이 6,146px)이 스크롤되는 것과 함께 페이지도 끝까지 내려갑니다.

**바꿀 내용**

1. 가로 1280px 이상에서는 문서 높이를 화면 높이에 맞춥니다. 상단 안내 바, 제목 줄, 탭 줄은 늘 제자리에 있고, 그 아래 영역이 남은 높이를 나눠 쓰며 안쪽에서만 스크롤됩니다.
2. 하단 고지문(`#foot`, 높이 124px)을 정리합니다. 글꼴 라이선스 문단은 도움말(`?`) 창으로 옮깁니다. "공모전 시연용 화면이며 영업 자료가 아닙니다"는 상단 안내 바에 이미 있습니다. 나머지 고지 문장과 자료 기준 시각은 화면에서 늘 보이는 한 줄(높이 24px 이하)로 둡니다(상단 안내 바의 오른쪽 또는 화면 맨 아래 고정 줄). 자료 기준 시각은 사라지면 안 됩니다.
3. 목차나 분류를 클릭했을 때는 해당 스크롤 영역만 움직입니다(`scrollIntoView` 대신 그 영역의 `scrollTo`).
4. 380px 폭의 좁은 화면은 지금처럼 페이지 스크롤을 씁니다.

**완료 기준**

- 전체 요약과 다섯 탭, 해상도 넷(1920x1080, 1600x900, 1366x768, 1280x800), 상세 패널을 열기 전과 뒤 모두에서 `document.documentElement.scrollHeight === innerHeight`.
- 영업 인사이트의 목차 다섯 항목을 차례로 클릭했을 때 `window.scrollY`가 0이고 탭 줄(`#rtabs`)의 y가 변하지 않으며, 가운데 영역의 `scrollTop`만 변합니다.
- 어느 탭에서도 내용이 잘려 닿을 수 없는 곳이 없습니다(각 스크롤 영역의 끝까지 휠과 키보드로 이동).

## 2. 버튼 줄을 상단으로

**사용자의 말**: "그리고 뒤로, 표로보기 등 버튼들이 상단에 배치해야되지 않나?"

**지금 상태**: 하단 버튼 줄(`#actbar`, 높이 39px에 위 간격 10px)은 1920x1080에서 y 936~982에 있고, 1600x900 이하에서는 상세 패널을 열기 전에도 화면 아래에 걸치거나 화면 밖에 있습니다.

| 화면 | 왼쪽 묶음의 버튼 | 폭 |
| --- | --- | --- |
| 전체 요약 | 문장으로 보기(`home-text-btn`), 요약 복사(`act-copy`), 범례 | 272px |
| 고객군과 시장 | 뒤로(`act-back`), 표로 보기(`mk-btn-tally`), 개정과 시장(`mk-btn-rev`), 요약 복사, 범례 | 386px |
| 가입 관문 | 뒤로, 표로 보기(`gt-btn-tbl`), 요약 복사, 범례 | 300px |
| 담보 비교 | 뒤로, 표로 보기(`cv-btn-tbl`), 비교표 복사(`data-act=cv-copy-table`), 요약 복사, 범례 | 406px |
| 영업 인사이트, 관계 지도 | 뒤로, 요약 복사, 범례 | 206px |

오른쪽 묶음은 모든 화면에서 화면 스킨 전환(`#skin`)과 애니메이션 설정(`#motion`)이고 폭 150px입니다.

**바꿀 내용**

1. 왼쪽 묶음을 제목 줄 오른쪽의 버튼 줄(`.th-cond-btns`: 조건 바꾸기, 비교, 범위, `?`가 있는 줄)로 옮깁니다. 이 줄의 남는 폭은 1920px에서 1,157px, 1280px에서 559px라, 가장 넓은 묶음(406px)도 모든 해상도에서 한 줄에 들어갑니다. 기존 버튼과는 구분선이나 간격으로 묶음을 나눕니다. 줄 높이 28px와 머리 영역 높이(96px, 1600px 미만은 86px)는 그대로입니다.
2. 오른쪽 묶음(화면 스킨, 애니메이션 설정)은 상단 안내 바의 오른쪽 끝으로 옮깁니다. 제목 줄에 함께 넣으면 1280x800의 고객군과 시장, 담보 비교에서 9px와 29px가 모자랍니다.
3. 하단의 `#actbar`는 없앱니다. 버튼의 id와 동작, 키보드 단축 동작은 그대로 둡니다. 탭 줄 왼쪽의 "전체 요약" 링크와 "뒤로" 버튼의 동작이 같다면 "뒤로"는 없앱니다(다르면 PR 글에 차이를 적고 둘 다 둡니다).
4. 380px에서는 버튼을 아이콘만 보이게 하거나 한 버튼 안의 메뉴로 접습니다.

**완료 기준**

- `#actbar`가 DOM에 없거나 높이 0입니다. 표의 버튼이 모두 제목 줄에서 동작합니다(화면마다 클릭 결과가 지금과 같음).
- 여섯 화면, 해상도 넷에서 제목 줄의 버튼 줄이 한 줄(높이 28px)이고 버튼과 조건 요약 문장이 잘리지 않습니다.
- 키보드 Tab 순서가 제목 줄의 버튼, 탭 줄, 본문 순서입니다.

## 3. 조건 바꾸기 패널과 큰 영역 전환의 애니메이션

**사용자의 말**: "조건 바꾸기 접기 모션이 너무 갑작스러워 좀 더 조정이 필요할 것 같아", "조건바꾸기 버튼 패널 나오는 모션 너무 빨라", "부드러운 느낌이 없잖아"

**지금 상태**(1920x1080, 담보 비교 탭, `requestAnimationFrame`으로 프레임마다 측정)

| 동작 | 측정값 |
| --- | --- |
| 열기 | 패널(높이 89px)이 첫 프레임에 전체 높이로 나타나고, 아래 콘텐츠가 같은 프레임에 97px 밀립니다. 애니메이션은 불투명도 0.4 → 1과 6px 이동뿐이고(`style.css` 195~196행 `layerDrop` 200ms), 24ms에 0.66, 58ms에 0.90으로 60ms 안에 대부분 끝납니다. |
| 접기 | `hidden` 속성으로 한 프레임에 사라지고(`core.js` 1221~1227행 `setCondOpen`), 아래 콘텐츠가 97px 한 번에 올라옵니다. 조건을 바꿔 자동으로 접힐 때(`core.js` 798행)도 같습니다. |

가장 큰 변화(패널이 펼쳐지는 것과 아래 콘텐츠가 밀리는 것)가 한 프레임에 끝나고, 눈에 보이는 것은 6px짜리 이동뿐입니다.

**바꿀 내용**

1. 패널이 높이 0에서 실제 높이까지 이어서 펼쳐지고, 아래 콘텐츠가 같은 곡선으로 함께 움직입니다. 접을 때는 같은 애니메이션을 거꾸로 합니다. 조건을 바꿔 자동으로 접힐 때도 같습니다.
2. 시간은 열기 400ms, 접기 320ms에서 시작합니다. 사용자가 보고 조정할 수 있게 시간과 이징을 CSS 변수 한 곳에서 정합니다(예: `--dur-panel-open`, `--dur-panel-close`, `--ease-panel`). 이징은 변화가 초반에 몰리지 않는 곡선을 씁니다.
3. 패널 안의 항목은 펼침이 절반쯤 진행된 뒤 불투명도로 들어옵니다.
4. 요청 28의 성능 기준(애니메이션하는 속성은 `transform`, `opacity`, `stroke-dashoffset`, `clip-path`만, 33ms를 넘는 프레임 0개)은 그대로입니다. 높이를 직접 전환하지 말고, 최종 레이아웃을 먼저 잡은 뒤 `transform`과 `clip-path`로 이전 위치에서 새 위치로 옮기는 방식(FLIP)을 권합니다. 1절에 따라 아래 영역이 화면 높이에 맞춰지므로, 패널이 열릴 때 아래 영역이 어떻게 줄어드는지도 같은 방식으로 이어지게 합니다.
5. 큰 영역이 바뀌는 다른 전환도 같은 방법으로 측정해, 한 프레임에 끝나는 것이 있으면 같은 기준으로 고칩니다: 상세 패널 열기와 닫기(탭마다), 표로 보기 창 열기와 닫기, 범례 창, 비교와 범위 드롭다운, 담보 비교의 단계 전환, 6절의 오른쪽 열 전환.

**완료 기준**(전환마다 `requestAnimationFrame`으로 700ms 동안 나타나는 요소와 밀리는 요소의 위치를 기록)

- 어느 프레임에서도 한 번에 12px 넘게 움직이지 않습니다(60Hz 기준).
- 시작 100ms 시점의 진행률이 50% 이하입니다.
- 닫힘에도 열림과 같은 종류의 애니메이션이 있습니다(한 프레임에 사라지는 전환 0개).
- 33ms를 넘는 프레임 0개(보통 속도, 세 번 실행한 가장 나쁜 값).
- 애니메이션 설정이 "끔"이면 즉시 전환됩니다(지금 동작 유지).
- PR 글에 전환별 측정표(전환, 시간, 한 프레임 최대 이동, 100ms 진행률, 닫힘 애니메이션 유무)를 고치기 전과 후로 적습니다.

## 4. 담보 비교: 요약 바는 단계 선택과 위치 표시만

**사용자의 말**: "담보비교 화면에서 어차피 담보별 상세내용을 화면 중단에서 표현한다면 상단에 있는 요약 담보 리스트에서도 상세내용 표시 인터랙션을 넣는건 불편하기만 하고 굳이 라는 생각이 드네"

**지금 상태**: 요약 바의 눈금 79개마다 호버 툴팁(`.hud-tip`, 222x82px, 담보 이름과 보유 여부와 판정 칩)이 떠서 탭 줄을 가립니다. 눈금 위를 드래그하며 탐색하는 인터랙션도 있습니다. 같은 내용을 바로 아래 상세 영역의 막대와 하단 상세 패널이 보여 줍니다.

**바꿀 내용**

1. 요약 바는 단계 선택과 현재 위치 표시만 맡습니다. 구간(진단, 수술, 치료, 입원, 통원)을 클릭하면 상세 영역이 그 단계로 바뀝니다. 구간 전체가 하나의 버튼입니다(호버, 포커스, 선택 상태 표시).
2. 눈금별 호버 툴팁과 드래그 탐색을 없앱니다. 요청 32의 4-1(요약 바 높이 전체가 드래그 탐색에 반응)은 철회합니다. Claude가 지정한 인터랙션이 역할을 겹치게 만들었습니다.
3. 반대 방향의 연동만 둡니다. 상세 영역에서 막대에 호버하거나 선택하면 요약 바의 해당 눈금이 강조됩니다(전체에서의 위치 표시).
4. 눈금의 판정 표시(채움, 윤곽)는 그대로 둡니다. 필터를 켰을 때 상세 영역에 보이지 않게 되는 담보가 요약 바로만 선택할 수 있었다면, 필터 상태에서도 상세 영역에서 선택할 수 있는 경로를 확인해 PR 글에 적습니다.
5. 담보 선택의 키보드 경로는 상세 영역의 막대입니다(좌우 화살표로 이동, Enter로 선택).

**완료 기준**

- 요약 바의 어느 지점에 호버해도 `.hud-tip`이 0개입니다.
- 구간 다섯 개의 클릭 영역이 구간 전체(이름표 줄 포함)이고, 클릭하면 상세 영역의 단계가 바뀝니다.
- 상세 영역의 막대 호버와 선택이 요약 바의 눈금 강조와 1:1로 대응합니다(막대 수만큼 확인).
- 오전 재검수의 두 건이 해소됩니다: 툴팁의 대표 판정 칩을 화면이 정하던 것(`tab4.src.js` `rowStackMetrics`의 `domChip`), 구간 이름표와 겹친 눈금이 클릭되지 않던 것. 상세 영역의 막대 툴팁이 같은 칩을 쓴다면 데이터의 `판정요약`에서 읽게 고칩니다.

## 5. 담보 비교: 하단 상세 패널을 세로로 넓게

**사용자의 말**: "담보비교 밑에 상품 상세내용 하단에 나오는거 수직으로 좀 더 넓어도 되겠어 어차피 하단 버튼들 전부 상단으로 올릴거잖아"

**지금 상태**(1920x1080): 담보를 선택하면 하단 상세 패널(`#z-right`)이 높이 268px로 나오고, 내용 영역(`.ev-body`)은 238px에서 안쪽 스크롤이 생깁니다. 기준 종형 다섯과 담보 전부(389건)를 선택해 잰 내용 높이는 최소 481px, 중앙값 570px, 최대 877px입니다. 첫 구역(회사별 조건 표)을 한 번에 보려면 292px가 필요한데, 지금은 389건 모두 첫 구역이 잘립니다.

**바꿀 내용**

1. 버튼 줄이 빠진 높이(49px)와 차트 영역의 여백을 상세 패널에 줍니다. 1920x1080에서 `.ev-body`를 340px 이상으로 합니다.
2. 네 해상도 모두에서 `.ev-body`가 292px 이상이어야 합니다. 1절의 조건(페이지 스크롤 없음) 안에서 맞춰야 하므로, 낮은 해상도에서는 차트 영역(막대의 최대 높이, 이름표의 높이, 간격)을 줄이거나 차트 영역이 안쪽에서 스크롤되게 합니다. 막대와 이름표가 읽히지 않을 만큼 줄이지는 않습니다(막대 최대 높이 96px 이상, 이름표 글자 13px 이상).
3. 비교 대상 회사가 늘면 첫 구역이 길어집니다(가상 20곳 화면에서 300~977px). 패널 높이를 고정 px 하나로 정하지 말고 화면 높이에 대한 비율과 최소값으로 정합니다.

**완료 기준**

- 1920x1080에서 `.ev-body` 높이 340px 이상, 나머지 세 해상도에서 292px 이상.
- 세 회사 화면에서 기준 종형 다섯과 담보 전부를 선택했을 때 첫 구역(회사별 조건 표)이 안쪽 스크롤 없이 다 보입니다(389건 가운데 389건).

## 6. 영업 인사이트 탭 정리

**사용자의 말**: "이 문구 표시하는 부분이 굳이 저렇게 공간을 많이 할애할 필요가 있을까?", "어차피 왼쪽에 목차가 있는데 가운데 영역에서 콘텐츠 초반에 퀵이동 버튼을 한번 더 넣을 필요가 있을까?", "응대카드가 제일 오른쪽에 있는게 나을 것 같은데, 컨텐츠를 선택하면서 하나씩 추가되는것도 눈으로 잘 보일거고"

**지금 상태**(1920x1080)

- 분류별 건수가 네 곳에 나옵니다: 왼쪽 목차, 가운데 맨 위의 요약 행(높이 60px), 그 아래 이동 버튼(`.ins-jump`, 높이 약 110px), 오른쪽 열의 요약 문장.
- 오른쪽 열(폭 510px, 높이 700px)에는 요약 문장 하나만 있습니다.
- 응대 카드 미리 보기는 가운데 영역의 오른쪽에 폭 345px로 들어가 있습니다.
- 분류 소개 줄에 내부 분류 코드가 보입니다("G1 … 0, G2 … 0, G3 … 3").

**바꿀 내용**

1. 요약은 가운데 영역 맨 위의 한 행(높이 32px 이하)으로 줄입니다. 전체 건수와 응대 화법에 추가한 건수만 적습니다. 분류별 건수는 왼쪽 목차에만 둡니다. 요약 문장 전체는 "요약 복사" 버튼으로 복사할 수 있게만 남깁니다(화면에 펼쳐 보이지 않음).
2. 가운데 영역의 이동 버튼(`.ins-jump`)을 없앱니다. 왼쪽 목차와 같은 기능입니다.
3. 오른쪽 열의 기본 내용을 응대 카드 미리 보기로 바꿉니다. 인사이트 목록은 가운데 열 전체 폭을 씁니다.
4. 인사이트 항목의 근거를 열면 오른쪽 열이 상세 패널로 바뀌고, 닫으면 미리 보기로 돌아옵니다. 이 전환은 3절의 기준을 따릅니다. 상세 패널이 열려 있는 동안에도 미리 보기로 돌아가는 버튼이 보입니다.
5. 목록에서 항목을 추가하면 오른쪽 미리 보기의 해당 위치에 항목이 삽입되는 애니메이션이 있고(펼쳐지며 들어오고 한 번 강조), 미리 보기가 그 위치로 스크롤됩니다. 제외하면 접히며 빠집니다. 추가한 건수 표시도 함께 바뀝니다.
6. 내부 분류 코드(G1~G3, A1, A2, Q1~Q3)는 화면에 보이지 않게 합니다. 분류 이름과 세부 이름만 적습니다.

**완료 기준**

- 화면에 분류별 건수가 한 곳(왼쪽 목차)에만 있습니다. `.ins-jump` 없음.
- 첫 번째 인사이트 항목의 윗변 y가 지금보다 150px 이상 위입니다(1920x1080에서 지금 약 545).
- 오른쪽 열에 미리 보기가 폭 480px 이상으로 보입니다(1920x1080).
- 항목을 추가한 뒤 600ms 안에 그 항목이 미리 보기의 보이는 영역 안에 있습니다. 추가와 제외를 번갈아 다섯 번 해도 목록과 미리 보기의 항목 수가 같습니다.
- 화면의 보이는 글자에 `G1`, `G2`, `G3`, `A1`, `A2`, `Q1`, `Q2`, `Q3`가 없습니다.
