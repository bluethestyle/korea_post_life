# 요청 19. 화면 흐름도(합의안)를 브라우저로 직접 눌러 보는 점검 (Antigravity 브라우저 에이전트용)

Antigravity의 브라우저 에이전트(`/browser`)에 사람이 붙여 넣어 돌리는 점검 지시문입니다. 요청 18에서 본 화면 흐름도는 이용자를 창구로 잡은 옛 구성이었고, 이번 것은 이용자를 본부의 영업 기획과 분석 담당자로 바로잡아 다시 만든 것입니다(2026-11-20). 시안 4는 이 흐름도대로 만들고 있어서, 흐름이 읽히는지를 시안보다 먼저 확인합니다. 시안 4의 점검은 시안이 올라간 뒤에 따로 요청합니다.

점검이 끝나면 보고 글을 Claude Code 대화에 붙여 넣어 주세요. 사진은 붙이지 않아도 됩니다. 보고 글에 PC의 폴더 경로가 들어가지 않게 사진은 파일 이름만 적게 했습니다.

아래 줄부터 끝까지를 그대로 붙여 넣습니다.

---

/browser 아래 주소를 열어 시나리오대로 실제로 눌러 보고, 본 것을 보고해 주세요.

- 화면 흐름도: `https://bluethestyle.github.io/korea_post_life/proto/flow.html`

이 쪽은 만들 화면의 설계도입니다. 화면을 쓰는 사람은 보험사 본부의 영업 기획과 분석 담당자이고, 우체국보험 상품을 한화생명, 삼성화재 상품과 견주어 넓게 보고, 좁혀 확인하고, 영업 인사이트를 뽑아 내보냅니다. 탭은 그 순서대로 다섯 개(브리핑, 고객군과 시장, 가입 관문, 담보 비교, 영업 인사이트)입니다. 쪽 안의 숫자는 예시라 옳고 그름을 판단하지 않습니다. 볼 것은 세 가지입니다: 화면이 어떤 순서로 이어지는지 바로 읽히는가, 누를 수 있는 것이 누를 수 있게 보이는가, 글자가 잘리거나 겹치지 않는가. 다른 사이트로 이동하거나 로그인하지 않고, 파일을 만들거나 고치지 않습니다.

## 점검 조건

- 창 크기 1920x1080에서 한 번, 1280x800에서 한 번, 380x780(휴대폰 너비)에서 한 번 합니다.
- 단계마다 화면 사진을 남깁니다. 움직임이 끝난 뒤의 장면을 찍습니다. 보고 글에는 사진의 파일 이름만 적고 폴더 경로는 적지 않습니다.
- 눌렀는데 반응이 없거나 늦은 곳, 글자가 잘리거나 겹치는 곳, 무엇을 눌러야 할지 알기 어려운 곳을 적습니다.
- 브라우저 콘솔에 오류가 나오면 그 글을 그대로 적습니다.

## 시나리오

1. 쪽이 열리면 맨 위의 고지 줄과 "사용자 원칙" 단추 넷을 봅니다. 단추를 하나씩 눌러 해당 구역으로 옮겨 가는지, 옮겨 간 뒤 구역 제목이 위 띠에 가려지지 않는지 봅니다.
2. "흐름도" 구역에서 장면 셋("주간 영업 주제 찾기와 응대 카드 배포", "상품 개정 건의와 경쟁사 비교 보고", "지점 문의에 대한 회신")을 차례로 고릅니다. 장면마다 걸음의 수와 이름이 바뀌는지, 고른 장면이 고른 것으로 보이는지 봅니다.
3. 장면 1에서 걸음을 처음부터 끝까지 하나씩 누릅니다("다음" 단추와 걸음 단추 둘 다 써 봅니다). 걸음마다 "누르는 것", "보이는 것", "다음에 갈 곳" 글이 바뀌는지, 아래 그림에서 지금 걸음의 탭이 어디인지 표시되는지, 번호 고리와 선이 걸음의 순서와 맞는지 봅니다. 마지막 걸음에서 "다음"이, 첫 걸음에서 "이전"이 어떻게 되는지 적습니다.
4. 장면 2와 장면 3도 끝까지 눌러 봅니다. 장면 3은 가운데에서 들어오는 길입니다. 세 길이 그림에서 서로 구별되는지 봅니다.
5. "탭마다 영역과 지금 자료로 되는 것" 표를 읽습니다. "된다"와 "안 된다" 표시가 구별되는지, 표의 긴 칸이 읽을 만한지 적습니다.
6. "브리핑 와이어프레임"에서 "틀로"와 "간편 1종 값으로"를 번갈아 누릅니다. 다섯 줄의 글이 바뀌는지, 줄마다 붙은 범위 표시("전체 고객군", "선택 종형")가 구별되는지 봅니다.
7. "시안 3에서 바뀌는 것과 그대로인 것"에서 거르기 단추 넷을 눌러 줄 수가 단추의 숫자와 맞는지 봅니다.
8. "일관성 규칙"과 "합의로 정한 것"을 훑고, "자세히"를 눌러 펼쳐지는지 봅니다.
9. 380 너비에서 2, 3, 6, 7을 다시 합니다. 가로로 밀리는 곳이 있는지, 흐름 그림이 좁은 폭에서 어떻게 보이는지 적습니다.

## 물음

- 처음 보는 영업 기획 담당자가 "이 화면은 어떤 순서로 쓰는가"를 30초 안에 말할 수 있겠습니까? 어디서 막혔습니까?
- 세 장면이 왜 따로 있는지 그림만 보고 알 수 있었습니까?
- 설명 없이는 뜻을 알기 어려운 말을 다섯 개까지 적어 주세요(예: 범위 띠, 근거 패널).
- 걸음을 누르는 동안 눈이 가야 할 곳(걸음 글, 그림)이 한 화면 안에 함께 보였습니까, 아니면 스크롤해야 했습니까? 창 크기별로 적어 주세요.

## 보고 형식 (마크다운)

1. 점수 표: 순서가 읽히는가, 누를 곳이 보이는가, 가독성. 각 5점 만점과 한 줄 이유.
2. 문제 표: 번호, 창 크기, 어디서(구역과 단추 이름), 무엇이(본 것 그대로), 얼마나 심한가(막힘, 불편, 사소), 사진 파일 이름.
3. 콘솔 오류: 있으면 글 그대로, 없으면 "없음".
4. 물음 넷의 답.
5. 확인하지 못한 것: 해 보지 못한 조작과 이유.
