# 요청 23. 열아홉 회사 시험 자료와 지금 화면에서 깨지는 곳 (Antigravity 개발 에이전트용 참고)

요청 22(정보를 층으로 나눠 보이기, 화면마다의 도형)의 "회사 수가 늘어도 되는 구성"을 확인할 때 쓰는 자료와 목록입니다. 따로 맡기는 일감이 아니라, 요청 22의 2단계부터 단계마다 함께 확인할 것입니다.

## 사람이 할 일

요청 22의 다음 단계를 시킬 때 이 한 줄을 덧붙입니다.

> `docs/gemini_requests/23_열아홉회사_시험자료와_깨지는곳_Antigravity.md`를 읽고, 이번 단계에서 고치는 탭은 가상 열아홉 회사 자료로도 합쳐서 깨지지 않는지 확인하라.

---

## 시험 자료 만드는 법

저장소 루트에서 한 명령입니다(파이썬 3.10 이상, 표준 라이브러리만 씁니다).

```
python scripts/dev/build_console4_synthetic.py
```

- 실제 두 회사(한화생명, 삼성화재)의 자료를 본떠 가상 생명보험사 9곳과 가상 손해보험사 8곳을 더합니다. 상대가 19곳, 우체국까지 20곳이 됩니다. 가상 회사의 이름은 "가상생명 01", "가상화재 01"처럼 가짜임이 보이게 되어 있고, 회사마다 고지 유형, 보유 담보, 면책과 감액, 가입나이가 조금씩 다릅니다.
- 결과는 `out/console4_synthetic.html`입니다(약 8.5MB). 맨 위에 "가상 자료(화면 배치 시험용, 실제 회사 자료 아님)" 표시가 붙습니다.
- `out/` 폴더는 커밋하지 않습니다(git 제외). 이 화면을 `site/` 아래에 두지 않습니다. 가상 회사의 값은 실제가 아니므로 공개하면 안 됩니다.
- `proto_src/console4/`의 원본은 건드리지 않습니다. 원본을 고친 뒤 이 명령을 다시 돌리면 고친 화면 코드로 가상 자료 화면이 만들어집니다.
- 회사 수를 바꿔 보려면 `--life`, `--nonlife` 인자를 씁니다(예: `--life 2 --nonlife 1`).

## 자료에 더해진 값 (Claude가 2026-11-23에 더함. 세 회사 자료에도 들어 있습니다)

- 지도 칸마다: `상대수`, `열린상대수`, `닫힌상대수`, `모르는상대수`, `관문만열린상대수`. 칸의 상태를 "열린 상대의 수"로 그릴 때 씁니다. 화면에서 회사별 상태를 다시 세지 않습니다.
- 범위(`기준별.<종형ID>.범위`)에 `업권별`: 생명보험과 손해보험의 회사 수와 상품 수.
- 브리핑 첫째 줄의 값에 `열린상대수분포`(칸마다의 열린 상대 수의 최솟값, 중앙값, 최댓값), 넷째 줄의 값에 `상대회사수`, `상대보유분포`.
- 회사 이름과 업권: 종형마다의 기관코드로 `d.json`의 `orgs`(회사 코드, 이름, 짧은 이름)를 찾습니다. 가상 자료에서는 20곳이 들어 있습니다.
- 문장: 회사나 종형 이름을 넷 이상 이어 쓰던 곳은 자료에서 "A, B, C 등 N곳"으로 줄여서 옵니다. 화면에서 다시 줄이지 않습니다.

더 필요한 집계가 있으면 화면에서 지어내지 말고 PR 글에 "자료에 필요한 값"으로 적어 주세요.

## 지금 화면에서 깨지는 곳 (2026-11-23, 가상 20곳 자료로 1920x1080, 1280x800, 380x780에서 잼)

콘솔 오류와 외부 요청은 없고 0.2초에 열립니다. 깨지는 것은 배치입니다.

모든 탭

- `core.js`의 회사 차례(`ORG_ORDER`)가 세 회사로 고정돼 있어 가상 17곳이 화면에서 빠집니다. 맨 위 "지금 고객군" 줄, 고객군과 시장의 "회사별 관문과 열린 종형", 가입 관문의 나무, 영업 인사이트, 응대 카드의 관문 줄이 이 값을 씁니다. 회사 목록은 자료에서 읽어야 합니다.
- "비교 상대" 줄이 이름 19개를 한 줄로 이어 씁니다. 범위 띠는 상대 19개의 상품을 다섯 줄로 모두 적습니다. 1280px에서는 접힌 요약 줄이 1,642px로 늘어 페이지가 가로로 414px 넘치고, 380px에서도 383px 넘칩니다.
- 화면 코드에 회사 수가 글자로 적혀 있습니다: "견준 세 회사 종형", "세 회사가 같아", "세 회사 모두", "세 회사 값", "상대 둘", "판정 칸 146개(담보 73줄, 상대 둘)". 수는 자료에서 읽어 적어야 합니다.

브리핑

- 치료 여정의 작은 막대에서 회사 이름이 한 글자씩 세로로 쪼개지고, 막대 열 20개가 카드 오른쪽 밖으로 나갑니다.
- 숫자와 단위가 겹치는 곳이 5건에서 13건으로 늡니다.

고객군과 시장

- 나이 열이 2개에서 8개로 늘어(회사마다 가입나이가 달라서) 열 머리와 작은 머리가 겹치고 칸의 글자가 세로로 쪼개집니다. 글 겹침이 3건에서 296건이 됩니다. 이것은 자료 쪽 문제이기도 합니다. Claude가 지도의 나이 열을 회사 수에 매이지 않게 고칠 예정이니, 화면은 열이 2~4개일 때를 기준으로 짭니다.
- 오른쪽 "회사별 관문과 열린 종형"은 세 회사만 적습니다.

가입 관문

- 관문 나무가 세 회사 세 갈래만 그리고 가상 17곳은 없습니다. 고지 질문 비교표는 3줄에서 20줄, "고지 차이" 카드는 상대마다 한 장씩 22장이 됩니다. 높이가 3,963px에서 7,693px(380px에서는 13,171px)입니다.

담보 비교 (가장 크게 깨집니다)

- 상품 비교표의 열이 6개에서 23개로 늘어 폭이 2,341px가 되고 페이지가 가로로 4,632px 넘칩니다. "가입금액의 100%"와 면책 일수가 겹칩니다(189건).
- 치료 여정의 범례는 실제 세 회사만 선 무늬가 있고 나머지는 이름만 있습니다.
- 오른쪽 "무엇을 견주나"가 종형 이름 19개를 모두 이어 씁니다.

영업 인사이트

- 높이가 6,354px에서 28,218px(380px에서는 47,936px)입니다. 상대마다의 관문 차이 카드가 늘어서입니다. 같은 뜻의 카드는 묶어야 합니다.
- 응대 카드 미리 보기가 A4 한 장을 넘습니다(약 1.2장).
