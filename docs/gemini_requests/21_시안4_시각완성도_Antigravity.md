# 요청 21. 시안 4의 시각 완성도 올리기: 신디케이트의 구성과 깊이 (Antigravity 개발 에이전트용)

2026-11-23에 정한 역할 나눔(화면의 구현과 개선은 Antigravity, 자료와 계산과 검수는 Claude)에 따른 첫 일감입니다. 사용자가 처음부터 바란 것은 어쌔신 크리드 신디케이트 메뉴 화면의 기하학적 구성, 유려한 스타일, 색 배치입니다. 지금 시안 4는 색과 선의 규칙은 지켰지만 인상은 거기에 못 미칩니다. 이 일감은 그 차이를 메우는 일입니다.

1. Claude가 "PR 2번(시안 4 수정)을 합쳤다"고 알린 뒤에 시작합니다. PC의 저장소에서 `git checkout main && git pull`로 맞춥니다.
2. 아래 가로줄 아래부터 끝까지를 Antigravity에 붙여 넣습니다.
3. 에이전트가 1단계(브리핑 탭)를 끝내면 PC에서 `site/proto/console4.html`을 브라우저로 열어 직접 보시고, 방향이 맞으면 "2단계를 하라"고 이어서 시킵니다. 방향이 다르면 본 느낌을 그대로 말해 주면 됩니다.

## Claude가 본 지금 시안과 기준 화면의 차이 (2026-11-23, 두 화면을 나란히 놓고 봄)

이 저장소의 시안 4(`site/proto/console4.html`, 원본 `proto_src/console4/`)의 시각 완성도를 올립니다. 먼저 `CLAUDE.md`, `proto_src/console4/API.md`, `docs/proposals/게임UI_기준표.md`의 10절을 읽으세요. 이용자는 보험사 본부의 영업 기획과 분석 담당자입니다.

## 기준 화면을 직접 봅니다

- 기준은 게임 어쌔신 크리드 신디케이트의 메뉴 화면입니다. 브라우저로 Steam 커뮤니티 허브의 이 게임(앱 번호 368500) 스크린샷 목록을 열어 메뉴 화면을 찾아봅니다: 진행 기록(PROGRESSION LOG, PROGRESS TRACKER), 일시 정지 메뉴, 기술(SKILLS), 갱 강화(GANG UPGRADES), 장비, 지도. 다섯 장 이상을 보고 구성을 적어 둡니다.
- 가져올 것은 구성의 문법입니다: 도형이 화면의 주인공이고 글은 적다, 고른 것의 설명은 옆 패널 하나에 모인다, 반투명 패널 너머로 바탕이 비친다, 제목은 크고 나머지는 작다, 금색과 빨강은 좁게 쓴다.
- 게임의 그림, 로고, 문장, 인물, 고유한 아이콘은 가져오지 않습니다. 화면 사진을 저장소에 넣지 않습니다.

## 반드시 지킬 것

1. 공개 저장소입니다. 비밀값, 사람 이름, PC의 폴더 경로를 어디에도 쓰지 않습니다.
2. 고칠 수 있는 파일은 `proto_src/console4/`의 `core.js`, `style.css`, `tab1.js`~`tab5.js`, `tab1.css`~`tab5.css`, `tab4.src.js`, `tpl.html`입니다. 자료 파일(`sales.json`, `combo.json`, `gate.json`, `cover.json`)과 `tab3.js`, `tab4.js`의 자료 부분은 손으로 고치지 않습니다. `tab4.js`는 `python proto_src/console4/gen_cover.py --assemble`로 다시 합칩니다. 그 밖의 `src/`, `scripts/`, `tests/`, `data/`, `.github/`, `docs/`(기록 파일 `docs/antigravity_log.md`는 예외), `site/index.html`은 건드리지 않습니다.
3. 숫자, 판정, 문장을 화면에서 지어내지 않습니다. 모두 자료에서 읽습니다. 문장을 줄여 보이고 싶으면 자료의 문장을 자르지 말고, 자료에 있는 값(칸 수, 건수, 분류 이름)으로 짧은 표시를 만들고 전체 문장은 근거 기둥에 그대로 보입니다.
4. 바꾸지 않는 것: 탭 다섯의 이름과 순서, 조건 줄, 범위 띠, 근거 기둥이라는 구조, 판정 칩 일곱의 뜻과 모양, 색의 규칙(빨강은 고른 것과 눈금과 원문 확인 표식에만, 판정에 쓰지 않음), 모서리 반경 0(고리와 원은 예외), 글꼴(한글 SUIT, 숫자 Saira Semi Condensed), 맨 위 고지와 `noindex`.
5. 읽기가 먼저입니다. 본문 글자는 13px 이상, 글자와 바탕의 명암비는 4.5 이상, 가로 넘침 0. 반투명 패널 위의 글자는 뒤 그림이 비쳐도 읽혀야 합니다(글자 뒤에는 무늬가 지나가지 않게 하거나 패널을 충분히 짙게).
6. 잰 값의 한도: 거의 흰 면은 화면 넓이의 10% 안쪽, 빨강은 2.5% 이하. `python proto_src/console4/shoot.py`가 잽니다.
7. 화면은 외부 요청이 없는 단독 HTML 한 파일입니다. 그림은 CSS와 인라인 SVG로만 그립니다. 바깥 그림 파일, 글꼴, 스크립트를 부르지 않습니다. 합친 파일은 2.6MB를 넘기지 않습니다.
8. 한국어 문장: 번역투를 쓰지 않고, 나열은 쉼표로 하며(가운뎃점으로 잇지 않음), 엠대시를 쓰지 않습니다.
9. `main`에 올리지 않습니다. `antigravity/console4-visual` 가지에 커밋하고 푸시해 PR을 엽니다. PR을 합치지는 않습니다. 한 일과 확인한 방법, 확인하지 못한 것을 `docs/antigravity_log.md` 맨 아래에 절로 더합니다.

## 할 일

### 1단계: 바탕과 브리핑 탭 (여기까지 하고 멈춥니다)

- 바탕의 깊이: 안개 그라데이션 위에 큰 기하 도형의 층을 만듭니다(인라인 SVG나 CSS). 예: 화면 아래 20%의 원근 격자를 더 또렷하게, 화면 한쪽에 기울어진 반투명 기둥이나 큰 사선 면 두셋, 먼 쪽이 흐려지는 격자. 글자가 놓이는 자리 뒤로는 무늬가 지나가지 않게 합니다. 패널은 뒤가 비치는 반투명으로 하되 5번의 명암비를 지킵니다.
- 브리핑의 주인공을 도형으로 바꿉니다. 지금 분석 요약 다섯 줄은 긴 문단입니다. 이것을 다섯 개의 큰 메달(지름 96px 이상의 고리나 다각형)로 바꿉니다. 메달마다 자료에서 읽은 대표 숫자 하나와 짧은 이름(고객군 지형, 개정과 시장, 가입 관문과 한도, 담보 포지션, 영업 인사이트), 범위 배지를 둡니다. 메달을 고르면 지금처럼 근거 기둥에 그 줄의 전체 문장과 식, 목록이 나옵니다. 처음 열었을 때는 첫 메달이 골라져 있어 문장이 바로 보이게 합니다. 전체 문장 다섯을 한 번에 읽고 싶은 사람을 위해 "문장으로 보기" 전환을 둡니다(지금의 목록 꼴).
- 메달의 대표 숫자는 각 줄의 `값`에서 고릅니다: 첫째 줄은 함께 열림 칸 수와 전체 칸 수, 둘째 줄은 개정으로 달라진 담보 수, 셋째 줄은 고지 질문 범위가 다른 상대 수, 넷째 줄은 견준 쌍과 공통 쌍, 다섯째 줄은 영업 인사이트 전체 수. 값의 열쇠 이름은 `sales.json`의 `기준별.<종형ID>.브리핑[].값`에서 직접 확인하고, 없는 값은 만들지 않습니다.
- 위쪽 지표 셋(고리)과 고객군 칸 띠는 메달 줄과 겹치는 정보입니다. 하나의 큰 구성으로 합칩니다. 고객군 24칸은 칸 하나가 20px 이상인 격자로 키워 지도처럼 보이게 합니다.
- 크기의 대비: 탭 제목을 48px 이상으로, 대표 숫자는 크게, 설명 글은 작고 적게.
- 색의 포인트: 금색은 "우체국에 있는 것, 채운 것"에 씁니다(예: 치료 단계 가운데 담보가 있는 단계, 우리 간편이 열리는 칸). 빨강은 고른 메달 하나에만 씁니다.
- 움직임: 탭이 열릴 때 메달과 격자가 차례로 놓이는 움직임(전체 600ms 안쪽), 고를 때 고리가 채워지는 움직임. "움직임 끔"에서는 바로 놓입니다. 움직임 도중에도 누를 수 있어야 합니다.
- 끝내는 기준: 1920x1080에서 브리핑 첫 화면의 절반 이상을 도형 구성이 차지하고, 긴 문단은 근거 기둥에만 있습니다. 1600x900, 1280x800, 380x780에서도 깨지지 않습니다. 콘솔 오류 0, 외부 요청 0, 가로 넘침 0, 6번의 한도 통과. 기준 종형 다섯을 모두 바꿔 보고 숫자가 자료와 같은지 확인합니다.
- 1단계가 끝나면 가지를 푸시해 PR을 열고, 무엇을 바꿨는지와 직접 본 기준 화면에서 무엇을 가져왔는지를 적고 멈춥니다.

### 2단계: 나머지 탭 (사람이 1단계를 보고 이어서 시킬 때)

(2026-11-23 덧붙임: 사용자가 1단계를 보고 방향을 더 잡았습니다. 이 2단계 대신 요청 22(`22_시안4_정보의층과_화면별도형_Antigravity.md`)를 씁니다.)

같은 문법을 탭마다 적용합니다. 탭마다 주인공 도형이 다르고, 첫 화면의 절반 이상을 차지하며, 긴 글은 근거 기둥으로 갑니다.

- 고객군과 시장: 지도 24칸을 큰 타일의 격자로. 칸 안에는 상태 기호와 숫자 하나만 두고 나머지는 근거 기둥으로 보냅니다. 상대가 관문만 수집한 종형으로만 열리는 칸의 표식은 유지합니다.
- 가입 관문: 세 회사의 관문 나무를 더 크게, 노드 사이의 선을 또렷하게. 열림, 심사로 확인, 닫힘, 자료 없음의 네 상태가 한눈에 갈리게 합니다.
- 담보 비교: 표는 표로 두고, 위에 치료 여정 격자(다섯 단계 곱하기 보장 분야)를 큰 타일로 둡니다. 우체국에 있는 칸은 금색, 없는 칸은 빗금.
- 영업 인사이트: 다섯 분류를 큰 타일 다섯으로, 고른 분류의 목록이 아래에 놓입니다. 응대 카드 미리 보기는 지금의 짙은 카드 그대로 둡니다.
