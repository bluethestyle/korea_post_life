# 요청 43. 관계 그래프 탭 3차 개선 검수 결과: 머지 전에 고칠 것 (Antigravity 개발 에이전트용)

분석 화면(`site/proto/console4.html`, 원본 `proto_src/console4/`)의 관계 그래프 탭 3차 개선이 브랜치 `claude/console4-graph-3`(PR "관계 그래프 탭 3차 개선", 13번)에 있습니다. 메인 세션이 재현 검수를 했고 머지를 보류했습니다. 아래 결함을 고치면 머지합니다.

- 통과한 것: 재빌드 결과가 커밋한 `site/proto/console4.html`과 같고, 용어 검사 0건, 전체 테스트 1,528 통과, 1 건너뜀, `graph_check.py` 기본 실행 상태 35개 실패 0개, 콘솔 오류와 외부 요청과 가로 오버플로 0, 다른 다섯 탭과 전체 요약은 `main` 빌드와 1920x1080, 1366x768에서 픽셀까지 같습니다. 조작 회귀도 없습니다: 실행 취소, 노드 클릭 선택(담보별 연결 79개, 종형 구성 96개, 시장 동향 40개 모두 실제 마우스 클릭으로 선택됨), 초기화가 필터와 선택을 함께 푸는 것, 범례 버튼, 필터 수와 번호 목록의 일치, 시장 동향의 빈 원 클릭.
- 머지를 막은 것: 번호 상자가 다른 담보를 가려 번호를 클릭하면 다른 담보가 선택되는 결함(1절 1번)과, 기준 해상도에서 남은 겹침과 누락(1절 2~6번).
- 이 문서의 수치는 Claude 쪽 서버에서 Playwright(Chromium)로 브랜치의 빌드 산출물(커밋 `b1688da`)을 열어 측정한 값입니다.
- **Antigravity 주간 한도가 약 8% 남았습니다.** 범위를 이 문서의 목록으로 좁히고, 1절의 번호 차례대로 고칩니다. 한도가 다하면 그때까지 고친 것을 커밋해 푸시하고, PR 글과 `docs/antigravity_log.md`에 어디까지 했는지와 남은 번호를 적습니다. 남은 것은 Claude 쪽에서 이어 고칩니다.

## 사람이 할 일

Antigravity에 이 지시를 넣습니다.

> `git fetch origin` 뒤 `git switch -c antigravity/graph-3-fix origin/claude/console4-graph-3` 로 브랜치를 만들고 `git merge origin/main` 을 한 다음, `docs/gemini_requests/43_관계그래프_3차개선_검수결과_보완_Antigravity.md` 를 읽고 1절의 번호 차례대로 고쳐 main 으로 가는 PR 을 연다. 한도가 다하면 거기까지 푸시하고 기록한다.

## 0. 출발 브랜치와 넘기는 방법

1. `git fetch origin` 뒤 `origin/claude/console4-graph-3`에서 브랜치 `antigravity/graph-3-fix`를 만듭니다.
2. 먼저 `origin/main`을 머지합니다(`git merge origin/main`). 3차 개선 브랜치가 갈라진 뒤 `main`이 더 나갔습니다. 첫 화면 배치 조정(위쪽 여백)과 우체국 상품 구성 변경의 화면 반영(통합건강보험 화면 제외, 기준 종형 기본값 변경, 보장 범위 한정 상품의 비교 범위)이 머지돼 `proto_src/console4/core.js`, `tab1.css`, `tab4.src.js`, `style.css`와 화면 자료가 바뀌었습니다.
   - `core.js`가 충돌하면 양쪽 변경을 모두 살립니다. 3차 개선 브랜치 쪽의 관계 그래프 문구 키(`gr*`)와 `window.App.legendIcon` 노출, `main` 쪽의 상품 구성 변경 반영을 하나도 빼지 않고 합칩니다. 어느 한쪽 파일로 통째로 덮지 않습니다.
   - `tab1.css`, `tab4.src.js`, `style.css`와 화면 자료는 3차 개선 브랜치가 고치지 않은 파일이므로 `main` 쪽 그대로 둡니다.
   - 빌드 산출물 `site/proto/console4.html`이 충돌하면 손으로 합치지 말고 원본 충돌을 푼 뒤 `python proto_src/console4/build.py`로 재빌드해 그 결과를 커밋합니다.
   - 머지 뒤 `python -m pytest -q`와 `python proto_src/console4/graph_check.py`를 한 번 실행해 머지 자체로 깨진 것이 없는지 먼저 봅니다.
   - **수치에 대한 주의**: 이 문서의 수치는 머지 전 3차 개선 브랜치(기준 종형 기본값 1종)에서 측정한 값입니다. 머지하면 기준 종형 기본값과 화면 자료가 바뀌어 기본 화면의 그룹 구성, 담보 수, 필터 수가 달라질 수 있습니다. 1절의 끝내는 기준은 머지한 화면에서 기본 기준 종형과 1종 두 경우에 적용하고, 기록에는 머지 뒤의 그룹과 필터 수를 함께 적습니다. 결함을 먼저 재현해 보려면 머지 전 브랜치의 빌드 산출물(`git show origin/claude/console4-graph-3:site/proto/console4.html`을 저장소 밖에 저장)에 3절의 스크립트를 실행합니다.
3. 끝나면 `main`으로 가는 PR을 엽니다. 이 PR이 3차 개선 PR을 대신합니다(메인 세션이 이 PR을 머지하고 3차 개선 PR은 닫습니다). `main`에 직접 푸시하지 않고, `claude/console4-graph-3`에도 푸시하지 않습니다.

## 1. 고칠 것 (우선순위순 6건)

화면의 기준 해상도는 사무용 모니터 1920x1080, 1600x900, 1366x768, 1280x800입니다. 아래에서 "그룹 일곱 개"와 "필터 전부"는 다음을 말합니다.

- 그룹 일곱 개(담보별 연결 보기, 기준 1종, 비교 범위 전체): 우체국만 보유(6), 우체국, 한화생명 보유(1), 모두 보유(14), 우체국, 삼성화재 보유(4), 한화생명만 보유(12), 한화생명, 삼성화재 보유(32), 삼성화재만 보유(10). 괄호는 담보 수입니다. 그룹 이름표는 `#gr-net-svg .gr-lb-g[data-gr-glabel="<그룹 키>"]`이고, 그룹 키는 `EPOST`, `EPOST,HANWHALIFE`, `EPOST,HANWHALIFE,SAMSUNGFIRE`, `EPOST,SAMSUNGFIRE`, `HANWHALIFE`, `HANWHALIFE,SAMSUNGFIRE`, `SAMSUNGFIRE`입니다. 이름표 안의 `.gr-lb-hit`을 클릭하면 그룹이 선택됩니다.
- 필터 전부: 왼쪽 패널에서 켤 수 있는 필터 11개(`[data-gr-filter]`). 단순 비교 불가(`f:diff`, 9), 관련 담보로 보장(`f:rel`, 19), 검수 대기(`f:wait`, 23), 보유 구분 셋(`cls:only`, `cls:shared`, `cls:peer`. 타사만 보유는 54), 보장 대분류 다섯(`dom:암보장`, `dom:뇌혈관보장`, `dom:뇌심장보장`, `dom:심장보장`, `dom:공통보장`). 우위와 열위는 0건이라 비활성이므로 뺍니다.

### 1번. 번호 상자와 지시선의 겹침 (기능 결함 포함)

- **현상**: 그룹을 선택했거나 필터를 켰을 때 대상 담보에 붙는 번호 상자(`.gr-cl-num`)가 다른 담보 노드, 회사 앵커, 이름표를 가립니다.
  - 1366x768, 그룹 "한화생명, 삼성화재 보유"에서 번호 21 상자(`.gr-cl-num[data-gr-for="STD_CV_TX_THROMBECTOMY"]`, 상자 좌표 [795, 641, 820, 666])를 클릭하면 번호가 가리키는 담보(뇌·심장질환 혈전제거술 치료비)가 아니라 상자에 가려진 다른 담보(재진단암 진단비, 중심 (807, 661))가 선택됩니다(`App.state.sel.graph`가 `n:STD_CA_DX_RECUR`, 상세 패널 제목 "재진단암 진단비"). 1280x800에서도 같은 번호 21이 유방암 수술비 쪽(`n:STD_CA_SURG_BREAST`)을 선택합니다. 1920x1080과 1600x900에서는 이 그룹의 번호 32개가 모두 제 담보를 선택합니다. 그룹 일곱 개의 번호 상자 69개를 전부 클릭하면 1920x1080은 69/69, 1366x768은 68/69가 제 담보를 선택합니다. 같은 1366x768에서 그룹 안 노드 중심을 클릭했는데 지시선이나 번호 상자에 가로막히는 곳도 1건 있습니다.
  - 1366x768, 그룹 "한화생명만 보유": 번호 10 상자가 한화생명 앵커(간편가입형(1년)) 원과 "한화생명" 이름표를 가리고, 번호 1 상자가 자기 노드(소액암 진단비)의 중심을 가려 노드 모양이 보이지 않습니다.
  - 1366x768, 필터 "타사만 보유(우체국 미보유)"(번호 54개): 번호 46, 53이 삼성화재 앵커 원을, 47이 삼성화재 앵커 이름표 글자를 가리고, 33, 48 등 3건이 다른 노드를 가립니다.
  - 1920x1080: 그룹 "모두 보유"(14개)의 5번 지시선(`line.gr-cl-lead`)이 "모두 보유" 그룹 이름표 글자 위를 지납니다. 그룹 "한화생명만 보유"의 번호 1이 자기 노드를 가리고, 필터 단순 비교 불가, 검수 대기, 우체국과 타사 보유, 타사만 보유에서 번호 상자가 다른 노드를 가리는 곳이 상태마다 1~2건 있습니다.
- **해상도별 측정값** (그룹 일곱 개와 필터 다섯(`f:diff`, `f:rel`, `f:wait`, `cls:shared`, `cls:peer`) 12개 상태의 합계):

| 해상도 | 번호 상자가 다른 담보 노드를 가림 | 지시선이 다른 이름표나 번호 상자를 지남 (걸린 상태 수) |
| --- | --- | --- |
| 1920x1080 | 2 | 15 (6개 상태) |
| 1600x900 | 0 | 23 (8개 상태) |
| 1366x768 | 4 | 31 (9개 상태) |
| 1280x800 | 8 | 34 (9개 상태) |

- **추정 원인과 코드 위치** (브랜치 `claude/console4-graph-3`의 `proto_src/console4/tab6.js` 행 번호, 코드로 확정하지 못한 부분이 있음):
  - `callObstacles`(1725행)가 피할 것으로 앵커 상자, 그룹 이름표, 그룹 원, 앵커 원, 번들 엣지, 그룹 이름표 지시선만 넣습니다. 담보 노드(`lay.npos`)와 담보 이름표(`lay.slabels`), 자기 노드는 넣지 않아 번호 상자가 노드 위에 놓일 수 있습니다.
  - `placeCallNums`(1801행)는 지시선 조건까지 채우는 자리가 없으면 상자만 겹치지 않는 자리(1839행), 그것도 없으면 겹침이 가장 적은 후보(1841~1846행)에 두고 `misses`만 셉니다. 이 대안 자리에서는 지시선 검사(`callLeadOk`)를 하지 않아 지시선이 이름표 글자를 지납니다. 후보 반지름(`ext` 0~80px)과 각도(±0.3rad)가 좁아 큰 그룹이나 54개 필터에서 대안으로 자주 넘어가는 것으로 보입니다.
  - 클릭 판정 `netHit`(2033행)은 담보 노드(반지름+4px, 최소 12px)를 먼저 찾고 번호 상자(`net.callShown`)는 그다음에 봅니다. 그래서 번호 상자가 노드 위에 있으면 노드가 선택됩니다.
- **고치는 방향** (예시, 다른 방법이어도 됩니다): 피할 것에 모든 담보 노드 원(자기 노드 포함)과 담보 이름표, 보장 대분류 집계 칩 자리를 넣고, 후보 범위를 넓히고, 대안 자리에서도 지시선 검사를 합니다. 클릭 판정에서는 번호 상자 안을 클릭하면 번호 상자의 담보를 먼저 고릅니다. 번호 상자를 둘 자리가 정말 없을 때 겹치게 두지 말고 그 사실을 `misses`로 세어 `graph_check.py`가 실패로 잡게 합니다.
- **끝내는 기준**: 네 해상도에서 그룹 일곱 개와 필터 전부(11개)에 대해 모두 0 또는 100%입니다.
  1. 번호 상자가 다른 담보 노드, 회사 앵커 원, 이름표(앵커 이름표, 그룹 이름표, 담보 이름표, 보장 대분류 집계 칩, 다른 번호 상자)와 겹치는 곳 0.
  2. 번호 상자가 자기 노드의 중심을 가리는 곳 0.
  3. 번호 상자 중심을 실제 마우스로 클릭했을 때 그 번호의 담보(`data-gr-for`)가 선택되는 비율 100%. 그룹 안 노드 중심 클릭이 그 노드를 선택하는 비율도 100%.
  4. 지시선이 이름표 글자(위 1의 이름표 전부)와 다른 번호 상자를 지나는 곳 0.
  5. 상세 패널 목록의 번호와 그래프 번호가 지금처럼 1..n 연속이고 담보 이름이 전수 일치.
- **`graph_check.py`에 넣을 것**: 위 1~4의 검사를 `proto_src/console4/graph_check.py`에 넣어, 네 해상도에서 그룹 일곱 개와 필터 전부를 차례로 켜고 건수를 결과 JSON에 적고 0이 아니면 요약 판정의 실패(`fails`)로 올립니다. 번호 상자와 이름표의 좌표는 `data-gr-lb`와 `data-gr-lbox` 속성(번호 상자는 `data-gr-lb="num"`), 지시선은 `line.gr-cl-lead`의 `x1, y1, x2, y2`, 노드는 지금 `SCREEN_JS`가 읽는 좌표로 읽을 수 있습니다. 판정은 이 파일에 이미 있는 `rect_overlap`, `seg_rect`, `rect_circle`을 씁니다. 클릭 비율 검사는 시간이 걸리면 1920x1080과 1366x768만 해도 됩니다(어느 쪽으로 했는지 기록). 3절의 스크립트는 1~3 가운데 클릭 검사만 하는 재현용입니다.

### 2번. 대상이 적을 때의 이름표

- **현상**: 지시는 "대상이 적으면 그룹 원 바깥에 이름표와 지시선, 많으면 번호"였는데, 이름표 분기(`placeCallNames`, 1756행, `CALL_NAME_MAX = 8`, 1696행)가 한 번도 쓰이지 않습니다. 대상이 8개 이하인 그룹 우체국만 보유(6), 우체국, 한화생명 보유(1), 우체국, 삼성화재 보유(4)와 필터 우체국만 보유(6)도 네 해상도 모두 번호로만 나옵니다(`.gr-l-cb` 안에 `.gr-cl-nm` 0개, `.gr-cl-num`만 있음). 1개짜리 그룹도 번호 1과 상세 패널 목록을 함께 봐야 합니다.
- **고칠 것**: 둘 가운데 하나를 고릅니다.
  - 가. 대상이 적은 그룹과 필터에서 이름표가 나오게 합니다. 끝내는 기준: 네 해상도에서 대상 8개 이하인 상태(위 네 상태)가 모두 이름표 방식이고, 이름표에 1번의 끝내는 기준 1, 3, 4를 그대로 적용해 0 또는 100%입니다(이름표 클릭은 그 담보를 선택). 이름표 방식일 때도 상세 패널 목록은 지금처럼 나옵니다.
  - 나. 화면에서 이름표가 겹쳐 쓸 수 없다면 이름표 분기를 지우고 번호 방식 하나로 정리합니다. 지울 것: `placeCallNames`, `CALL_NAME_MAX`, `calloutPlan`(1715행)의 분기, `calloutSVG`(1854행)의 `mode === 'name'` 분기, `netHit`와 CSS의 `.gr-cl-nm` 규칙, 1692~1695행 주석의 이름표 설명. 지운 뒤에도 1번의 끝내는 기준을 지킵니다.
- 어느 쪽을 골랐는지와 그 이유(가를 시도했다면 어떤 상태에서 겹쳤는지 수치)를 PR 글과 기록에 적습니다.

## 3. 재현 스크립트 (번호 상자 클릭)

스크립트를 저장소 밖의 임시 폴더에 `check43.py`로 저장하고 저장소 루트에서 실행합니다(`python <임시 폴더>/check43.py`). Playwright(Chromium)가 필요합니다. 스크립트와 출력은 커밋하지 않습니다. 상태마다 페이지를 다시 열어 번호 상자 하나씩 실제 마우스로 클릭하므로 상태 하나에 해상도마다 1~3분 걸립니다.

```python
import asyncio, sys
from pathlib import Path
from playwright.async_api import async_playwright
# 쓰기: python check43.py [HTML 경로] [상태] [해상도들]
#   상태: g:<그룹 키> 또는 f:<필터 키>. 기본은 그룹 "한화생명, 삼성화재 보유"
#   예: python check43.py site/proto/console4.html f:cls:peer 1366x768
HTML = sys.argv[1] if len(sys.argv) > 1 else 'site/proto/console4.html'
STATE = sys.argv[2] if len(sys.argv) > 2 else 'g:HANWHALIFE,SAMSUNGFIRE'
SIZES = [tuple(map(int, s.split('x'))) for s in (sys.argv[3] if len(sys.argv) > 3 else '1920x1080,1600x900,1366x768,1280x800').split(',')]
URL = Path(HTML).resolve().as_uri() + '#t=graph'
NUMS = "() => [...document.querySelectorAll('#gr-net-svg .gr-cl-num')].map(e => { const r = e.querySelector('rect').getBoundingClientRect(); return {n: e.textContent.trim(), id: e.dataset.grFor, x: r.left + r.width / 2, y: r.top + r.height / 2}; })"
async def open_state(pg):
  await pg.goto(URL)
  await pg.wait_for_function("() => !!document.getElementById('gr-net-svg')", timeout=15000)
  await pg.wait_for_timeout(800)
  kind, key = STATE.split(':', 1)
  if kind == 'g':
    await pg.locator(f'#gr-net-svg .gr-lb-g[data-gr-glabel="{key}"] .gr-lb-hit').click()
  else:
    await pg.locator(f'[data-gr-filter="{key}"]').click()
  await pg.wait_for_timeout(600)
async def main():
  async with async_playwright() as p:
    b = await p.chromium.launch()
    for w, h in SIZES:
      pg = await b.new_page(viewport={'width': w, 'height': h})
      await open_state(pg)
      nums = await pg.evaluate(NUMS)
      bad = []
      for it in nums:
        await open_state(pg)
        await pg.mouse.click(it['x'], it['y'])
        await pg.wait_for_timeout(300)
        sel = await pg.evaluate("() => (App.state.sel || {}).graph || ''")
        if sel != 'n:' + it['id']:
          bad.append((it['n'], it['id'], sel))
      print(f'{STATE} {w}x{h} 번호 {len(nums)}개, 클릭 결과가 다른 번호 {len(bad)}개', bad)
      await pg.close()
    await b.close()
asyncio.run(main())
```

3차 개선 브랜치(커밋 `b1688da`)의 빌드 산출물에서 기본 상태로 실행한 출력입니다.

```
g:HANWHALIFE,SAMSUNGFIRE 1920x1080 번호 32개, 클릭 결과가 다른 번호 0개 []
g:HANWHALIFE,SAMSUNGFIRE 1600x900 번호 32개, 클릭 결과가 다른 번호 0개 []
g:HANWHALIFE,SAMSUNGFIRE 1366x768 번호 32개, 클릭 결과가 다른 번호 1개 [('21', 'STD_CV_TX_THROMBECTOMY', 'n:STD_CA_DX_RECUR')]
g:HANWHALIFE,SAMSUNGFIRE 1280x800 번호 32개, 클릭 결과가 다른 번호 1개 [('21', 'STD_CV_TX_THROMBECTOMY', 'n:STD_CA_SURG_BREAST')]
```

Claude 쪽에서 출력을 확인한 것은 그룹 상태(`g:`)뿐입니다. 필터 상태(`f:`)로 실행했을 때 서버 부하로 페이지를 다시 여는 대기(15초)가 시간 초과로 끝난 적이 있으니, 같은 오류가 나면 `timeout` 값을 늘려 실행합니다. 머지 뒤 화면에서는 그룹 키와 번호가 달라질 수 있으므로 그룹 이름표의 `data-gr-glabel` 값을 확인하고 넣습니다.

고친 뒤에는 네 해상도 모두 "클릭 결과가 다른 번호 0개"여야 합니다. 2번에서 이름표 방식을 살렸다면 이름표(`.gr-cl-nm`)도 같은 방법으로 클릭해 봅니다.

## 5. 확인 방법

1. `python proto_src/console4/build.py`로 재빌드하고 결과를 커밋합니다. 다시 빌드해도 `git status`가 깨끗해야 합니다.
2. `python proto_src/console4/graph_check.py`(기본 네 해상도): 1번에서 더한 검사를 포함해 실패 0개. 결과 JSON의 상태 수와 실패 수를 기록에 적습니다.
3. `python proto_src/console4/shoot.py <폴더>`: 가로 오버플로 0px, 콘솔 오류 0, 외부 요청 0.
4. `python proto_src/console4/terms_check.py --built`: 0건.
5. `python -m pytest -q`: 실패 0, 통과 수를 기록에 적습니다(3차 개선 브랜치는 1,528 통과, 1 건너뜀).
6. 조작이 그대로 동작하는지 봅니다: 실행 취소(첫 선택 전 비활성, 선택 뒤 활성, 누르면 직전 상태), 노드 클릭 선택(담보별 연결, 종형 구성, 시장 동향의 노드 중심 실제 마우스 클릭), 초기화가 켜 둔 필터와 선택을 함께 푸는 것, 시장 동향 전체 필터의 채움 없는 빈 원 가운데 클릭으로 선택되는 것, 범례 접기 버튼과 오른쪽 위 범례 버튼이 같은 상태(`aria-expanded`)로 움직이는 것.
7. 다른 다섯 탭과 전체 요약의 캡처가 고치기 전과 같습니다(1920x1080, 1366x768).
8. 1절 각 번호의 끝내는 기준을 측정한 표(고치기 전과 후)를 기록에 적습니다. 측정 방법(어떤 스크립트, 어떤 상태와 해상도)도 함께 적습니다.
