> **처리 상태: 2026-11-25 에 Claude 쪽에서 처리했으므로 Antigravity 에 넣지 않습니다.** Antigravity 주간 한도가 9% 남아 작은 수정은 Claude 가 직접 하기로 했습니다. 아래 1~4절을 그대로 기준으로 삼아 고쳤고, 결과는 6절에 적었습니다(커밋 `0418080`).

- 검수 방법: 네 편을 Manim `-qm`(1280x720, 30fps)으로 렌더링하고 1초 간격 프레임과 의심 구간의 더 촘촘한 프레임을 직접 봤습니다. 렌더링 오류와 `[BOUNDS WARNING]`은 0건이었습니다.
- 처음에는 우선순위가 낮은 요청으로 분석 화면 쪽 요청 40, 37, 38 다음에 맡길 예정이었습니다. Claude 쪽에서 처리했으므로 이 순서는 더 이상 해당하지 않습니다.

시각은 `-qm` 렌더링 기준이고, 아래 "지금 모습"은 해당 시각의 프레임을 보고 적었습니다. 코드 위치는 파일과 함수 이름으로 적었습니다.

## 2. 푸시 전 자체 확인

요청 39의 4절과 같은 방법입니다. 프레임 추출 스크립트 `scripts/dev/extract_video_frames.py`는 수정하지 않고 실행만 합니다(PyAV가 필요하므로 Manim 가상환경의 python으로 실행).

```bash
python scripts/dev/extract_video_frames.py <2편 mp4> <출력 폴더>/part2_fix --step 0.25 --start 22 --end 31
python scripts/dev/extract_video_frames.py <4편 mp4> <출력 폴더>/part4_fix --step 0.25 --start 95 --end 98.5
# 고치기 전과 후를 1초 간격 전체로 뽑아 고친 구간 밖의 프레임을 비교
python scripts/dev/extract_video_frames.py <mp4> <출력 폴더>/<before|after>
```

인자는 mp4 경로, 출력 폴더, `--step`(기본 1초), `--start`, `--end`(초)입니다. 파일 이름은 `t_030.0.jpg`처럼 시각입니다. 출력 폴더는 저장소 밖에 두고 커밋하지 않습니다.
