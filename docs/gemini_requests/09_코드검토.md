# 요청 9. 추출·검증 코드 검토

대상: 공개 저장소 https://github.com/bluethestyle/korea_post_life (Gemini 웹에서 "코드 가져오기"로 불러옵니다)

보험 상품요약서·사업방법서에서 급부와 가입조건을 뽑아 검증하는 파이프라인입니다. 모델은 글자만 옮기고, 코드가 숫자로 바꾸고 원문과 대조하며, 판정 모델이 확률을 매깁니다. 아래 파일을 읽고 **틀린 값을 조용히 통과시키거나 맞는 값을 버릴 수 있는 곳**을 찾아 주세요. 문체·이름 짓기 같은 취향 문제는 적지 않습니다.

읽을 파일 (우선순위 순)
1. src/postlife/extract/benefits.py — 금액·기간 글자를 숫자로 바꾸는 함수(parse_money, parse_months, period_token, money_token), 보장개시일 날수(waiting_definitions, waiting_days_of, plain_start_in), 원문 대조(literal_problems, limit_in_source, limit_is_partial, _with_cell_notes), 행 만들기(benefit_rows)
2. src/postlife/extract/verify.py — 판정 문항(checks), 구간 나누기(classify)
3. src/postlife/extract/pipeline.py — 재추출 흐름(run_block), 가입유형별 부분 나누기(run_summary)
4. src/postlife/extract/segment.py — 조각 자르기(rider_blocks, scope_parts, scope_matches, renewal_periods)
5. src/postlife/extract/conditions.py, conditions_run.py — 가입나이·한도·결합 제약
6. src/postlife/extract/tables.py — PDF 표를 담보 단위로 묶기
7. src/postlife/ids.py, src/postlife/validate.py, src/postlife/sheets_io.py

특히 봐 주면 좋은 것
- 숫자 읽기: 어떤 글자가 들어오면 다른 금액·기간으로 읽히는가. (예: 최근에 "2.5만원"을 5만원으로 읽던 오류를 고쳤습니다. 비슷한 것이 더 있는지)
- 정규식: 글자가 줄바꿈·쉼표·따옴표로 갈렸을 때 놓치거나 엉뚱한 곳에 맞는 경우
- 원문 대조가 "있다"고 잘못 답하는 경우(다른 급부의 같은 글자에 맞는 경우 등)
- ID(특약계보키·급부ID)가 서로 다른 것을 같게 만들거나 같은 것을 다르게 만드는 경우
- 시트 쓰기에서 자료가 사라질 수 있는 순서

답은 표 하나로 주세요. 확신이 없는 것은 "추정"이라고 적습니다.
