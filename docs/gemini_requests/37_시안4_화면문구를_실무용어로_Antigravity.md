### 3-3. 문구와 함께 고칠 코드

문구만 바꾸면 동작이 달라지는 곳입니다. 5-5의 함정 1, 2도 이 절의 키에서 생깁니다.

1. `core.js` 483~485라인 `countWord`: 회사 수를 "개사"로 세므로 2와 3을 "두", "세"로 바꾸지 않고 숫자만 반환합니다(`return fmt(n);`). `wordTwo`, `wordThree`를 지우고, `sameCountSuffix`(71라인)도 다른 곳에서 쓰지 않으므로 지웁니다. 결과 예: "3개사 동일", "자료 있는 2개사 동일".
2. `core.js` 1181~1182라인 `SINCE_OPTS`: 이력 없음 선택지의 글자를 `condNoHist` 대신 새 키 `condNoHistShort`("이력 없음")로 씁니다. 선택지의 그룹 제목이 "최종 입원·수술 시점"이라 짧은 표기를 씁니다(대조표 52번). 조회 조건 요약과 토스트(`core.js` 750, 1205, 1216라인)는 `condNoHist`("입원·수술 이력 없음")를 그대로 씁니다.
3. `core.js` 401라인 `MAP_KEY`: 지금은 `condRenAll`, `condRenRenew`, `condRenNon`의 문구를 `S['지도']`의 키로 씁니다. 문구가 "갱신형", "비갱신형"으로 바뀌면 갱신 유형 필터가 전체 현황으로 떨어집니다. 키는 자료의 글자로 고정합니다: `{ null: '전체', '갱신': '갱신', '비갱신': '비갱신' }`(5-5의 함정 1).

## 4. 탭 파일에 직접 적힌 문자열

대조표 2-2에서 센 파일들에, 이 문서에서 찾은 3건, 확정 이름으로 정한 2건, 비교역할 표시 1건, 1절 4번에서 정한 말 2건(`tab4.src.js` 984 "갈림", `proto_src/graph/tpl.html` 678 "길 찾기")을 더했습니다(비고 "추가한 행"). `tab3.js` 405라인은 키와 같은 글자라 두 행으로 나눴습니다. 옮기는 방법은 이렇습니다.

- `tab1.js`부터 `tab6.js`(`tab4.js`는 원본 `tab4.src.js`)와 `tpl.html`의 화면 문자열은 문구 표 `COPY`로 옮긴 다음 새 문자열로 고칩니다. 키 이름은 탭별 접두어를 씁니다(예: `tab3.js`는 `gt`, `tab4.src.js`는 `cv`, `tab5.js`는 `ins`, `tab6.js`는 `gr`). 문구 표로 옮길 때 `App.TERM.x`는 `TERM.x`로, `App.label(...)`은 `label(...)`로 적습니다. 모두 옮기기 어려우면 이 표에 있는 문자열부터 옮기고, 옮기지 못한 것은 PR 글에 파일과 라인을 적습니다.
- `tpl.html`은 화면이 열리기 전에 보이는 글자라 제자리에서 고치되, 같은 말이 `COPY`에 있으면 글자를 맞춥니다.
- **키로 쓰는 값과 같은 글자는 행을 한정해 바꿉니다.** 지금 문자열은 표에 적힌 라인(요청 35로 라인이 밀렸으면 같은 문맥의 그 라인) 한 곳에서만 바꾸고, 파일 전체를 한 번에 찾아 바꾸지 않습니다. 같은 글자가 다른 라인에서 키(5-5)로 쓰이거나 다른 행의 더 긴 지금 문자열 안에 들어 있기 때문입니다. 비고에 "이 행에서만 바꿈"이라고 적은 행은 지금 문자열이 같은 파일의 키와 같은 글자인 행입니다. 그 라인 안에 같은 문자열이 둘 이상 있으면 둘 다 화면 글자인지 확인한 뒤 바꿉니다(표의 행은 모두 확인했습니다).
- `proto_src/graph/tpl.html`(관계망 시안 2, `site/proto/graph2.html`)은 문구 표가 없는 별도 화면이라 제자리에서 고칩니다. 데이터 쪽 머지로 `graph.json`의 노드 종류와 엣지 종류 이름이 바뀌어 화면 글자가 자료와 어긋나므로 같은 용어로 맞춥니다.
- 새 문자열에 확정 이름이 들어가는 곳은 `App.TERM.*`를 넣었습니다. 템플릿 안에서는 `${App.TERM.talk}`(HTML을 만드는 라인은 `${esc(App.TERM.talk)}`), 작은따옴표 문자열 안에서는 `' + App.TERM.talk + '`처럼 문자열을 이어 붙입니다. 문구 표로 옮기면서 템플릿으로 다시 써도 됩니다.
- `tab1.js`와 `core.js`(문구 표 밖)에는 바꿀 화면 문자열이 없습니다. 두 파일에서 지금 용어가 든 문자열은 모두 키로 쓰는 값이고 5-5의 목록에 있습니다. 두 파일에서 키 값을 화면에 내는 자리는 5-6의 표 1에 있습니다.

화면 코드가 조건문, 아이콘 맵, CSS 클래스 맵, 탭 이동, 집계의 키로 쓰는 값은 자료에서 바꾸지 않았습니다. 화면에 보일 이름은 아래 표에서 읽습니다. 아래 값은 지금 `main`의 자료 파일에서 스크립트로 옮겨 적었고 글자까지 같습니다.

| 위치 | 형식 | 내용 |
| --- | --- | --- |
| `sales.json`(`App.S`) 최상위 `표시명` | 평면 맵 `{값: 화면 이름}` 53개 | 가입 가능 상태, 현황 표 라벨, 행 종류, 판정 값, 판정 집계 키, 판정 이름, 영업 인사이트 분류, 영업 인사이트 세부 코드, 비교역할, 탭, 개정 종류 |
| `graph.json` 최상위 `표시명` | 같은 평면 맵(지금 `main` 9개) | 비교역할(관문전용, 직전개정시연), 미연결사유(대기, 대상외), 매핑 판정(passed, below, undecided), 속성 이름(검토상태), 개정 종류(종료) |
| `cover.json`(`tab4.js`의 `CV`) `판정표[사유].표시명` | 문자열 필드 | 판정표 항목마다 `판정`(키) 옆의 화면 이름 |
| `graph.json` `kinds`, `ekinds` | 배열(번호 순서 그대로) | 종류 이름 자체를 화면 이름으로 실었다(화면은 종류를 번호로 다룬다) |

평면 맵인 이유: 같은 값이 구분마다 다른 이름을 가져야 하는 경우가 없습니다. 예를 들어 `검토 대기`는 판정 집계 키, 판정 이름, 셀(`칸`)의 분류수 키 어디서나 "검수 대기"이고, `같음`은 판정 값과 판정 이름 모두 "동일"입니다. 표에 없는 값은 값 그대로 보입니다. 판정표의 `표시명`은 언제나 `S['표시명'][판정표[사유].판정]`과 같습니다(Claude가 11항목 모두 확인).

### 5-2. 이름을 정하는 곳: 자료에서 읽는 이름과 문구 표에 적는 이름

같은 이름을 자료와 화면 코드에 따로 적으면 한쪽만 바뀌어 어긋납니다. 이름마다 정하는 곳을 하나로 둡니다.

| 이름 | 정하는 곳 | 화면 코드에서 쓰는 법 |
| --- | --- | --- |
| 상품-영업 분석, 관계 그래프, 고객군별 가입 가능 현황(짧은 표기 가입 가능 현황), 응대 화법 | 자료에 없음. `core.js`의 `TERM` 상수에 한 번만 적는다 | `COPY`는 `TERM.app` 따위를 끼우고, 탭 파일은 `App.TERM.*`. `tabGraph`, `grEvTitle`은 `TERM.graph`, `TAB_NAME.graph`는 `cp('tabGraph')` |
| 요약, 인수기준 비교(탭) | 자료 표시명(`브리핑`, `가입 관문`) | `TAB_NAME`은 `label(S['탭'][i])`. 문장 안은 `TERM.brief`, `TERM.gate` 또는 `App.TAB_NAME.gate` |
| 단순 비교 불가 | 자료 표시명(`단정 주의`, `우열을 매기지 않음`) | 판정 칩은 `verdictName(사유)`와 `label('우열을 매기지 않음')`(5-4). 목록 이름과 문장은 `TERM.noCompare` |
| 영업 인사이트 분류 다섯(인수기준 차이, 우위 담보, 관련 담보, 열위 담보, 미보유 담보) | 자료 표시명(분류 키) | 분류 키를 낼 때 `App.label(p['분류'])`. 문장과 제목 안은 `TERM.catGate`, `TERM.catStrong`, `TERM.catRel`, `TERM.catWeak`, `TERM.catMiss` |
| 영업 인사이트 세부 여덟 | 자료 표시명(G1~Q3) | `App.label(코드)`. 코드 글자는 화면에 내지 않는다 |
| 판정 이름과 판정 칩 | 자료(`판정표`의 `표시명`, 판정 이름의 표시명) | `verdictName(사유)`, `App.label(판정 이름)`. `vd` 키 여섯은 `label(판정 이름 키)` |
| 가입 가능 상태, 현황 표 라벨, 행 종류(통원수술), 비교역할, 개정 종류(삭제), 미연결사유, 속성 이름 | 자료 표시명 | `App.label(값)`(5-6) |
| 미확인(판정 칩 `unknown`의 기본 이름) | 자료에 없음. `COPY.vdUnknown` | 그대로 |
| 짧은 표기(가능, 제한, 함께 가능, 동향, 대분류 따위) | 자료에 없음. `COPY.shortLabel` | `App.short(값)`(5-7) |

- 문장 속의 일반 용어(가입 가능, 가입 제한, 검수 대기, 우위, 열위, 상이, 일반심사 대상, 관련 담보로 보장 따위)는 대조표 확정안을 글자로 적습니다. 이 글자는 이름이 아니라 서술이고, 자료의 표시명과 띄어쓰기까지 같게 적었습니다(Claude가 표시명 44개와 대조해 어긋남 0건).
- "관련 담보"는 분류 이름이면서 일반 용어(관련 담보로 보장, 관련 담보 있음)이기도 해서 6-2의 이름 검사에 넣지 않았습니다. 분류 이름으로 쓰는 곳(`tab5.js` 593라인)만 `TERM.catRel`을 씁니다.
- 조사는 지금 이름에 맞춰 붙였습니다(예: "응대 화법은", "단순 비교 불가와", "인수기준 차이가"). 이름이 다시 바뀌면 `TERM`의 값과 함께 조사를 확인합니다.

### 5-3. 표시 이름 함수와 확정 이름 상수

`core.js`에서 `S`를 읽은 바로 뒤, `COPY` 앞에 둡니다. 아래 코드는 Claude가 화면 원본의 복사본에 넣어 문법과 화면 열기를 확인한 것입니다.

```js
// core.js: const DD = ...; 바로 뒤
// ---------- 표시 이름(자료의 표시명 표)과 확정 이름 상수 ----------
// 비교역할: 시트 값 관문전용은 인수기준비교로 바뀐다(사용자 승인). 두 값을 같은 뜻으로 받는다
const GATE_ONLY_ROLES = ['관문전용', '인수기준비교'];
const isGateOnlyRole = v => GATE_ONLY_ROLES.includes(v);
const LABELS = {};
function addLabels(map) {
  if (map) Object.assign(LABELS, map);
  const known = GATE_ONLY_ROLES.find(r => Object.prototype.hasOwnProperty.call(LABELS, r));
  if (known) GATE_ONLY_ROLES.forEach(r => { if (!Object.prototype.hasOwnProperty.call(LABELS, r)) LABELS[r] = LABELS[known]; });
}
addLabels(S['표시명']);
function label(v) {
  if (v == null) return v;
  return Object.prototype.hasOwnProperty.call(LABELS, v) ? LABELS[v] : v;   // 표에 없는 값은 값 그대로
}
// 현황 표 행 이름: 머리말이 행 종류 값이라 그 부분만 표시 이름으로 바꾼다('수술만 1~2년 전' → '통원수술 1~2년 전')
function rowLabel(r) {
  if (!r) return '';
  const k = r['종류'], nm = String(r['이름'] == null ? '' : r['이름']);
  return k && nm.startsWith(k) ? label(k) + nm.slice(k.length) : nm;
}
const TERM = {
  // 자료에 없는 확정 이름: 여기 한 곳에만 적는다
  app: '상품-영업 분석',
  graph: '관계 그래프',
  seg: '고객군별 가입 가능 현황',
  segShort: '가입 가능 현황',
  talk: '응대 화법',
  // 자료의 표시명에서 읽는 확정 이름: 글자로 적지 않는다
  brief: label(S['탭'][0]),
  gate: label(S['탭'][2]),
  noCompare: label('단정 주의'),
  catGate: label('관문 차이'),
  catStrong: label('앞세울 강점'),
  catRel: label('관련 담보 안내'),
  catWeak: label('조건 열위 방어'),
  catMiss: label('개정 검토 후보'),
};
// 그 아래에 const COPY = { ... } (3절의 식이 label과 TERM을 쓴다)
```

- `ui.verdict`, `ui.tag`, `ui.eq`는 함수 안에서 한 번 표시 이름을 거치게 하므로 호출하는 쪽(예: `tab4.src.js` 1174 `ui.tag(p['분류'])`, `tab5.js` 554, 591, `tab3.js` 361, 380의 `ui.eq` parts)은 고치지 않아도 됩니다. 호출하는 쪽에 `App.label`을 이미 넣었어도 결과가 같습니다. 표시 이름 가운데 다른 키와 같은 글자가 없어서 두 번 거쳐도 바뀌지 않습니다(Claude가 `sales.json`과 `graph.json`의 표시명 전부를 대조).
- 행 이름(`row['이름']`, `r['이름']`, `it.period['이름']`)은 머리말이 행 종류라 `App.rowLabel(행)`을 씁니다. `rowLabel`의 정의는 5-3에 있습니다.
- 세부 코드(G1~Q3)는 코드 글자를 화면에 내지 않고 이름만 냅니다(`p['세부이름'] || App.label(p['세부'])`). 요청 35에서 그 자리가 없어졌으면 건너뜁니다.

### 5-7. 짧은 표기

대조표의 "짧은 표기" 열은 자료에 싣지 않았습니다. 좁은 자리(칩, 탭, 필터 버튼, 열 이름, 링 차트 가운데)의 표기는 문구 표에서 정합니다. 문구 표에 맵 하나를 두고, 키는 자료 값이나 자료가 이미 새 이름으로 실은 글자입니다. 영업 인사이트 분류 다섯은 확정 이름을 짧은 표기 없이 그대로 씁니다.

```js
// COPY 안(새 키)
shortLabel: {
  '열림': '가능', '닫힘': '제한', '일부 나이만 열림': '일부 나이 가능', '함께 열림': '함께 가능',
  '우체국만 가입 가능': '우체국만 가능', '우체국만 가입 제한': '우체국만 제한', '미확인': '미상',
  '보장 대분류': '대분류', '시장 동향': '동향', '담보 관계': '관계',
  // 표시 이름으로 받는 자리(tab3.js의 KIND_T가 이미 표시 이름)
  '가입 가능': '가능', '가입 제한': '제한', '일부 나이만 가입 가능': '일부 나이 가능', '함께 가입 가능': '함께 가능',
},
// App.short: 짧은 표기가 있으면 짧은 표기, 없으면 표시 이름(5-3의 App 내보내기)
```
