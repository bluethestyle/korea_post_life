## 두 판독 값 파일 (`meritz_*_benefits_2reader.jsonl`)

초기 적재(2026-11-20 결정)에서 Claude 에이전트 두 판독(sonnet, opus)이 상품요약서 급부 표의 세부보장 한 줄마다 낸 값입니다. 판독 지시문은 `docs/backfill_reader_guide.md`, 견줌과 기계 검사는 `scripts/compare_readers.py`와 `src/postlife/extract/reader_rows.py`입니다. 묶음마다 낸 값 파일을 상품마다 하나로 합쳤고, 한 줄이 세부보장 하나입니다(번호 차례).

| 칸 | 뜻 |
| --- | --- |
| `번호` | 표 읽기(`extract/tables.py`의 메리츠화재 설정)가 그 요약서에서 낸 조각 순번(3자리)과 세부보장 순번. 예: `R012-3` |
| `쪽`, `특약명`, `급부명`, `형` | 그 줄의 PDF 쪽, 조각의 특약명과 세부보장명, 형(형 구간이 있는 요약서만). 이름은 조각에 적힌 그대로입니다 |
| `급부명비움` | 조각의 세부보장명 칸에 지급사유 문장이 들어 있어 `급부명`을 비운 줄의 사유(6AFMG `R175-1`). 그런 줄은 행을 만들지 않습니다 |
| `조각지문` | 그 줄의 조각 글자(세부보장명, 지급사유, 지급금액, 쪽, 적용범위, 조각의 머리와 주석)를 빈칸을 떼고 이어 만든 12자리 해시(`reader_rows.cover_fingerprint`). 적재할 때 문서를 다시 받아 표를 다시 읽고, 지문이 다른 줄은 쓰지 않습니다 |
| `sonnet`, `opus` | 두 판독의 값(`판독값/1`의 칸에서 숫자, 허용값, 30자 이하의 낱말만). 판독자가 쓴 모름 이유는 빼고 `모름칸`에 칸 이름만 남겼습니다 |
| `일치`, `기계검사`, `이름같은줄갈림`, `대상확인필요`, `자동판정` | `compare_readers.py`가 낸 칸별 일치, 두 판독의 기계 검사 문제와 표시, 자동 판정(확정 또는 판정필요) |

### 삼성생명과 KB라이프생명 (`samsunglife_*`, `kblife_*`, 2026-11-24)

꼴은 메리츠화재와 같습니다. 다른 점만 적습니다.

- 번호는 표 읽기가 그 요약서에서 낸 조각 순번입니다. 삼성생명은 특약별 작은 표(`extract/blocks.py`, `scripts/dump_blocks.py`), KB라이프생명은 쪽을 넘어 이어지는 표 하나(`extract/tables.py`의 KB 설정, `scripts/dump_tables.py --org kblife`)입니다.
- 삼성생명 요약서는 한 급부 표 안에 종별 값이 함께 있어, 대상 설정의 읽을종(New플러스원 2종, The라이트 3종)이 아닌 줄은 묶음 단계에서 뺐습니다. `조각지문`은 종의 토막을 떼기 전의 원래 조각으로 만듭니다.
- `조각지문`은 `scripts/compare_readers.py --pieces <조각 파일>`이 씁니다. 네 파일 모두 이 방법으로 다시 견주어 지문이 판정 때 넣은 값과 같은 것을 확인했고, `기계검사`와 `자동판정`은 지금 코드로 다시 낸 값입니다(판정과 판정값은 그대로 옮김).
- 판정값에만 쓰는 칸 `지급단위근거`(`{문서, 쪽}`): 그 줄의 칸에 지급단위 구절이 없고 같은 상품의 다른 문서 쪽에 있을 때 적습니다. KB라이프생명 입원 특약 42줄(간편 21, 일반 21)은 요약서 표에 "1일당"이 없고 약관의 그 특약 조항에만 있어 `{"문서": "약관", "쪽": N}`을 적었습니다. 적재는 공시 수집 결과의 약관에서 그 쪽만 다시 뽑아, 그 특약 이름의 조항 제목이 줄 첫머리에 나온 뒤에 "1일당"이 있는지 봅니다. 약관이 없거나 그 쪽에 없으면 그 줄은 쓰지 않습니다.
- New플러스원 341줄: 확정 283, opus 32, sonnet 6, 수정 14, 검토 대기 6. The라이트 291줄: 확정 241, opus 21, sonnet 4, 수정 15, 검토 대기 10. KB 간편심사형 184줄: 확정 154, opus 5, sonnet 4, 수정 21. KB 일반심사형 184줄: 확정 159, opus 2, 수정 21, 검토 대기 2.
- New플러스원의 R054, R055(진단 후 보험연도 구간마다 금액이 다른 줄 18개)는 판독 지시문 4.2절의 `경과기간별지급률`(행없음, 시트에는 차등지급 급부)로 읽은 opus를 골랐습니다. 메리츠화재의 경과 기간별 금액 줄과 같은 기준입니다.
- 가입조건 파일은 종형 아홉 모두 두 판독이 같고, New플러스원과 KB의 여섯은 근거낱말 표시 때문에 판정필요였다가 원문 대조로 확정했습니다. 가입조건 행은 삼성생명 36, KB라이프생명 24입니다.
- 공시 문서의 문장은 싣지 않습니다. 회사마다 세 파일(급부 둘, 가입조건 하나)의 글에서 이름(특약명, 급부명, 종형명, 근거낱말)과 30자 이하의 대상 낱말을 뺀 나머지를 그 회사 요약서와 사업방법서의 글자와 12자 토막으로 견주어, 겹치는 토막이 없는 것을 확인했습니다.

## 두 판독 가입조건 값 파일 (`meritz_main_conditions_2reader.jsonl`)

초기 적재에서 Claude 에이전트 두 판독(sonnet, opus)이 사업방법서의 가입나이 표에서 주계약(기본계약) 줄을 종형마다 읽은 값입니다. 판독 지시문은 `docs/backfill_conditions_guide.md`, 견줌과 기계 검사는 `scripts/compare_condition_readers.py`와 `src/postlife/extract/reader_conditions.py`입니다. 일감(6AFLT_MAIN, 6AFMG_SIMPLE, 6AFMH_6AFMI)마다 낸 값 파일을 하나로 합쳤고, 한 줄이 종형 하나입니다.

| 칸 | 뜻 |
| --- | --- |
| `일감` | 판독 일감 이름 |
| `종형ID`, `공시상품코드`, `종형명` | 대상 설정(`data/targets/meritz.json`)의 종형. 종형ID는 `variants.build`와 같은 규칙입니다 |
| `사업방법서해시`, `쪽범위` | 판독한 사업방법서 파일의 해시(공시 수집 결과의 `해시`)와 가입나이 표가 있는 쪽 범위. 적재할 때 받은 문서의 해시가 다르면 주의로 남기고, 쪽 범위는 기계 검사에 씁니다 |
| `sonnet`, `opus` | 두 판독의 값(`가입조건판독/1`의 표 하나를 종형에 붙인 꼴). `표`(판독자가 붙인 표 이름), `근거쪽`, `근거낱말`(표 제목의 20자 이하 낱말), `줄`(쪽, 성별, 보험기간, 납입기간, 최저나이, 최고나이, 최고나이식), `한도없음`, `한도`, `모름`(칸 이름만) |
| `일치`, `다른줄`, `기계검사`, `자동판정` | `compare_condition_readers.py`가 낸 칸별 일치(줄, 한도, 근거쪽), 두 판독이 갈린 줄, 두 판독의 기계 검사 문제와 표시, 자동 판정(확정 또는 판정필요) |
| `판정`, `판정값` | 최종 판정. `확정`(두 값이 같음), `sonnet`이나 `opus`(그 판독의 값), `수정`(메인 세션이 원문 쪽을 보고 고친 값이 `판정값`에 있음), `검토 대기`(쓰지 않음) |

- 종형 15개 모두 두 판독의 줄과 한도가 같고 기계 검사의 문제와 표시가 없어 자동 판정이 확정입니다. 가입한도는 15개 모두 문서에 적혀 있지 않습니다(`한도없음`). 만들어지는 가입조건 행은 102개입니다(6AFLT 15, 6AFMG 66, 6AFMH 12, 6AFMI 9).
- 공시 문서의 문장은 싣지 않습니다. 합친 파일에서 종형명과 근거낱말을 뺀 글 981개를 판독한 사업방법서와 요약서의 쪽 글자 전체와 12자 토막으로 견주어 겹치는 토막이 없는 것을 확인했습니다(가장 긴 글은 19자).
- `scripts/load_reader_conditions.py`는 받은 사업방법서 PDF에서 그 쪽 글자를 다시 뽑아 기계 검사를 다시 돌리고, 문제가 나오거나 판정할 때 없던 표시가 새로 나온 종형은 쓰지 않습니다. 시트에 주계약 특약 행이 없는 종형은 그 행도 씁니다(관문전용은 `variants.main_row`, 정밀비교는 급부 적재와 같은 행).
